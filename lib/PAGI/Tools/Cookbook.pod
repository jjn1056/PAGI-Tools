=head1 NAME

PAGI::Tools::Cookbook - Recipes for Common PAGI Tasks

Route matches a complete URL leaf. Mount composes an application under a
prefix. Router selects and owns routing outcomes. Middleware wraps behavior.
Compose owns the application root and lifespan.

=head1 DESCRIPTION

This cookbook provides ready-to-use solutions for common web development tasks
with PAGI. Each recipe is self-contained and can be adapted to your needs.

B<Prerequisites:> This cookbook assumes you've read L<PAGI::Tutorial> (the
PAGI protocol tutorial) and L<PAGI::Tools::Tutorial> (this distribution's
guide to middleware, helper classes, and built-in apps).

=head1 ROUTING RECIPES

These recipes cover the immutable L<PAGI::Routing> tree, the mutable
L<PAGI::App::Router>, and the method-oriented L<PAGI::Endpoint::Router>. For a
small runnable declarative app, see F<examples/declarative-routing>.

  PAGI::Routing          immutable functional declarations   $c handlers
  PAGI::App::Router      mutable imperative builder          verb methods + $c
  PAGI::Endpoint::Router class/role-oriented frontend        local method names

All three materialize the same immutable Router and share Pattern parsing,
Resolver slash addresses, Compiler dispatch, metadata, constraints, GET/HEAD,
Router-owned HTTP outcomes, reverse routing, and written declaration order.

=head2 A Declarative Route Tree with Package Handlers

Load handler packages normally and pass fully qualified coderefs. This gives
Perl's usual compile-time loading and avoids method-name strings or signature
guessing:

  package MyApp::Routes::Home;
  use strict;
  use warnings;
  use Future::AsyncAwait;

  async sub home {
      my ($c) = @_;
      return $c->html('<h1>Home</h1>');
  }

  1;

  # app.pl
  use MyApp::Routes::Home ();
  use PAGI::Compose qw(compose);
  use PAGI::Routing qw(:routes);

  my $routing = router(
      routes => [
          route('/' => \&MyApp::Routes::Home::home, name => 'home'),
      ],
  );

  compose(app => $routing)->to_app;

The final expression is the complete native PAGI app. A direct
C<< $routing->to_app >> already emits the Router's stock/custom 404 and built-in
405, but has no root ErrorHandler, response guard, or lifespan. Compile once
for the application instance; do not call C<to_app> inside a request.

=head2 Inline, Router, and Application Mounts

The C<routes> form constructs a complete child Router. Its names and reverse
paths are known to the parent, and its own 404/405 outcomes remain final:

  mount('/tenants/{tenant_id}',
      routes => [
          route('/users/{user_id}' => \&show_user, name => 'user'),
      ],
      name        => 'tenant',
      constraints => { tenant_id => qr/[a-z0-9-]+/ },
  )

For C</tenants/acme/users/42>, child handlers and mount/route middleware see
C<tenant_id =E<gt> 'acme'> and C<user_id =E<gt> '42'> in
C<path_params>. The child C<path> is C</users/42>, C<root_path> contains the
actual C</tenants/acme> prefix, and C<raw_path> remains the original wire path.
Reverse routing supplies both captures:

  $c->path_for('/tenant/user', {
      tenant_id => 'acme',
      user_id   => 42,
  });

Use C<app> for a separately configured modular Router:

  package MyApp::People;
  use PAGI::Routing qw(router route);

  sub routing {
      return router(routes => [
          route('/' => \&index, name => 'index'),
          route('/{person_id}' => \&show, name => 'show'),
      ], desc => 'People routes');
  }

  package MyApp::Root;
  use PAGI::Routing qw(router route mount);
  use MyApp::People ();

  sub routing {
      my $people = MyApp::People->routing;
      return router(routes => [
          route('/' => \&home, name => 'home'),
          mount('/people',
              app  => $people,
              name => 'person',
          ),
      ]);
  }

The root resolver publishes C</home>, C</person/index>, and
C</person/show>. The child Router keeps only its local descriptions; inside a
request, Context uses the active placement for relative calls such as
C<< $c->path_for('show') >>. After C</people> matches, the child Router owns its
full, partial, and no-match results. Its 404 or 405 flows through child Router,
Mount-occurrence, and enclosing Router middleware; the root never resumes
sibling scanning.

An opaque application uses the same named option:

  mount('/admin', app => $admin_app)

Once its prefix matches, it owns the outcome. Its 404/405 cannot resume parent
scanning, it applies no HTTP method filter, and its child names are not visible
to the parent.

An immutable Router in C<app> is inspectable. Other C<to_app> objects and
native coderefs are opaque. Either kind may be named or unnamed; the name
controls reverse-routing hierarchy, not dispatch mode.

A raw route is different again:

  route('/files/*path', raw => $file_endpoint, methods => ['GET'])

That is one exact/wildcard HTTP leaf. It participates in methods, automatic
HEAD, partial matching, and names, and receives the original routed path. A
C<< mount('/files', app =E<gt> $file_app) >> owns a protocol-capable prefix,
receives the implicit remainder in child C<path>, and extends C<root_path>.

Mounts are declaration-ordered owners. Put a narrow mount before a broad one.
C<mount('/api')> accepts both C</api> and C</api/> directly and passes child
path C</>; unlike Starlette's default behavior it does not redirect C</api> to
C</api/>.

A separately configured child can own local missing-route presentation:

  my $api = router(
      routes => [route('/items' => \&items)],
      http_default => PAGI::Pages->not_found(
          detail => 'No API route matched.',
      ),
  );
  my $root = router(routes => [
      mount('/api', app => $api, name => 'api'),
      route('/api/missing' => \&unreachable),
  ]);

After C</api> is selected, the child's custom 404 and built-in 405 are final;
C<unreachable> is never considered.

=head2 Complete Declarative Apples Application

This is the complete runnable shape from F<examples/starlette-apples/app.pl>:

  use v5.40;

  use Future::AsyncAwait;
  use List::Util qw(max);
  use Types::Standard qw(Int);

  use PAGI::Compose qw(compose);
  use PAGI::Pages;
  use PAGI::Routing qw(route mount);

  my %apples_db = (
      1 => { id => 1, name => 'Gala',       color => 'Red/Yellow' },
      2 => { id => 2, name => 'Honeycrisp', color => 'Rosy Red' },
  );

  async sub list_apples($c) {
      my @ids = sort { $a <=> $b } keys %apples_db;
      return $c->json([map { $apples_db{$_} } @ids]);
  }

  async sub read_apple($c) {
      my $apple_id = $c->path_param('apple_id');
      my $apple = $apples_db{$apple_id};
      return $c->json($apple) if $apple;
      return $c->json({ error => 'Apple not found' }, status => 404);
  }

  async sub create_apple($c) {
      my $data = await $c->request->json;
      my $new_id = max(0, keys %apples_db) + 1;
      my $new_apple = { id => $new_id, %$data };
      $apples_db{$new_id} = $new_apple;
      return $c->json($new_apple, status => 201);
  }

  async sub update_apple($c) {
      my $apple_id = $c->path_param('apple_id');
      return $c->json({ error => 'Apple not found' }, status => 404)
          unless exists $apples_db{$apple_id};

      my $data = await $c->request->json;
      $apples_db{$apple_id} = {
          %{$apples_db{$apple_id}},
          %$data,
      };
      return $c->json($apples_db{$apple_id});
  }

  async sub delete_apple($c) {
      my $apple_id = $c->path_param('apple_id');
      return $c->json({ error => 'Apple not found' }, status => 404)
          unless exists $apples_db{$apple_id};

      my $deleted_apple = delete $apples_db{$apple_id};
      return $c->json({
          success => \1,
          deleted => $deleted_apple,
      });
  }

  compose(
      routes => [
          route('/' => PAGI::Pages->welcome,
              name => 'home', desc => 'PAGI welcome page'),
          mount('/apples',
              routes => [
                  route('/' => \&list_apples,
                      methods => ['GET'], name => 'list',
                      desc => 'List apples'),
                  route('/' => \&create_apple,
                      methods => ['POST'], name => 'create',
                      desc => 'Create an apple'),
                  route('/{apple_id:&Int}' => \&read_apple,
                      methods => ['GET'], name => 'read',
                      desc => 'Read an apple'),
                  route('/{apple_id:&Int}' => \&update_apple,
                      methods => ['PUT'], name => 'update',
                      desc => 'Update an apple'),
                  route('/{apple_id:&Int}' => \&delete_apple,
                      methods => ['DELETE'], name => 'delete',
                      desc => 'Delete an apple'),
              ],
              name => 'apples',
              desc => 'Apples API namespace'),
      ],
  );

C</apples> and C</apples/> reach the child C</> leaves. The selected child owns
C<PATCH /apples> and its C<Allow: GET, HEAD, POST>. Constraint C<Int> validates
the decoded capture but does not coerce it.

=head2 Declarative Middleware Placement and Helpers

Middleware entries are pure app-to-app PAGI wrappers. The complete order is:

  outer Router middleware
    -> Router-mount middleware
      -> child Router middleware
        -> inline-mount middleware
          -> route middleware
            -> handler

Scope rewriting and match metadata happen before the matching mount/route
wrapper. Mount middleware can therefore read dynamic mount captures. The first
entry in each list is outermost.

Use L<PAGI::Middleware::Helpers> to keep channel ownership visible:

  use Future::AsyncAwait;
  use PAGI::Middleware::Helpers qw(clone_scope wrap_send wrap_receive);
  use PAGI::Routing qw(:routes :middleware);

  my $factory = sub {
      my ($app) = @_;

      return async sub {
          my ($scope, $receive, $send) = @_;

          # Immediate request-local shallow state change; no I/O.
          my $child = clone_scope($scope, { request_id => make_id() });

          # Construction only: no event has been emitted or received yet.
          my $out = wrap_send($send, async sub {
              my ($event, $downstream) = @_;
              if (($event->{type} // '') eq 'http.response.start') {
                  $event = {
                      %$event,
                      headers => [@{$event->{headers} // []},
                          ['x-request-id', $child->{request_id}]],
                  };
              }
              await $downstream->($event); # this actually emits and awaits
          });

          my $in = wrap_receive($receive, async sub {
              my ($downstream) = @_;
              my $event = await $downstream->(); # receive happens here
              return $event;
          });

          await $app->($child, $in, $out);
      };
  };

  my $routing = router(
      routes => [
          route('/' => \&home, middleware => [$factory]),
      ],
      # Explicit configured-class description remains useful beside the bare factory.
      middleware => [middleware('RequestId', header => 'X-Request-ID')],
  );

C<wrap_send> and C<wrap_receive> never delegate automatically. An interceptor
may short-circuit, replace, expand, filter, or synthesize events. Return or
await the downstream Future when completion, failure, and backpressure must
remain attached. Factory execution happens once during C<to_app>; returned
wrappers run per request. Use the bare factory for the low-boilerplate inline
form; keep C<middleware(...)> when an explicit configured-class description is
useful.

=head2 Negotiated 404 and 405 Responses

Router owns HTTP NONE and PARTIAL. Supply a Pages endpoint through
C<http_default> for custom NONE presentation; PARTIAL remains the Router's
negotiated 405 with authoritative C<Allow>:

  use PAGI::Compose qw(compose);
  use PAGI::Pages;
  use PAGI::Routing qw(router);

  my $pages = PAGI::Pages->new;

  my $routing = router(
      routes       => \@routes,
      http_default => $pages->not_found(
          detail => 'No application route matched.',
      ),
  );
  my $app = compose(app => $routing)->to_app;

Pages selects HTML, RFC 9457 problem JSON, or text from C<Accept>, adds
C<Vary: Accept>, and defaults errors to C<Cache-Control: no-store>. Use a
configured Pages instance or subclass here for application presentation; no
Pages object is discovered through Context, Compose, or global state.

A selected application's own 404 or 405 is left untouched. C<http_default>
runs only for HTTP NONE: it never receives a method mismatch, WebSocket or SSE
miss, selected handler exception, or handler-returned 404. GET contributes
HEAD to the Router-generated 405 union.

=head2 Compose Safety and Application Error Policy

Compose installs the same root safety graph for every HTTP target:

  outer idempotent application-root HEAD boundary
    automatic ErrorHandler
      response-completion guard
        author middleware, in listed order
          target

Router 404/405 responses pass through this graph unchanged. Compose's stock
error response is a negotiated, no-store Pages 500, with a final hardcoded
UTF-8 text 500 only if Pages rendering itself fails. Put the application's
official error policy inside request IDs, access logging, and security
middleware so those layers observe it:

A bare Router has no root ErrorHandler, response-completion guard, or lifespan
owner, but its compiled app already installs a Router HeadBoundary. If a
selected application sends nothing, a direct Router call completes without
synthesizing a response. Compose wraps that same Router in the safety graph
above; the outer idempotent HEAD boundary becomes the wire owner, and the guard
converts pre-start silence into its production-safe 500.

  my $app = compose(
      app => $routing,
      middleware => [
          'RequestId',
          'AccessLog',
          'SecurityHeaders',
          middleware('ErrorHandler',
              handler  => \&server_error,
              on_error => \&report_error),
      ],
  )->to_app;

For example, a database failed Future before response start is awaited by the
author ErrorHandler, reported through C<on_error>, and rendered by
C<server_error>. C<on_error> may return immediately or through a Future; its
failure is contained. If the database fails after a streaming response has
started, ErrorHandler awaits reporting, calls no renderer, emits no second
start, and rethrows the original database exception so the server can abort.

Ordinary ErrorHandler instances default to static production mode and never
consult C<PAGI_ENV>. Compose's private outer instance resolves development per
handled request and falls back to safe production output if resolution fails.
The built-in renderer negotiates through Pages. To fix one representation, use
the existing handler seam:

  middleware('ErrorHandler',
      handler => PAGI::Pages->internal_server_error(as => 'json'))

A custom renderer remains authoritative for its own content and headers.

=head2 Real Catch-All Routes

A Router default means "nothing matched." A wildcard is a real route:

  router(routes => [
      route('/api/users' => \&users),
      route('/*path' => \&spa, methods => ['GET']), # keep last
  ]);

  router(routes => [
      mount('/docs', routes => [
          route('/assets/*path' => \&asset),
          route('/*path' => \&docs_spa, methods => ['GET']),
      ]),
      route('/health' => \&health),
  ]);

The subtree catch-all affects only C</docs>. A GET-only catch-all makes an
unknown POST a 405 because its path matched partially. C<methods =E<gt> '*'>
turns the catch-all into a full match for every method and can supersede a 405
collected from an earlier specific route.

=head2 Custom HEAD without Running an Expensive GET

Put the explicit HEAD route before GET:

  route('/report' => \&head_report, methods => ['HEAD']),
  route('/report' => \&get_report,  methods => ['GET']),

Reversing the declarations invokes GET for HEAD because GET automatically
includes HEAD and the first full match wins. If C<head_report>'s constraint
returns false, the GET route's automatic HEAD remains the fallback. The router
suppresses the final wire body for either handler while preserving status and
GET-equivalent headers. Put body-derived response middleware in the router's
C<middleware> list, inside that HEAD boundary.

=head2 Constraint Forms and Wildcard Safety

All constraints receive one decoded scalar and validate without coercion:

  # Short path-local regex.
  route('/regex/{id:\d+}' => \&show);

  # Reusable named semantic constraint.
  use Types::Standard qw(Int);
  route('/typed/{id:&Int}' => \&show);

  # Explicit reusable object chosen while building the route.
  route('/object/{id}' => \&show,
      constraints => { id => Int },
  );

  # Explicit per-value predicate.
  route('/predicate/{slug}' => \&show,
      constraints => { slug => sub {
          my ($value) = @_;
          return $value =~ /\A[a-z0-9-]+\z/;
      } },
  );

The object form needs C<check($value)> and may provide
C<get_message($value)>; Type::Tiny is not a hard runtime dependency. C<Int>
accepts signed integers and PAGI retains the original string. A narrower local
provider can close over it:

  sub PersonId {
      my $int = Int;
      return sub {
          my ($value) = @_;
          return $int->check($value) && $value > 0;
      };
  }

  route('/people/{id:&PersonId}' => \&show);

An unescaped inline source beginning with C<&> is always provider intent and
must end in a capitalized package-function name. Use C<[&]Int> for a literal
leading ampersand. The alternative C<\&Int> requires a single-quoted Perl
path; C<< "\&Int" >> loses the backslash and requests the provider. Providers
run once with no arguments during source construction and return a regex,
predicate, or check object. The returned predicate, not the provider factory,
runs during matching and reverse routing.

Unqualified providers resolve as exact CODE slots in the package directly
calling the routing constructor; qualified packages must already be loaded.
There is no inherited method lookup, C<AUTOLOAD>, module loading, registry
fallback, or regex fallback after provider intent. Regex and inline
C<{id:\d+}> constraints are anchored over the complete value. Predicates must
be synchronous; database/resource checks belong in selected middleware or the
handler. The same rules select normal/raw HTTP, WebSocket, SSE, and all mount
forms, and C<path_for>/C<url_for> enforce them for named routes.

C<*path> captures decoded values including C<..>, repeated separators, and
backslashes. Never concatenate that value with a filesystem root. When no
custom authorization or response headers are needed, mount
L<PAGI::App::File> and let it own the complete file response:

  use PAGI::App::File;

  my $files = PAGI::App::File->app_path('public')->to_app;

For a raw handler that genuinely needs custom policy, validate the request
path before any filesystem check and emit only the returned lexical path:

  use Future;
  use Future::AsyncAwait;
  use PAGI::Pages;
  use PAGI::Utils qw(path_from_root);

  my $files = async sub {
      my ($scope, $receive, $send) = @_;
      my $untrusted_path = $scope->{path};

      my $path = path_from_root('/var/www/files', $untrusted_path);
      unless (defined $path) {
          my $response = PAGI::Pages->forbidden($scope);
          return await Future->wrap($response->respond($send));
      }

      unless (-f $path && -r $path) {
          my $response = PAGI::Pages->not_found($scope);
          return await Future->wrap($response->respond($send));
      }

      await Future->wrap($send->({
          type    => 'http.response.start',
          status  => 200,
          headers => [['content-type', 'application/octet-stream']],
      }));
      return await Future->wrap($send->({
          type => 'http.response.body', file => $path, more => 0,
      }));
  };

L<PAGI::Utils/path_from_root> is lexical and performs no I/O. It neither
resolves symlinks nor grants access; run authentication and authorization as
separate policy after it returns. The PAGI server opens the eventual C<file>
event. Configured symlinks extend administrator authority, so use a dedicated
root that attackers cannot modify and enforce suitable filesystem ownership
and permissions. Those are deployment best practices, not physical
confinement enforced by the helper. See the
L<rooted file-serving upgrade guide|https://github.com/jjn1056/PAGI-Tools/blob/main/UPGRADING.md#rooted-file-serving-security-contract>
for changed status and option behavior.

=head2 Normal, Raw, WebSocket, and SSE Handler Lifecycles

A normal HTTP handler builds local response state and returns it. Routing owns
the single emission:

  route('/normal' => async sub {
      my ($c) = @_;
      return $c->text('Hello');
  });

A raw endpoint owns every event and receives all channels:

  route('/raw', raw => async sub {
      my ($scope, $receive, $send) = @_;
      await $send->({
          type => 'http.response.start', status => 200, headers => [],
      });
      await $send->({
          type => 'http.response.body', body => 'Hello', more => 0,
      });
  });

Do not call C<< $c->respond >> inside a normal handler. Return the Response, or
choose C<raw> for manual event ownership.

Normal WebSocket and SSE handlers are imperative and their completion is
awaited:

  websocket('/chat/{room}' => async sub {
      my ($c) = @_;
      await $c->accept;
      await $c->send_text('joined ' . $c->path_param('room'));
      await $c->run;
  });

  sse('/events' => async sub {
      my ($c) = @_;
      await $c->start;
      await $c->send_event(data => 'ready');
      await $c->run;
  });

Use C<< websocket('/raw', raw =E<gt> $app) >> or
C<< sse('/raw', raw =E<gt> $app) >> when a native application must own those
protocol events. Their resolved return values are inert.

=head2 Names, Reverse URLs, and Inspection

Route and Mount names are local logical segments; slash alone forms hierarchy.
Names are optional for C<routes> and C<app> mounts:

  my $routing = router(routes => [
      mount('/api/v1', routes => $shared, name => 'v1'),
      mount('/api/v2', routes => $shared, name => 'v2'),
  ]);

  $routing->path_for('/v1/user', { id => 42 });
  $c->path_for('/v2/user', { id => 42 });
  $c->url_for('/v2/user',  { id => 42 });

An unnamed Mount leaves child addresses unprefixed. A dot such as
C<v1.1> remains literal within one segment. Duplicate absolute addresses,
duplicate parameters along one effective pattern, and defensive Router cycles
croak during Router construction.

Relative Context references start at the current containing namespace and use
exact C<.>/C<..> normalization:

  # Current address: /person/blog/show; captures person_id=42, blog_id=7
  $c->path_for('index');                    # inherits person_id
  $c->path_for('../show');                  # parent namespace
  $c->path_for('show', { blog_id => 8 });  # explicit value wins
  $c->path_for('/person/blog/show', {
      person_id => 9,
      blog_id   => 3,
  });                                      # absolute: no inheritance

Relative calls inherit only captures required by the target. Absolute Context
references and all Router-object calls inherit nothing. Inheritance constructs
a URL; it does not authorize the resource. Handlers must still enforce access.

Compact reverse arguments are C<(\%params, \%query, $fragment)>. Use empty
hashrefs as placeholders when skipping a component, or use named arguments:

  $c->url_for('show', { blog_id => 8 }, { view => 'full' }, 'comments');
  $c->url_for('show',
      query    => { view => 'full' },
      fragment => 'comments',
  );

Query keys are sorted; query and fragment components are UTF-8 encoded. The
forms cannot be mixed. All reverse helpers return strings or croak. They emit
no events, send no redirect, and do not mutate a response.

Router C<path_for> has no request prefix or placement. Context C<path_for>
uses the active placement and includes the compiled-router entry C<root_path>
exactly once. C<url_for> adds a scheme and authority validated by
L<PAGI::Authority>.

For HTTP behind a trusted proxy, wrap outer-to-inner:

  ReverseProxy -> TrustedHosts -> PAGI::Routing

Malformed or duplicate Host never falls back to C<server>. The shipped proxy
and Host middleware remain HTTP-only, so WebSocket/SSE scopes must already be
normalized and validated.

Inspect direct children and named leaves without mutating the tree:

  my $children = $routing->routes;
  my $named    = $routing->named_routes;
  my $leaf     = $routing->route_named('/v2/user');

C<named_routes> maps absolute addresses to their original leaves. Immutable
Router C<app> mounts are inspected recursively; other applications are opaque.
C<desc> is a human note for listings and tools.

=head2 Matched-Route Metadata

Each compiled router publishes a request-local, read-only convention before
router middleware:

  $scope->{'pagi.routing'} = {
      version => 1,
      frames  => [{
          resolver          => $resolver,
          root_path         => '/proxy', # optional additive v1 field
          logical_namespace => '/',
          captures          => {},       # private reverse-routing snapshot
          mounts            => [],
          match             => undef,
      }],
  };

A matched structural or inspectable Router Mount appends this exact Mount
record to the current frame before its Mount middleware runs:

  {
      path      => '/tenants/{tenant_id}', # declared mount path
      name      => 'tenant',                # declared value or undef
      desc      => 'Tenant routes',         # declared value or undef
  }

All keys are present; nested records are outer-to-inner. A selected leaf sets
this exact C<match> before route middleware:

  {
      kind              => 'route', # or websocket / sse
      route             => '/tenants/{tenant_id}/users/{user_id}',
      name              => '/tenant/show', # absolute or undef
      logical_namespace => '/tenant',
      desc              => 'Display one tenant user', # declared or undef
  }

C<< Route->name >> is the declaration-local final segment, such as C<show>;
matched C<name> is the composed absolute address. C<logical_namespace> remains
available for unnamed leaves.

An opaque application mount instead sets terminal C<match> with
C<kind =E<gt> 'mount'>, its complete effective mount path in C<route>,
C<name =E<gt> undef>, its containing C<logical_namespace>, and its declared
C<desc> or undef. It does not append a C<mounts> record for itself. A
Router-owned NONE/PARTIAL outcome leaves C<match> undefined. See
L<PAGI::Routing/MATCHED-ROUTE SCOPE CONVENTION> for the complete
public schema.

Each matched Mount first appends its Mount record to the current frame. Entering
an inspectable Router Mount then appends a distinct child boundary frame. That
frame retains the root Resolver and root entry C<root_path> while copying the
selected placement's namespace, captures, and cumulative Mount chain.

An opaque Mount instead leaves its terminal Mount match in the parent frame. If
its native target happens to be another separately compiled Router, that Router
appends its own child frame to a compatible container, using its own Resolver
and its own entry C<root_path>. Child middleware can inspect the new innermost
frame while parent middleware retains the terminal Mount frame.

Each active frame is shared only through request-local shallow scopes within
its boundary: router/mount middleware can inspect the final match after awaiting
downstream. Middleware outside the compiled app keeps its original top-level
scope and does not see downstream top-level additions.

Opaque, malformed, or newer C<pagi.routing> data forms an incompatible
boundary. The child installs a fresh v1 container, ignores foreign ancestry,
and leaves the incoming data untouched; it does not croak. Older/manual v1
frames may omit C<root_path>, and Context reverse routing then falls back to
the current request value.

=head2 Lifespan Around Declarative Routing

Routing deliberately ignores lifespan scopes. Put lifecycle policy at the
deployed application root with L<PAGI::Compose>:

  use Future::AsyncAwait;
  use PAGI::Compose qw(compose);

  my $app = compose(
      app => $routing,
      lifespan => {
        startup => async sub {
          my ($state, $scope) = @_;
          $state->{db} = await connect_db();
        },
      },
  )->to_app;

The server owns C<$state> and makes it visible to later request scopes. Compose
fails startup clearly if callbacks are configured but the server does not
provide valid state. It consumes lifespan itself, so do not put a second
lifespan consumer around the same deployed root.

For a hand-built native PAGI application, L<PAGI::Lifespan> remains the
low-level wrapper form:

  use PAGI::Lifespan;

  my $app = PAGI::Lifespan->wrap(
      $native_app,
      startup => \&startup,
  );

At the raw event level, L<PAGI::Utils/handle_lifespan> can drive a lifespan
scope directly:

  use PAGI::Utils qw(handle_lifespan);

  return await handle_lifespan($scope, $receive, $send,
      startup => \&startup,
  ) if $scope->{type} eq 'lifespan';

=head2 Path Parameters and Wildcards

The mutable frontend uses the shared C<{name}> Pattern syntax and Context
handlers:

  my $router = PAGI::App::Router->new;

  $router->get('/users/{id}' => sub {
      my ($c) = @_;
      my $id = $c->path_param('id');
      return $c->json({ id => $id, name => "User $id" });
  })->name('user');

  $router->get('/posts/{post_id}/comments/{comment_id}' => sub {
      my ($c) = @_;
      return $c->json({
          post_id    => $c->path_param('post_id'),
          comment_id => $c->path_param('comment_id'),
      });
  })->name('comment');

Handlers receive C<$c>; they do not rebuild Request/Response wrappers or emit
the returned HTTP Response themselves.

=head3 Wildcard Routes

Use C<*name> syntax to capture multiple path segments:

  my $router = PAGI::App::Router->new;

  $router->get('/files/*path' => sub {
      my ($c) = @_;
      return $c->text('File path: ' . $c->path_param('path'));
  })->name('file');

Wildcards match one or more segments; C<{name}> matches one. Treat wildcard
filesystem input with the containment rules described earlier in this
cookbook.

=head2 WebSocket and SSE Routes

Normal protocol handlers also receive one Context:

  $router->websocket('/ws' => async sub {
      my ($c) = @_;
      await $c->accept;
      await $c->each_text(async sub {
          my ($text) = @_;
          await $c->send_text("Echo: $text");
      });
  })->name('socket');

  $router->websocket('/ws/chat/{room}' => async sub {
      my ($c) = @_;
      await $c->accept;
      await $c->send_text('Joined room: ' . $c->path_param('room'));
      await $c->run;
  })->name('chat');

=head3 SSE Routes

  $router->sse('/events' => async sub {
      my ($c) = @_;
      await $c->keepalive(30);
      await $c->send_event(data => 'Connected at: ' . time);
      await $c->run;
  })->name('events');

  $router->sse('/events/{channel}' => async sub {
      my ($c) = @_;
      await $c->start;
      await $c->send_event(
          data => 'Subscribed to: ' . $c->path_param('channel'),
      );
      await $c->run;
  })->name('channel');

When existing protocol code must receive C<($scope, $receive, $send)> and own
events directly, mark the declaration explicitly:

  $router->websocket('/native-ws', raw => $native_ws_app);
  $router->sse('/native-events', raw => $native_sse_app);

=head2 Route-Level Middleware

Every Router, route, WebSocket, SSE, Mount, and Compose boundary accepts the same four
forms: class name, synchronous factory coderef, configured object with
C<wrap>, or L<PAGI::Routing::Middleware> description:

  use PAGI::Routing qw(middleware);

  my $auth_mw = sub {
      my ($app) = @_;
      return async sub {
          my ($scope, $receive, $send) = @_;
          return await authorized($scope)
              ? $app->($scope, $receive, $send)
              : deny($send);
      };
  };

  $router->get('/admin' => [
      'RequestId',
      $auth_mw,
      $configured_metrics,
      middleware('Session', cookie_name => 'sid'),
  ] => sub {
      my ($c) = @_;
      return $c->text('Admin panel');
  });

Declaration normalizes these entries. During C<to_app>, each factory is called
with the inner native app and each configured object's C<wrap> method is
called. The returned native wrappers run per request and control downstream
calls plus C<$scope>, C<$receive>, and C<$send>. The first listed entry is
outermost. Middleware never receives a response-valued C<$next> callback.

=head2 Nested Routers and Mounting

Build mutable children explicitly and take an immutable snapshot when the
parent should retain their names, metadata, and structure:

  my $api_router = PAGI::App::Router->new;
  $api_router->get('/users' => sub {
      my ($c) = @_;
      return $c->json([{ id => 1, name => 'Alice' }]);
  })->name('users');

  my $main_router = PAGI::App::Router->new;
  $main_router->mount('/api', app => $api_router->to_router)->name('api');

  $main_router->mount('/reports', routes => sub {
      my ($reports) = @_;
      $reports->get('/' => sub {
          my ($c) = @_;
          return $c->json({ report => 'current' });
      })->name('index');
  })->name('reports');

The C<routes =E<gt> sub> callback is a mutable App/Endpoint builder shorthand.
The functional L<PAGI::Routing/mount> constructor instead takes
C<routes =E<gt> [ ... ]>; it does not execute a builder callback.

  my $snapshot = $main_router->to_router;
  $snapshot->path_for('/api/users');

Each C<to_router> creates a fresh snapshot. Retain C<$snapshot> when route
identity, reverse generation, and the compiled app must describe one coherent
configuration. Later builder mutations do not alter it.

An opaque application mount hides child routing:

  $main_router->mount('/static',
      app => PAGI::App::File->new(root => './public'));

Opaque mounts own every protocol below their prefix and rewrite C<path> and
C<root_path>. A native exact HTTP target instead uses
C<< get('/download', raw => $native_app) >>. Package strings are not implicit
route or Mount targets: load the package, construct the child object, and
choose an immutable discoverable Router or opaque native application
explicitly.

All declarations retain written order. Put a root or static opaque mount last,
because a matched prefix owns dispatch immediately and later declarations are
not reconsidered.

=head2 Class-Based Routing with PAGI::Endpoint::Router

L<PAGI::Endpoint::Router> provides an object-oriented approach to routing. You define a class that extends C<PAGI::Endpoint::Router>, implement a C<routes()> method, and use method names as handlers.

=head3 Basic Router Class

  package MyApp;
  use parent 'PAGI::Endpoint::Router';
  use strict;
  use warnings;
  use Future::AsyncAwait;

  sub new {
      my ($class, %args) = @_;
      die 'repository required' unless $args{repository};
      return bless { repository => $args{repository} }, $class;
  }

  sub routes {
      my ($self, $r) = @_;

      $r->get('/' => 'home')->name('home');
      $r->get('/people/{id}' => 'show')->name('show');
      $r->get('/closure' => sub {
          my ($c) = @_;
          return $c->text('ordinary Context closure');
      })->name('closure');
  }

  async sub home {
      my ($self, $c) = @_;
      return $c->html('<h1>Welcome!</h1>');
  }

  async sub show {
      my ($self, $c) = @_;
      my $person = await $self->{repository}->find($c->path_param('id'));
      return $c->json($person);
  }

  1;

  # In app.pl:
  # use MyApp;
  # use PAGI::Compose qw(compose);
  # compose(app => MyApp->new(repository => $repository))->to_app;

Handler methods are called with:

=over 4

=item * C<$self> - the exact constructed Endpoint object; ordinary validated
fields such as C<$self-E<gt>{repository}> hold application configuration

=item * C<$c> - the shared protocol-specific L<PAGI::Context>; read the request
via C<< $c->request >>, build the response with C<< $c->json >> /
C<< $c->html >> / C<< $c->text >> and
return it

=back

Unqualified strings are local handler names resolved with C<can> while the
snapshot is built; they never load packages. Inherited and role-installed
methods work. Coderef handlers are ordinary shared C<($c)> handlers and are not
rebound to the object. Explicit C<< $endpoint->new_context(...) >> constructs a
Context only for that caller; overriding it does not change compiled route
Contexts.

=head3 WebSocket Handlers

WebSocket handler methods receive C<($self, $c)> and use the shared
WebSocket Context directly:

  package MyApp;
  use parent 'PAGI::Endpoint::Router';
  use strict;
  use warnings;
  use Future::AsyncAwait;

  sub routes {
      my ($self, $r) = @_;

      $r->websocket('/ws' => 'handle_ws')->name('socket');
      $r->websocket('/ws/chat/{room}' => 'handle_chat')->name('chat');
  }

  async sub handle_ws {
      my ($self, $c) = @_;
      await $c->accept;
      await $c->each_text(async sub {
          my ($text) = @_;
          await $c->send_text("Echo: $text");
      });
  }

  async sub handle_chat {
      my ($self, $c) = @_;
      await $c->accept;
      await $c->send_text('Joined room: ' . $c->path_param('room'));
      await $c->run;
  }

  1;

=head3 SSE Handlers

SSE handler methods likewise receive C<($self, $c)>:

  package MyApp;
  use parent 'PAGI::Endpoint::Router';
  use strict;
  use warnings;
  use Future::AsyncAwait;

  sub routes {
      my ($self, $r) = @_;

      $r->sse('/events' => 'handle_events')->name('events');
      $r->sse('/events/{channel}' => 'handle_channel')->name('channel');
  }

  async sub handle_events {
      my ($self, $c) = @_;
      await $c->keepalive(30);
      await $c->send_event(data => 'Connected at: ' . time);
      await $c->run;
  }

  async sub handle_channel {
      my ($self, $c) = @_;
      await $c->start;
      await $c->send_event(data => 'Channel: ' . $c->path_param('channel'));
      await $c->run;
  }

  1;

Use the Endpoint-aware C<raw> form only when a native protocol app must own
C<($scope, $receive, $send)> itself.

=head3 Initializing Resources

C<PAGI::Endpoint::Router> has no private state store or lifecycle hooks.
Constructor fields hold Endpoint configuration. Request state belongs to the
server lifespan and is read through C<< $c->state >>:

  package MyApp;
  use parent 'PAGI::Endpoint::Router';
  use strict;
  use warnings;
  sub new {
      my ($class, %args) = @_;
      return bless { repository => $args{repository} }, $class;
  }

  async sub home {
      my ($self, $c) = @_;
      return $c->json({
          service => $self->{repository}->service_name,
          uptime  => time() - $c->state->{started_at},
      });
  }

  1;

Make Compose the complete deployed root when startup and shutdown own that
server-provided state:

  use PAGI::Compose qw(compose);
  use MyApp;

  my $endpoint = MyApp->new(repository => $repository);

  my $app = compose(
      app => $endpoint,
      middleware => [$application_logging],
      lifespan => {
          startup  => async sub ($state, $scope) {
              $state->{db} = DBI->connect('dbi:SQLite:dbname=app.db');
              $state->{started_at} = time;
          },
          shutdown => async sub ($state, $scope) {
              $state->{db}->disconnect if $state->{db};
          },
      },
  )->to_app;

Immediate values and Future-backed callback completion are both accepted.
Compose owns the lifespan scope and the server owns the state identity and its
propagation into request scopes. A nested Compose does not run lifecycle
callbacks; put the only lifecycle owner at the deployed root.

=head4 Compatibility/low-level: PAGI::Lifespan

L<PAGI::Lifespan> remains available when its existing hook-registration form
is specifically required or when composing a hand-built native application:

  use Future::AsyncAwait;
  use PAGI::Compose qw(compose);
  use PAGI::Lifespan;

  my $app = PAGI::Lifespan->new(
      startup  => async sub ($state) {
          $state->{db} = DBI->connect('dbi:SQLite:dbname=app.db');
      },
      shutdown => async sub ($state) {
          $state->{db}->disconnect if $state->{db};
      },
      app      => compose(app => $endpoint)->to_app,
  )->to_app;

Here the low-level wrapper owns lifecycle hooks while the nested Router owns
its mandatory 404 and 405 outcomes and Compose owns HTTP completion safety.

=head3 Route-Level Middleware and Local Adapters

Endpoint middleware uses the universal native app-to-app contract. Adapt a
local wrapping method explicitly with C<middleware_as>:

  package MyApp;
  use parent 'PAGI::Endpoint::Router';
  use strict;
  use warnings;
  use Future::AsyncAwait;
  use PAGI::Routing qw(middleware);

  sub routes {
      my ($self, $r) = @_;

      $r->get('/admin' => [
          'RequestId',
          $self->middleware_as('require_auth'),
          $self->{configured_metrics},
          middleware('Session', cookie_name => 'sid'),
      ] => 'admin_page');
  }

  sub require_auth {
      my ($self, $inner_app) = @_;
      return async sub {
          my ($scope, $receive, $send) = @_;
          return await $self->allows($scope)
              ? $inner_app->($scope, $receive, $send)
              : deny($send);
      };
  }

  async sub admin_page {
      my ($self, $c) = @_;
      return $c->html('<h1>Admin Panel</h1>');
  }

  1;

C<middleware_as> validates the unqualified method immediately. At C<to_app>,
the method receives C<($self, $inner_app)> and returns a native app
synchronously. That returned app runs per request. The other entries show the
class, configured object, and explicit description forms. The first entry is
outermost, and this same contract works for HTTP, WebSocket, and SSE.

Use C<< $self->app_as('native_method') >> when a local method should receive
C<($self, $scope, $receive, $send)>. Supply it after C<raw> for an exact,
method-aware leaf, through C<< app => >> for an opaque prefix mount, or to
C<http_default>. It is not an ordinary route handler adapter.

=head3 Mounting Sub-Routers

Construct modular Endpoint objects and mount them through a known Router
boundary:

  # lib/MyApp/API.pm
  package MyApp::API;
  use parent 'PAGI::Endpoint::Router';
  use strict;
  use warnings;
  use Future::AsyncAwait;

  sub new {
      my ($class, %args) = @_;
      return bless { repository => $args{repository} }, $class;
  }

  sub routes {
      my ($self, $r) = @_;

      $r->get('/' => 'list_users')->name('index');
      $r->get('/{id}' => 'get_user')->name('show');
      $r->post('/' => 'create_user')->name('create');
  }

  async sub list_users {
      my ($self, $c) = @_;
      return $c->json([
          { id => 1, name => 'Alice' },
          { id => 2, name => 'Bob' },
      ]);
  }

  async sub get_user {
      my ($self, $c) = @_;
      my $id = $c->path_param('id');
      return $c->json({ id => $id, name => "User $id" });
  }

  async sub create_user {
      my ($self, $c) = @_;
      my $data = await $c->request->json;
      return $c->json({ id => 3, name => $data->{name} }, status => 201);
  }

  1;

  # lib/MyApp.pm
  package MyApp;
  use parent 'PAGI::Endpoint::Router';
  use strict;
  use warnings;
  use Future::AsyncAwait;
  use MyApp::API;

  sub new {
      my ($class, %args) = @_;
      my $api = MyApp::API->new(repository => $args{repository});
      return bless { api => $api }, $class;
  }

  sub routes {
      my ($self, $r) = @_;

      $r->get('/' => 'home')->name('home');
      $r->mount('/api', app => $self->{api}->to_router)->name('api');
  }

  async sub home {
      my ($self, $c) = @_;
      return $c->html('<h1>Home</h1>');
  }

  1;

  # app.pl
  use MyApp;
  use PAGI::Compose qw(compose);

  compose(app => MyApp->new(repository => $repository))->to_app;

Now C</api> and C</api/42> are handled by the exact constructed child object.
The retained snapshot can generate C</api/show> and inspect that child's
metadata. Reusing the same child object at sibling placements reuses one child
Router identity within the snapshot while each mount keeps its own path and
local name.

=head3 Complete Example

This root keeps Endpoint configuration in ordinary object fields, request
state in Compose lifespan state, and every declaration inspectable:

  # lib/MyApp/People.pm
  package MyApp::People;
  use strict;
  use warnings;
  use parent 'PAGI::Endpoint::Router';
  use Future::AsyncAwait;

  sub new {
      my ($class, %args) = @_;
      return bless { repository => $args{repository} }, $class;
  }

  sub routes {
      my ($self, $r) = @_;
      $r->get('/' => 'index')->name('index');
      $r->get('/{id}' => 'show')->name('show');
  }

  sub index {
      my ($self, $c) = @_;
      my @people = $self->{repository}->all;
      return $c->json({
          people => \@people,
          first  => $c->path_for('show', { id => $people[0]{id} }),
      });
  }

  sub show {
      my ($self, $c) = @_;
      return $c->json(
          $self->{repository}->find($c->path_param('id')),
      );
  }

  1;

  # lib/MyApp.pm
  package MyApp;
  use strict;
  use warnings;
  use parent 'PAGI::Endpoint::Router';
  use Future::AsyncAwait;
  use MyApp::People;

  sub new {
      my ($class, %args) = @_;
      my $people = MyApp::People->new(repository => $args{repository});
      return bless {
          people          => $people,
          static          => $args{static},
          access_factory  => $args{access_factory},
      }, $class;
  }

  sub routes {
      my ($self, $r) = @_;

      $r->get('/' => 'home')->name('home');
      $r->mount('/people', app => $self->{people}->to_router)->name('people');
      $r->get('/admin' => [
          $self->middleware_as('require_auth'),
      ] => 'admin')->name('admin');
      $r->websocket('/ws/{room}' => 'chat')->name('chat');
      $r->sse('/events' => 'events')->name('events');

      # app_as exposes a local native method as one exact raw HTTP leaf.
      $r->get('/download', raw => $self->app_as('download'));

      # Prefix owners follow written order; the static catch-all stays last.
      $r->mount('/',
          app        => $self->{static},
          middleware => [$self->{access_factory}],
      );
  }

  sub home {
      my ($self, $c) = @_;
      return $c->json({
          people => $c->path_for('people/index'),
          events => $c->path_for('events'),
          uptime => time() - $c->state->{started_at},
      });
  }

  sub require_auth {
      my ($self, $inner_app) = @_;
      return async sub {
          my ($scope, $receive, $send) = @_;
          return await $self->deny($send)
              unless $self->authorized($scope);
          return await $inner_app->($scope, $receive, $send);
      };
  }

  sub authorized {
      my ($self, $scope) = @_;
      for my $header (@{$scope->{headers} // []}) {
          next unless lc($header->[0]) eq 'authorization';
          return $header->[1] eq 'Bearer example-token';
      }
      return 0;
  }

  async sub deny {
      my ($self, $send) = @_;
      await $send->({
          type    => 'http.response.start',
          status  => 401,
          headers => [['content-type', 'text/plain']],
      });
      await $send->({
          type => 'http.response.body', body => 'Unauthorized', more => 0,
      });
  }

  sub admin {
      my ($self, $c) = @_;
      return $c->json({ ready => $c->state->{db}->ping ? \1 : \0 });
  }

  async sub chat {
      my ($self, $c) = @_;
      await $c->accept;
      await $c->send_text('room=' . $c->path_param('room'));
      await $c->run;
  }

  async sub events {
      my ($self, $c) = @_;
      await $c->start;
      await $c->send_json({ connected => time });
      await $c->run;
  }

  async sub download {
      my ($self, $scope, $receive, $send) = @_;
      await $send->({
          type    => 'http.response.start',
          status  => 200,
          headers => [['content-type', 'application/octet-stream']],
      });
      await $send->({
          type => 'http.response.body', body => "example download\n", more => 0,
      });
  }

  1;

  # app.pl
  package Local::Repository;
  use strict;
  use warnings;

  sub new {
      return bless {
          people => [
              { id => 1, name => 'Ada' },
              { id => 2, name => 'Grace' },
          ],
      }, shift;
  }

  sub all {
      my ($self) = @_;
      return map { +{%$_} } @{$self->{people}};
  }

  sub find {
      my ($self, $id) = @_;
      my ($person) = grep { $_->{id} == $id } @{$self->{people}};
      return defined $person ? {%$person} : undef;
  }

  package Local::Database;
  use strict;
  use warnings;

  sub new        { return bless { connected => 1 }, shift }
  sub ping       { return $_[0]{connected} }
  sub disconnect { $_[0]{connected} = 0; return }

  package main;
  use strict;
  use warnings;
  use Future::AsyncAwait;
  use PAGI::App::File;
  use PAGI::Compose qw(compose);
  use MyApp;

  my $repository = Local::Repository->new;

  my $access_factory = sub {
      my ($inner_app) = @_;
      return async sub {
          my ($scope, $receive, $send) = @_;
          return await $inner_app->($scope, $receive, $send);
      };
  };

  my $application_logging = sub {
      my ($inner_app) = @_;
      return async sub {
          my ($scope, $receive, $send) = @_;
          warn 'request scope: ' . ($scope->{type} // 'unknown') . "\n";
          return await $inner_app->($scope, $receive, $send);
      };
  };

  my $endpoint = MyApp->new(
      repository     => $repository,
      static         => PAGI::App::File->new(root => 'public'),
      access_factory => $access_factory,
  );

  my $snapshot = $endpoint->to_router;
  compose(
      app => $snapshot,
      middleware => [$application_logging],
      lifespan => {
          startup => async sub {
              my ($state, $scope) = @_;
              $state->{started_at} = time;
              $state->{db} = Local::Database->new;
          },
          shutdown => async sub {
              my ($state, $scope) = @_;
              $state->{db}->disconnect;
          },
      },
  )->to_app;

This is a mechanically complete composition skeleton: the in-process
C<Local::Repository> and C<Local::Database> stand-ins make every dependency
explicit, but a deployed application would replace them with its own durable
repository and lifecycle-managed database implementation.

Endpoint C<routes> methods build a fresh immutable snapshot; middleware
factories and C<wrap> adapters run when that snapshot is compiled; and their
returned native apps run once per request. The complete Compose root owns
application middleware plus lifecycle, while the server owns state identity.
Relative C<path_for> calls use the current placement: C<show> inside the People
child resolves below C</people>, while C<people/index> at root resolves through
the named child. The root/static mount is deliberately last because written
order determines ownership.

Run the application returned by F<app.pl> with
C<pagi-server app.pl --port 5000>.

See C<examples/endpoint-router-demo/> for more examples.

=head2 Deliberate Starlette Differences

The shared Route/Mount/Router vocabulary is not a claim of API identity.
Ordinary PAGI handlers receive an explicit Context; C<raw>, Mount C<app>,
Router C<http_default>, and Compose C<app> receive native three-channel PAGI
applications. Constraints validate without coercion. Logical names use slash
addresses and relative Context lookup. SSE is a first-class scope, and
middleware at Router, Mount, Route, and Compose boundaries is pure PAGI
app-to-app wrapping.

Starlette's single multiprotocol Router C<default> was considered and
deliberately not copied. PAGI's C<http_default> handles only HTTP NONE, leaving
stock WebSocket and SSE misses intact. Compose, not Router, owns root lifespan.
OpenAPI/schema generation and C<include_in_schema> remain deferred; the
inspectable immutable tree is a future seam, not a shipped schema API.

=head2 Session Management

Use L<PAGI::Middleware::Session> for session management. The middleware
populates C<< $scope->{'pagi.session'} >>; the L<PAGI::Session> helper wraps
that hashref with a convenient (and typo-catching) API.

  use strict;
  use warnings;
  use Future::AsyncAwait;
  use PAGI::App::Router;
  use PAGI::Middleware::Builder;
  use PAGI::Session;
  use PAGI::Request;
  use PAGI::Response;

  my $router = PAGI::App::Router->new;

  $router->get('/login', raw => async sub {
      my ($scope, $receive, $send) = @_;
      my $req = PAGI::Request->new($scope, $receive);
      my $res = $req->response;

      # Set session data
      my $session = PAGI::Session->new($scope);
      $session->set(user_id  => 123);
      $session->set(username => 'alice');

      await $res->text('Logged in!')->respond($send);
  });

  $router->get('/profile', raw => async sub {
      my ($scope, $receive, $send) = @_;
      my $req = PAGI::Request->new($scope, $receive);
      my $res = $req->response;

      # Read session data (the second arg is a default for optional keys)
      my $session = PAGI::Session->new($scope);
      my $username = $session->get('username', 'Guest');

      await $res->text("Hello, $username!")->respond($send);
  });

  $router->get('/logout', raw => async sub {
      my ($scope, $receive, $send) = @_;
      my $req = PAGI::Request->new($scope, $receive);
      my $res = $req->response;

      # Clear session data
      PAGI::Session->new($scope)->clear;

      await $res->text('Logged out!')->respond($send);
  });

  # Wrap the router with the session middleware
  my $app = builder {
      enable 'Session',
          secret      => 'your-secret-key-here',
          cookie_name => 'session_id',
          expire      => 86400;  # 1 day
      $router;
  };

=head1 REAL-TIME PATTERNS

=head2 Real-Time Fan-Out (Pub/Sub)

Fanning a message out to other WebSocket or SSE connections means one
scope's handler holding and calling C<send> for a different scope. PAGI's
sequential-sends contract only covers a single scope's own C<send>, so an
architecture that holds other scopes' sends cannot earn full fidelity to it
without its own multiplexing layer. That layer is the scope of the coming
B<PAGI-Channels> distribution (own-scope receive-multiplexed messaging,
with in-memory and Redis backends) rather than this Cookbook. Reach for it
when you need chat rooms, live dashboards, or any other fan-out pattern.

=head2 In-Loop WebSocket Rate Limiting

Rate limiting used to be middleware that wrapped C<receive> and injected a
synthetic C<websocket.disconnect> when a client went over budget. That shape
cannot be made faithful to the protocol: the server, not middleware, owns
disconnect delivery, so a middleware-fabricated disconnect is a ghost event
with a made-up reason, and closing from inside a wrapped C<receive> means
the close send races whatever the real handler does next, unawaited.

Enforce the limit where the real receive loop already lives instead -- a
token bucket checked against each incoming message, with a real, awaited
C<< $ws->close >> when the budget is blown:

  use PAGI::WebSocket;
  use Time::HiRes qw(time);

  $router->websocket('/chat', raw => async sub {
      my ($scope, $receive, $send) = @_;
      my $ws = PAGI::WebSocket->new($scope, $receive, $send);
      await $ws->accept;

      my $limit  = 10;               # messages per second
      my $burst  = 2;                # allow short bursts up to limit * burst
      my $tokens = $limit * $burst;
      my $last   = time();

      await $ws->each_text(async sub {
          my ($text) = @_;

          my $now = time();
          $tokens += ($now - $last) * $limit;
          $tokens = $limit * $burst if $tokens > $limit * $burst;
          $last = $now;

          if ($tokens < 1) {
              return await $ws->close(code => 1008, reason => 'Rate limit exceeded');
          }
          $tokens -= 1;

          await $ws->send_text("you said: $text");
      });
  });

C<each_text> already serializes callback invocations against the receive
loop -- the next message is not read until this callback's Future settles --
so the token check and the reply share the same natural ordering the old
middleware wrapper had to fake with a synthetic event. Closing from inside
the loop is a real, awaited C<websocket.close> that the server delivers
exactly once, with the real code and reason -- no synthesized disconnect,
and nothing races it.

If several routes need the same limiter, factor the token-bucket state and
check into a small helper function and call it from each route's loop --
ordinary code reuse, not middleware pretending to own protocol lifecycle
events it can't actually generate.

=head2 SSE Dashboard

Server-Sent Events are ideal for real-time dashboards:

  use strict;
  use warnings;
  use Future::AsyncAwait;
  use PAGI::App::Router;
  use PAGI::SSE;

  my $router = PAGI::App::Router->new;

  $router->sse('/events', raw => async sub {
      my ($scope, $receive, $send) = @_;

      my $sse = PAGI::SSE->new($scope, $receive, $send);

      # Start the stream explicitly before anything else touches it --
      # don't lean on a method's own implicit auto-start.
      await $sse->start;

      # Enable keepalive to prevent proxy timeout
      await $sse->keepalive(15);

      # Subscribe to metrics updates (your pub/sub system). The callback
      # comes from an external, synchronous pub/sub API, so it can't await
      # here -- handle the returned Future explicitly (on_fail + retain)
      # instead of firing it and forgetting it.
      my $sub_id = subscribe_metrics(sub {
          my ($metrics) = @_;
          $sse->try_send_event(
              event => 'metrics',
              data  => $metrics,
          )->on_fail(sub {
              my ($error) = @_;
              warn "metrics send failed: $error";
          })->retain;
      });

      $sse->on_close(sub { unsubscribe_metrics($sub_id) });
      await $sse->run;
  });

  $router->to_app;

JavaScript client:

  const events = new EventSource('/events');

  events.addEventListener('metrics', (e) => {
      const data = JSON.parse(e.data);
      document.getElementById('cpu').textContent = data.cpu.toFixed(1) + '%';
      document.getElementById('memory').textContent = data.memory.toFixed(1) + '%';
  });

See C<examples/sse-dashboard/> for a complete dashboard example.

=head2 Handling a Mixed Event Stream

When the receive stream carries more than one kind of event -- the protocol's
own events plus application events injected by middleware -- the
L<PAGI::Context> event dispatcher lets you register one handler per event type
and run a single loop, instead of hand-rolling a C<while> over C<receive>.

  use PAGI::Context;

  $router->websocket('/notify', raw => async sub {
      my ($scope, $receive, $send) = @_;
      my $ctx = PAGI::Context->new($scope, $receive, $send);
      await $ctx->accept;

      # A protocol event from the client
      $ctx->on('websocket.receive', async sub {
          my ($ctx, $event) = @_;
          await $ctx->send_text("echo: " . ($event->{text} // ''));
      });

      # An application event injected into the receive stream by middleware
      # (for example a pub/sub bridge such as the PAGI-Channels companion dist)
      $ctx->on('app.notify', async sub {
          my ($ctx, $event) = @_;
          await $ctx->send_json({ notice => $event->{message} });
      });

      # A fallback for anything you did not register a handler for
      $ctx->on_default(sub {
          my ($ctx, $event) = @_;
          warn "unexpected event: $event->{type}";
      });

      $ctx->on_error(sub {
          my ($ctx, $err, $source) = @_;
          warn "[$source] $err";
      });

      my $reason = await $ctx->run;   # 'disconnect', 'stop', or 'error'
  });

Handlers receive the protocol-typed C<$ctx> (so C<send_text>/C<send_json> work),
run in registration order, and may be C<async sub>s. The loop runs until the
client disconnects, a handler calls C<< $ctx->stop >>, or C<receive> fails;
C<run()> resolves with the reason and clears the handlers afterward so closures
over C<$ctx> do not leak.

=head2 Closing an SSE stream, and recording why

Returning from an SSE handler ends the stream when your code does. Call
C<< $sse->close >> to end it B<explicitly and immediately> -- from anywhere,
including deep in a helper -- which also wakes a parked C<< $sse->run >>. An
optional C<reason> is recorded server-side (logs, metrics, tracing) and passed
to C<on_close>; it is B<never> sent to the client, since SSE has no close frame:

  $router->sse('/quotes', raw => async sub {
      my ($scope, $receive, $send) = @_;
      my $sse = PAGI::SSE->new($scope, $receive, $send);

      my $sub = subscribe_feed($sse->query_param('job'));

      # One cleanup hook, however the stream ends (client gone, our close, ...).
      $sse->on_close(async sub {
          my ($sse, $reason) = @_;
          await $sub->cancel;                  # async cleanup, awaited
      });

      while (defined(my $tick = await $sub->next)) {
          await $sse->send_event(event => 'quote', data => $tick);
          next unless $tick->{final};

          # Tell the CLIENT with an in-band event it listens for, then close with
          # a SERVER-SIDE reason for your logs.
          await $sse->send_event(event => 'done', data => { ok => 1 });
          return await $sse->close(reason => 'feed_complete');
      }
      await $sse->close(reason => 'feed_gone');
  });

The two "why" channels are deliberately separate: a normal C<sse.send> event is
the only thing the browser can observe, while C<reason> is server-side metadata.
Because the close is an event on C<$send>, middleware can observe it -- wrap
C<$send> to fan close reasons out to metrics or tracing without touching the
handler:

  sub observe_sse_closes {
      my ($app) = @_;
      return async sub {
          my ($scope, $receive, $send) = @_;
          my $wrapped = async sub {
              my ($event) = @_;
              metric_inc('sse_close', $event->{reason} // 'unspecified')
                  if ($event->{type} // '') eq 'sse.close';
              return await $send->($event);    # forward unchanged
          };
          await $app->($scope, $receive, $wrapped);
      };
  }

Apply it at the mount or Router level (event middleware). See L<PAGI::SSE/close>
for the method, L<PAGI::Spec::Www/"Close SSE - C<send> event"> for the protocol
event, and L<PAGI::Cookbook/"Ending a stream: return vs C<sse.close>"> for the
raw form.

=head2 Declining an SSE request (404 / 401 / 204 stop-reconnect)

An SSE request is an ordinary C<GET> with C<Accept: text/event-stream>. Before
you start the stream you can B<decline> it and return a normal HTTP response
instead -- no event stream. Use C<< $sse->decline >>, which is how most
application code should write this:

  $router->sse('/feed', raw => async sub {
      my ($scope, $receive, $send) = @_;
      my $sse = PAGI::SSE->new($scope, $receive, $send);

      # Auth check before we commit to a stream.
      unless (authorized($sse->query_param('token'))) {
          return await $sse->decline(
              status  => 401,
              headers => [['content-type', 'text/plain']],
              body    => 'Unauthorized',
          );
      }

      await $sse->start;
      # ... stream ...
  });

Three common reasons to decline:

=over 4

=item * B<404> -- no such SSE endpoint. C<PAGI::App::Router> already does this
for an unmatched SSE route (see L</SSE Routes>); you rarely write it by hand.

=item * B<401> / B<403> -- authentication or authorization failed; don't open a
stream.

=item * B<204> -- the spec's mechanism to B<stop> an C<EventSource> from
reconnecting. A browser's C<EventSource> reconnects on any non-success or
network drop; answering the request with C<204 No Content> tells it to stop for
good.

=back

  # Tell EventSource to stop reconnecting: a bare 204.
  await $sse->decline(status => 204);

A decline is not a disconnect: no C<sse.disconnect> event ever follows it,
because the stream never started. If your code calls C<< $sse->receive >> (or
anything that reads C<$receive> directly) after a decline expecting to
observe that non-event, it parks forever instead -- there is nothing left to
receive. Return right after declining, as above.

First-send-wins picks the mode: once you have sent C<sse.start> a decline
raises, and once you have sent C<sse.http.response.start> a stream event
(C<sse.send>, C<sse.start>, ...) raises. Decide before you start.

See L<PAGI::SSE/decline> for the method and
L<PAGI::Spec::Www/"Decline SSE - C<send> event"> for the protocol events and
the full state machine.

=head3 Under the hood

C<decline> sends C<sse.http.response.start> followed by
C<sse.http.response.body> on the raw C<$send> (the same one you passed to
C<< PAGI::SSE->new >>), then marks the connection closed. This is what it is
doing on your behalf -- shown so the underlying contract is explicit, not as
a recommended application style:

  # Equivalent to: await $sse->decline(status => 401, headers => [...], body => 'Unauthorized');
  await $send->({
      type    => 'sse.http.response.start',
      status  => 401,
      headers => [['content-type', 'text/plain']],
  });
  await $send->({ type => 'sse.http.response.body', body => 'Unauthorized', more => 0 });

=head1 BACKGROUND WORK

Web requests should respond quickly. Long-running work should be done in the background.

=head2 Fire-and-Forget Async I/O

For non-blocking operations (async HTTP calls, async database queries),
use C<< ->on_fail() >> to handle errors, then C<< ->retain() >> to prevent
"lost future" warnings:

  use strict;
  use warnings;
  use Future::AsyncAwait;
  use Future::IO;
  use PAGI::App::Router;
  use PAGI::Compose qw(compose);
  use PAGI::Response;

  my $router = PAGI::App::Router->new;

  # Simulated async email service
  async sub send_welcome_email {
      my ($email) = @_;
      # In reality: await $http_client->post_async($email_api, ...);
      await Future::IO->sleep(2);
      warn "Email sent to $email\n";
  }

  $router->post('/signup', raw => async sub {
      my ($scope, $receive, $send) = @_;
      my $res = PAGI::Response->new($scope);

      # Respond immediately -- the client does not wait for the email
      await $res->status(201)->json({ status => 'created' })->respond($send);

      # Fire-and-forget: scheduled now, runs on later event-loop ticks
      # (after this handler returns). Always add on_fail() before retain()
      # to avoid silently swallowing errors.
      send_welcome_email('user@example.com')
          ->on_fail(sub { warn "Email send failed: @_" })
          ->retain();
  });

  compose(app => $router)->to_app;

B<Warning:> C<< ->retain() >> alone silently swallows errors - always add
C<< ->on_fail() >> first.

B<Middleware authors:> If your middleware inherits from L<IO::Async::Notifier>,
use C<< $self->adopt_future($f) >> instead. It properly tracks futures and
propagates unhandled errors to the notifier's C<invoke_error> method.

=head2 CPU-Bound Work in Subprocess

B<Note:> This pattern uses L<IO::Async::Function>, which is specific to
L<PAGI::Server>'s L<IO::Async> backend. It won't work with other PAGI servers.

For blocking or CPU-intensive work, use L<IO::Async::Function> to run in a child process:

  use strict;
  use warnings;
  use Future::AsyncAwait;
  use IO::Async::Function;
  use IO::Async::Loop;
  use PAGI::App::Router;
  use PAGI::Compose qw(compose);
  use PAGI::Response;

  my $loop = IO::Async::Loop->new;

  # Worker runs code in subprocess
  my $pdf_worker = IO::Async::Function->new(
      code => sub {
          my ($data) = @_;
          # This blocking code runs in a CHILD PROCESS
          # It doesn't block the main event loop
          sleep 5;  # Simulate heavy work
          return "PDF generated for $data";
      },
  );
  $loop->add($pdf_worker);

  my $router = PAGI::App::Router->new;

  $router->post('/generate-pdf', raw => async sub {
      my ($scope, $receive, $send) = @_;
      my $res = PAGI::Response->new($scope);

      # Option A: Wait for result (blocks this request only)
      my $result = await $pdf_worker->call(args => ['report']);
      await $res->json({ result => $result })->respond($send);

      # Option B: respond immediately, generate in the background
      # await $res->json({ status => 'processing' })->respond($send);
      # my $f = $pdf_worker->call(args => ['report']);
      # $f->on_done(sub { warn "PDF ready: $_[0]\n" });
      # $f->on_fail(sub { warn "PDF failed: $_[0]\n" });
      # $f->retain();
  });

  compose(app => $router)->to_app;

B<Warning:> IO::Async::Function forks child processes. If running with C<--workers N>, each server worker forks its own Function workers. With 4 server workers and 2 Function workers each, you have 12 processes. For high-volume CPU work, consider a dedicated job queue instead.

See C<examples/background-tasks/> for complete working examples.

=head1 COMMAND-LINE RECIPES

=head2 Environment Modes

pagi-server auto-detects development vs production mode based on whether
you're running in an interactive terminal:

  # Development mode (TTY detected) - Lint middleware + access logging
  pagi-server app.pl

  # Production mode (no TTY, e.g., systemd/docker) - no middleware, no logging
  # This happens automatically when running as a daemon

  # Explicit mode selection
  pagi-server -E production app.pl
  pagi-server -E development app.pl
  pagi-server -E none app.pl  # Disable all auto-middleware

  # Via environment variable
  PAGI_ENV=production pagi-server app.pl

  # Enable logging in production (writes to file)
  pagi-server -E production --access-log /var/log/pagi.log app.pl

  # Disable auto-middleware even in development
  pagi-server --no-default-middleware app.pl

=head2 Inline Apps with -e

Like C<perl -e>, you can run inline PAGI apps. This is useful for quick
tests or one-liners:

  # Quick static file server
  pagi-server -MPAGI::App::Directory \
      -e 'PAGI::App::Directory->new(root => "/var/www")->to_app'

  # Serve a single file
  pagi-server -MPAGI::App::File \
      -e 'PAGI::App::File->new(root => ".")->to_app'

  # Quick redirect
  pagi-server -MPAGI::Compose -MPAGI::Pages \
      -e 'PAGI::Compose::compose(app => PAGI::Pages->redirect("https://example.com"))->to_app'

=head2 Loading Modules with -M

The C<-M> flag loads modules before C<-e> code runs, like C<perl -M>:

  # Load multiple modules
  pagi-server -MPAGI::App::File -MPAGI::Middleware::Builder \
      -e 'use PAGI::Middleware::Builder; builder { enable "GZip"; PAGI::App::File->new(root => ".") }'

  # Cuddled form (no space after -M)
  pagi-server -MPAGI::App::File -e 'PAGI::App::File->new(root => ".")->to_app'

=head2 Common pagi-server Patterns

  # Development with verbose logging
  pagi-server --log-level debug app.pl

  # Production multi-worker deployment
  pagi-server -E production --host 0.0.0.0 -p 80 --workers 4 app.pl

  # With custom library paths
  pagi-server -I ./lib -I ./local/lib app.pl

  # HTTPS with TLS
  pagi-server --ssl-cert cert.pem --ssl-key key.pem -p 443 app.pl

  # Daemonized with PID file
  pagi-server -D --pid /var/run/pagi.pid app.pl

  # Maximum performance (no access logging)
  pagi-server --no-access-log --workers 8 -E production app.pl

  # Using EV event loop for better performance
  pagi-server --loop EV app.pl

=head1 DEPLOYMENT

=head2 TLS/HTTPS

L<PAGI::Server> supports TLS natively:

  pagi-server app.pl --port 443 \
      --ssl-cert /path/to/cert.pem \
      --ssl-key /path/to/key.pem

For development, generate a self-signed certificate:

  openssl req -x509 -newkey rsa:4096 -keyout key.pem -out cert.pem \
      -days 365 -nodes -subj '/CN=localhost'

  pagi-server app.pl --port 3443 \
      --ssl-cert cert.pem --ssl-key key.pem

Then access via C<https://localhost:3443> (browser will warn about self-signed cert).

See C<examples/11-tls-https/> for more TLS configuration options.

=head2 Serving Large Files with X-Sendfile

For production deployments behind a reverse proxy (Nginx, Apache), use
L<PAGI::Middleware::XSendfile> to delegate file serving to the proxy.
This frees your application worker immediately while the proxy handles
the file transfer using optimized kernel sendfile.

=head3 Why X-Sendfile?

Direct file serving from your application ties up a worker process for
the entire transfer. With slow clients or large files, this limits your
concurrency. X-Sendfile lets your app send a header telling the proxy
to serve the file:

  # Your app sends:
  X-Accel-Redirect: /protected/files/large.bin
  Content-Type: application/octet-stream

  # Nginx intercepts and serves the file directly

Benefits:

=over 4

=item * Worker freed immediately after sending headers

=item * Proxy uses kernel sendfile (zero-copy, efficient)

=item * Proxy handles Range requests, caching, connection management

=item * Slow clients don't block your app

=back

=head3 Nginx Configuration

Configure an internal location for protected files:

  # nginx.conf
  location /protected/ {
      internal;                       # Only accessible via X-Accel-Redirect
      alias /var/www/files/;          # Actual file location
  }

=head3 Application Setup

  use strict;
  use warnings;
  use Future::AsyncAwait;
  use PAGI::Middleware::Builder;
  use PAGI::App::File;

  my $app = builder {
      enable 'XSendfile',
          type    => 'X-Accel-Redirect',
          mapping => { '/var/www/files/' => '/protected/' };

      PAGI::App::File->new(
          root          => '/var/www/files',
          handle_ranges => 0,  # Let nginx handle Range requests
      );
  };

B<Note:> Setting C<handle_ranges =E<gt> 0> is important. It tells your app
to ignore Range headers and always send full files. The reverse proxy will
handle Range requests more efficiently using its native sendfile.

=head3 Custom Download Handler

For more control (authentication, logging, custom headers):

  use Future;
  use Future::AsyncAwait;
  use PAGI::App::Router;
  use PAGI::Pages;
  use PAGI::Request;
  use PAGI::Utils qw(path_from_root);

  my $router = PAGI::App::Router->new;

  $router->get('/download/{filename}', raw => async sub {
      my ($scope, $receive, $send) = @_;
      my $req = PAGI::Request->new($scope, $receive);

      my $filename = $req->path_param('filename');
      my $filepath = path_from_root('/var/www/files', $filename);
      unless (defined $filepath) {
          my $response = PAGI::Pages->forbidden($scope);
          return await Future->wrap($response->respond($send));
      }

      # Authentication and authorization are separate from path validation.
      my $user = authenticate($scope);
      unless ($user && can_download($user, $filepath)) {
          my $response = PAGI::Pages->forbidden($scope);
          return await Future->wrap($response->respond($send));
      }

      unless (-f $filepath && -r $filepath) {
          my $response = PAGI::Pages->not_found($scope);
          return await Future->wrap($response->respond($send));
      }

      # Validate request-derived header data independently.
      my ($download_name) = $filename =~ /\A([A-Za-z0-9][A-Za-z0-9._-]*)\z/;
      unless (defined $download_name) {
          my $response = PAGI::Pages->forbidden($scope);
          return await Future->wrap($response->respond($send));
      }

      # Send file response directly via raw protocol events (XSendfile middleware will intercept)
      await Future->wrap($send->({
          type    => 'http.response.start',
          status  => 200,
          headers => [
              ['content-type', 'application/octet-stream'],
              ['content-disposition', qq{attachment; filename="$download_name"}],
          ],
      }));
      return await Future->wrap($send->({
          type => 'http.response.body', file => $filepath, more => 0,
      }));
  });

  my $app = builder {
      enable 'XSendfile',
          type    => 'X-Accel-Redirect',
          mapping => { '/var/www/files/' => '/protected/' };
      $router;
  };

Replace C<authenticate> and C<can_download> with application policy. The
request filename is used only after independent path and header validation;
the validated lexical C<$filepath> is the C<file> event intercepted by
XSendfile. Hash mappings are component-aware, use the most-specific source
prefix, and leave an unmatched original C<file> event unchanged rather than
publishing a raw proxy path.

=head3 Apache Configuration (mod_xsendfile)

Enable mod_xsendfile and whitelist your file directory:

  # Apache config
  XSendFile On
  XSendFilePath /var/www/files

  # Application
  my $app = builder {
      enable 'XSendfile', type => 'X-Sendfile';
      $my_app;
  };

=head3 Filehandle Support

The middleware also works with filehandle responses, but only if the
filehandle object has a C<path()> method. L<IO::File::WithPath> from CPAN
is an easy drop-in for this:

  use IO::File::WithPath;

  # This works - IO::File::WithPath provides the path method
  my $fh = IO::File::WithPath->new('/path/to/file.bin', 'r');
  await $send->({ type => 'http.response.body', fh => $fh });

  # This does NOT trigger X-Sendfile (no path method)
  open my $plain_fh, '<', '/path/to/file.bin';
  await $send->({ type => 'http.response.body', fh => $plain_fh });

For plain filehandles, either use C<file =E<gt> $path> directly, or use
L<IO::File::WithPath>. See L<PAGI::Middleware::XSendfile> for details.

=head1 RESPONSE STATE & LIFECYCLE

A C<PAGI::Response> is a detached value: building it is fully separate from
sending it. That split means there is no single "is this done?" flag — instead
there are a few distinct signals, each answering a different question. This
section maps them so you can tell, at any point, what is going on.

=head2 The three phases

A response moves through three phases. Each has its own signal:

=over 4

=item 1. B<Build> — the handler accumulates status, headers, and a body source
on the value. No connection, no I/O. The signal here is L<PAGI::Response/has_body_source>:
"has a body source been registered?"

=item 2. B<Send committed> — C<< $ctx->respond($res) >> (or a raw
C<< $res->respond($send) >> behind the context's guard) has begun emitting the
response and has taken the connection. The signal is L<PAGI::Response/is_sent>:
"has this response gone out?" It is set at the moment the send is committed, so
a second send is rejected.

=item 3. B<Finished> — every byte has been emitted; for a stream, the callback
has run to completion and the writer is closed. There is no flag for this: it is
the resolution of the Future returned by C<respond>. C<await>-ing the send B<is>
waiting for "finished".

=back

The reason "finished" is a Future and not a flag is the same reason the value is
detached: PAGI never models a half-sent live byte-sink as state on the value.
"Committed" is a flag; "finished" is the thing you C<await>.

=head2 The signals you can inspect

  Signal                      Phase          Question it answers
  --------------------------  -------------  -------------------------------------
  has_status                  build          Was a status code set explicitly?
  has_header($name)           build          Was this header set?
  has_content_type            build          Was Content-Type set?
  has_body_source             build          Was a body (bytes/file/stream) set?
  is_sent                     send           Has the response been emitted?
  (Future from respond)       finished       Has every byte been written?
  $writer->bytes_written      finished*      How many bytes streamed so far?
  $writer->is_closed          finished*      Has the stream writer been closed?

The C<$writer> signals (*) apply only while streaming, on the
L<PAGI::Response::Writer> handed to your C<stream> callback or returned by
C<writer>. They describe the live stream; the response value itself only carries
the build and send signals.

=head2 has_body_source is intent, not bytes

The signal most likely to surprise you is C<has_body_source>. It reports that a
body B<source> is registered — not that bytes exist, and not that anything was
sent. For a stream this matters: the callback is stored at build time and does
not run until C<respond>, so a freshly-registered stream has produced zero bytes
yet C<has_body_source> is already true. That is deliberate and is the only
coherent meaning — C<respond> is what drives the stream, so "are there bytes
yet?" is unanswerable at build time and irrelevant to "is there a body to send?"

This mirrors the distinction Node.js draws between C<writableEnded> ("the
producer declared it is done") and C<writableFinished> ("all data has been
flushed"). C<has_body_source> is the former, decoupled from any I/O;
C<await>-ing C<respond> is the latter.

Intentional empty bodies count as a registered source: C<empty>, C<redirect>,
and C<send_raw('')> all set an (empty) body, so C<has_body_source> is true for
them. Only a response that never had a body method called reports false.

=head2 Deciding "did the handler produce a response?"

A framework that lets handlers populate C<< $ctx->res >> and then auto-sends it
needs to know, after the handler returns, whether to send, skip, or fall through
to the next route. That is a three-way decision, and it is a precedence ladder —
not a single predicate:

    # After running the handler, which mutated $ctx->res:
    if ($ctx->res->is_sent) {
        # The handler already took the connection itself — e.g. it called
        # ->writer($send) for live streaming, or used SSE/WebSocket. Do nothing;
        # sending again would be a double-send.
    }
    elsif ($ctx->res->has_body_source || $ctx->res->has_status) {
        # The handler registered a body, or set a status (a bare 204 / redirect
        # has no body but IS a response). Send it once, through the guard.
        await $ctx->respond($ctx->res);
    }
    else {
        # The handler touched nothing send-able — fall through to the next match
        # (or a 404).
    }

Three things make this ladder correct:

=over 4

=item * B<Check C<is_sent> first.> A handler that called C<< ->writer($send) >>
has already emitted headers (C<writer> marks the response sent), but
C<has_body_source> stays false because the live-writer path bypasses the body
slots. Without the C<is_sent> guard you would mistake an actively-streaming
response for "nothing produced".

=item * B<C<|| has_status> is required.> A C<302> redirect or a C<204> can have
no body source, yet it is a real response. C<has_status> catches the
status-only case so you do not 404 a legitimate empty-body response.

=item * B<Never inspect the private slots.> Use C<has_body_source>, not
C<< exists $res->{_stream} >> and friends — those are private and may change
(see L<PAGI::Response/SUBCLASSING (FRAMEWORK INTEGRATION)>). The predicate is
the supported way to ask.

=back

If instead your framework has handlers B<return> the response (PAGI's own
endpoint contract), you do not need this ladder at all: the returned value is
the answer, and "fall through" is an explicit sentinel you define, not an
inference from an empty response.

=head1 TESTING

Use L<PAGI::Test::Client> to test apps directly without a running server:

  use strict;
  use warnings;
  use Test2::V0;
  use PAGI::Test::Client;

  # Load your app
  my $app = require './app.pl';
  my $client = PAGI::Test::Client->new(app => $app);

  subtest 'GET /' => sub {
      my $res = $client->get('/');
      is $res->status, 200, 'status is 200';
      like $res->text, qr/Hello/, 'body contains Hello';
  };

  subtest 'POST /api/users' => sub {
      my $res = $client->post('/api/users',
          json => { name => 'Alice' },
      );
      is $res->status, 201, 'status is 201';
      is $res->json->{id}, 1, 'returns user id';
  };

  subtest 'form submission' => sub {
      my $res = $client->post('/login',
          form => { user => 'admin', pass => 'secret' },
      );
      is $res->status, 302, 'redirects after login';

      # Session cookies persist across requests
      my $dashboard = $client->get('/dashboard');
      is $dashboard->status, 200, 'authenticated access';
  };

  subtest 'custom headers' => sub {
      my $res = $client->get('/api/data',
          headers => { Authorization => 'Bearer token123' },
      );
      is $res->status, 200;
  };

  done_testing;

See L<PAGI::Test::Client> for the full API including WebSocket and SSE testing.
