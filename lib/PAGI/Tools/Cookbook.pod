=head1 NAME

PAGI::Tools::Cookbook - Recipes for Common PAGI Tasks

=head1 DESCRIPTION

This cookbook provides ready-to-use solutions for common web development tasks
with PAGI. Each recipe is self-contained and can be adapted to your needs.

B<Prerequisites:> This cookbook assumes you've read L<PAGI::Tutorial> (the
PAGI protocol tutorial) and L<PAGI::Tools::Tutorial> (this distribution's
guide to middleware, helper classes, and built-in apps).

=head1 ROUTING RECIPES

These recipes use the sole routing-construction API, L<PAGI::Routing>. For a
small runnable declarative app, see F<examples/declarative-routing>.

  Endpoint::HTTP/WebSocket/SSE  optional behavior for one exact route
  Route                         exact path and HTTP method policy
  Mount                         prefix ownership and app composition
  Router                        ordered children and NONE/PARTIAL outcomes
  Compose                       root lifespan, middleware, and safety

L<PAGI::Routing/HANDLERS> says what a coderef or object means in each
position.

=head2 HTTP Defaults: Pages, Request Handlers, and Native Applications

Without C<http_default> the Router answers HTTP NONE and PARTIAL in plain
text. Put a source-free Pages application directly in C<http_default> for the
ordinary custom 404:

  use PAGI::Pages qw(not_found);
  use PAGI::Routing qw(router);

  my $routing = router(
      routes       => \@routes,
      http_default => not_found(detail => 'No route matched.'),
  );

For the application's own presentation, give C<http_default> a page from a
configured Pages instance instead of the function; PARTIAL remains the
Router's plain-text 405 with authoritative C<Allow>:

  use PAGI::Compose qw(compose);
  use PAGI::Pages;
  use PAGI::Routing qw(mount router);

  my $pages = PAGI::Pages->new;

  my $routing = router(
      routes       => \@routes,
      http_default => $pages->not_found(
          detail => 'No application route matched.',
      ),
  );
  my $app = compose(
      routes => [mount('/' => app => $routing)],
  )->to_app;

Pages selects HTML, RFC 9457 problem JSON, or text from C<Accept>, adds
C<Vary: Accept>, and defaults errors to C<Cache-Control: no-store>. Use a
configured Pages instance or subclass here for application presentation; no
Pages object is discovered through Compose or global state.

When the response depends on the Request, use a bare one-Request handler:

  use PAGI::Response qw(response);

  my $routing = router(
      routes => \@routes,
      http_default => sub ($request) {
          return response('Problem', {
              title  => 'Not Found',
              status => 404,
              detail => 'No route matched ' . $request->path,
          });
      },
  );

Use C<as_app_object> only for an advanced native PAGI default. It marks the
three-channel CODE explicitly. C<request_response> instead adapts a
one-Request handler into Mount C<app>; ordinary C<http_default> use needs no
adapter.

A selected application's own 404 or 405 is left untouched. C<http_default>
runs only for HTTP NONE: it never receives a method mismatch, WebSocket or SSE
miss, selected handler exception, or handler-returned 404. GET contributes
HEAD to the Router-generated 405 union.

=head2 A Declarative Route Tree with Package Handlers

Load handler packages normally and pass fully qualified coderefs. This gives
Perl's usual compile-time loading and avoids method-name strings or signature
guessing:

  package MyApp::Routes::Home;
  use strict;
  use warnings;
  use Future::AsyncAwait;
  use PAGI::Response;

  async sub home {
      my ($request) = @_;
      return PAGI::Response::response('HTML', '<h1>Home</h1>');
  }

  1;

  # app.pl
  use MyApp::Routes::Home ();
  use PAGI::Compose qw(compose);
  use PAGI::Routing qw(:routes);

  compose(
      routes => [
          route('/' => \&MyApp::Routes::Home::home, name => 'home'),
      ],
  )->to_app;

The final expression is the complete native PAGI app; a Router compiled with
its own C<to_app> instead has no root ErrorHandler, response guard, or
lifespan (L<PAGI::Compose/RELATIONSHIP TO OTHER PAGI APIS>).

=head2 An Application's Request Class

Give every handler the application's own Request subclass with one
middleware:

  use v5.40;
  use PAGI::Tools qw(compose middleware response route);

  package MyCompany::Request {
      use parent 'PAGI::Request';

      sub company_name($self) { return 'Example Corp' }
  }

  package main;

  my $app = compose(
      middleware => [middleware('RequestClass', class => 'MyCompany::Request')],
      routes     => [route('/reports' => sub ($request) {
          return response('Text', $request->company_name . ' reports');
      })],
  );

Route handlers, Endpoint::HTTP methods, C<refuse> handlers, WebSocket
C<deny> / SSE C<decline> handlers, an ErrorHandler C<handler> listed after
the middleware, and Authentication C<backend>s below it all receive a
C<MyCompany::Request>, in mounted applications too. The class's C<new> must
accept WebSocket and SSE scopes, and should be cheap and leave the body
unread: an endpoint built per request calls it twice. For one or two
helpers, a function that takes the request is simpler. See L<PAGI::Middleware::RequestClass> for the order, the costs, and
the hand-written equivalent.

=head2 Custom Request Route Helpers

A project or higher-level framework can give some routes a different Request
class than the application's. Build a named helper from C<request_response>,
whose C<request_factory> wins over the scope's class, and return an ordinary
Route:

  use v5.40;
  use PAGI::Response qw(response);
  use PAGI::Routing qw(route request_response);

  package MyCompany::Request {
      use parent 'PAGI::Request';

      sub company_name($self) { return 'Example Corp' }
  }

  package MyCompany::Routing {
      use Exporter qw(import);

      our @EXPORT_OK = qw(my_special_route);

      sub my_special_route($path, $handler, @options) {
          return PAGI::Routing::route(
              $path => PAGI::Routing::request_response(
                  $handler,
                  request_factory => sub ($scope, $receive) {
                      return MyCompany::Request->new($scope, $receive);
                  },
              ),
              @options,
          );
      }
  }

  package main;
  MyCompany::Routing->import('my_special_route');

  sub reports($request) {
      return response('Text', $request->company_name . ' reports');
  }

  my $route = my_special_route('/reports' => \&reports,
      methods => ['GET'],
      name    => 'reports',
  );

In a normal distribution, put the two packages under F<lib/> and load the
helper with Perl's usual compile-time import:

  use MyCompany::Routing qw(my_special_route);

  my $route = my_special_route('/reports' => \&reports,
      methods => ['GET'],
      name    => 'reports',
  );

C<my_special_route> creates no new node type. Its result is a normal immutable
L<PAGI::Routing::Route>, so method selection, middleware, constraints, names,
reverse routing, descriptions, and inspection continue to use the core
Router. The request factory runs synchronously once for each matching request,
receives the exact C<($scope, $receive)> pair, and must return a
L<PAGI::Request> instance or subclass. It must not consume the request body or
return a Future.

Because the helper package calls C<route>, an unqualified inline provider such
as C<{id:&ReportId}> resolves in C<MyCompany::Routing>. This is useful when the
helper package owns the routing dialect. Use an explicit C<constraints> value
or a qualified provider such as C<{id:&MyApp::Types::ReportId}> when the
constraint belongs elsewhere.

=head2 Inline, Router, and Application Mounts

The C<routes> form constructs a complete child Router. Its names and reverse
paths are known to the parent, and its own 404/405 outcomes remain final:

  mount('/tenants/{tenant_id}',
      routes => [
          route('/users/{user_id}' => \&show_user, name => 'user'),
      ],
      name        => 'tenant',
      constraints => { tenant_id => qr/[a-z0-9-]+/ },
  )

For C</tenants/acme/users/42>, child handlers and mount/route middleware see
C<tenant_id =E<gt> 'acme'> and C<user_id =E<gt> '42'> in
C<path_params>. The child C<path> is C</users/42>, C<root_path> contains the
actual C</tenants/acme> prefix, and C<raw_path> remains the full path the client
requested.
Reverse routing supplies both captures:

  use PAGI::Routing::URL qw(path_for);

  path_for($request, '/tenant/user', {
      tenant_id => 'acme',
      user_id   => 42,
  });

Use C<app> for a separately configured modular Router:

  package MyApp::People;
  use PAGI::Routing qw(router route);

  sub routing {
      return router(routes => [
          route('/' => \&index, name => 'index'),
          route('/{person_id}' => \&show, name => 'show'),
      ], desc => 'People routes');
  }

  package MyApp::Root;
  use PAGI::Routing qw(router route mount);
  use MyApp::People ();

  sub routing {
      my $people = MyApp::People->routing;
      return router(routes => [
          route('/' => \&home, name => 'home'),
          mount('/people',
              app  => $people,
              name => 'person',
          ),
      ]);
  }

The root resolver publishes C</home>, C</person/index>, and
C</person/show>. The child Router keeps only its local descriptions; inside a
request, L<PAGI::Routing::URL> uses the active placement for relative calls
such as C<< path_for($request, 'show') >>. After C</people> matches, the child Router owns its
full, partial, and no-match results. Its 404 or 405 flows through child Router,
Mount-occurrence, and enclosing Router middleware; the root never resumes
sibling scanning.

An application mount uses the same C<app> option:

  mount('/admin', app => $admin_app)

It applies no HTTP method filter, and its child names are not visible to the
parent.

A Router in C<app> makes a Router mount, which the parent can inspect; any
other C<to_app> object or native coderef makes an application mount, which it
cannot. Either kind may be named or unnamed; the name controls
reverse-routing hierarchy, not dispatch mode.

A native Route leaf is different again:

  use PAGI::Utils qw(as_app_object);
  route('/files/*path' => as_app_object($file_endpoint), methods => ['GET'])

That is one exact/wildcard HTTP leaf. It participates in methods, automatic
HEAD, partial matching, and names, and receives the original routed path. A
C<< mount('/files', app =E<gt> $file_app) >> owns a protocol-capable prefix,
receives the implicit remainder in child C<path>, and extends C<root_path>.
For an object endpoint, a finite explicit method declaration still consults
C<allowed_methods> once and must be a restriction of that snapshot.
L<PAGI::Routing::Route> has the complete method rules.

Mounts are declaration-ordered owners. Put a narrow mount before a broad one.
C<mount('/api')> accepts both C</api> and C</api/> directly and passes child
path C</>; unlike Starlette's default behavior it does not redirect C</api> to
C</api/>.

A separately configured child can own local missing-route presentation:

  my $api = router(
      routes => [route('/items' => \&items)],
      http_default => PAGI::Pages->not_found(
          detail => 'No API route matched.',
      ),
  );
  my $root = router(routes => [
      mount('/api', app => $api, name => 'api'),
      route('/api/missing' => \&unreachable),
  ]);

C<unreachable> is never considered.

=head2 Serving behind a proxy prefix

When a reverse proxy publishes the application under C</app>, every link and
redirect it emits must start with C</app>. The application sees C<root_path>
C</app> and its own C<path> below it (see
L<PAGI::Spec::Www/Paths, Mounts and Root Paths>), and C<path_for>,
C<url_for>, L<PAGI::HTTPConnection/request_uri> and the C<next> of a
L<PAGI::Middleware::Requires> redirect all include the prefix. Test it as it will be served, requesting the browser's URL:

  use v5.40;
  use PAGI::Compose qw(compose);
  use PAGI::Response qw(response);
  use PAGI::Routing qw(route);
  use PAGI::Routing::URL qw(path_for);
  use PAGI::Test::Client;

  my $app = compose(routes => [
      route('/reports' => sub ($request) {
          response('JSON', {
              path      => $request->path,                # /reports
              root_path => $request->scope->{root_path},  # /app
              here      => $request->request_uri,         # /app/reports?x=1
              link      => path_for($request, 'reports'), # /app/reports
          });
      }, name => 'reports'),
  ]);

  # As a server configured with root path /app serves it, behind a proxy
  # that removes /app before forwarding.
  my $client = PAGI::Test::Client->new(app => $app, root_path => '/app');
  my $report = $client->get('/app/reports?x=1')->json;

The client's C<root_path> builds the scope such a server builds, with the
application still the root, so its own lifespan runs.

A proxy that forwards C</app> unchanged needs the application mounted at the
prefix -- C<< compose(routes => [mount('/app', app => $app)]) >> -- which
gives each request the same scope. B<A mounted application's own lifespan
does not run> (see L<PAGI::Compose/LIFESPAN OWNERSHIP AND STATE>): lift its
startup and shutdown into the outer C<compose>.

Use C<raw_path_info> only where the encoded path below the mount matters
(telling C<%2F> from C</>), and never use C<raw_path> to decide access.

=head2 Complete Declarative Apples Application

This is the complete runnable shape from F<examples/starlette-apples/app.pl>:

  use v5.40;

  use Future::AsyncAwait;
  use Types::Standard qw(Int);

  use AppleApp::Middleware qw(with_apples_api_header);
  use AppleApp::Model qw(apple_model);
  use PAGI::Compose qw(compose);
  use PAGI::Pages qw(welcome not_found status);
  use PAGI::Response qw(response);
  use PAGI::Routing qw(route mount middleware);
  use PAGI::Routing::URL qw(url_for path_for);
  use PAGI::Utils qw(app_path);

  my $manager_file = app_path('public', 'index.html');

  sub startup($state, $scope) {
      $state->{apples} = apple_model();
      return;
  }

  sub apples($request) {
      my $state = $request->state
          or die 'starlette-apples requires Compose lifespan state';
      return $state->get('apples');
  }

  async sub list_apples($request) {
      my $apples = apples($request);

      return response('JSON', [
          map {
              +{
                  %$_,
                  url => url_for(
                      $request,
                      'read',
                      { apple_id => $_->{id} },
                  ),
              }
          } @{$apples->all}
      ]);
  }

  async sub export_apples($request) {
      my $items = apples($request)->all;

      return response('NDJSON', async sub ($writer) {
          for my $apple (@$items) {
              last if $writer->is_disconnected;
              await $writer->write_item($apple);
          }
      });
  }

  async sub authentication_required($request) {
      return status(401,
          detail  => 'A valid access token is required.',
          headers => ['WWW-Authenticate' => 'Bearer realm="apples"'],
          cache_control => 'no-store',
      );
  }

  async sub read_apple($request) {
      my $id = $request->path_param('apple_id');
      my $apple = apples($request)->find($id);

      return response('JSON', $apple) if $apple;
      return response('JSON',
          { error => 'Apple not found' },
          status => 404,
      );
  }

  async sub create_apple($request) {
      my $data = await $request->json;
      my $apple = apples($request)->create($data);

      return response('JSON',
          $apple,
          status  => 201,
          headers => [
              Location => path_for(
                  $request,
                  'read',
                  { apple_id => $apple->{id} },
              ),
          ],
      );
  }

  async sub update_apple($request) {
      my $id = $request->path_param('apple_id');
      my $apples = apples($request);

      return response('JSON',
          { error => 'Apple not found' },
          status => 404,
      ) unless $apples->find($id);

      my $data = await $request->json;
      my $apple = $apples->update($id, $data);

      return response('JSON',
          { error => 'Apple not found' },
          status => 404,
      ) unless $apple;

      return response('JSON', $apple);
  }

  async sub delete_apple($request) {
      my $id = $request->path_param('apple_id');
      my $apple = apples($request)->delete($id);

      return response('JSON',
          { error => 'Apple not found' },
          status => 404,
      ) unless $apple;

      return response('JSON', {
          success => \1,
          deleted => $apple,
      });
  }

  compose(
      routes => [
          route('/' => response('File', $manager_file, inline => 1),
              name => 'home',
              desc => 'Apple manager SPA',
          ),
          route('/welcome' => welcome(),
              name => 'welcome',
              desc => 'PAGI welcome page',
          ),
          mount('/apples',
              routes => [
                  route('/' => \&list_apples,
                      methods => ['GET'], name => 'list'),
                  route('/' => \&create_apple,
                      methods => ['POST'], name => 'create'),
                  route('/export' => \&export_apples,
                      methods => ['GET'], name => 'export'),
                  route('/auth-required' => \&authentication_required,
                      methods => ['GET'], name => 'auth_required'),
                  route('/{apple_id:&Int}' => \&read_apple,
                      methods => ['GET'], name => 'read'),
                  route('/{apple_id:&Int}' => \&update_apple,
                      methods => ['PUT'], name => 'update'),
                  route('/{apple_id:&Int}' => \&delete_apple,
                      methods => ['DELETE'], name => 'delete'),
              ],
              name       => 'apples',
              middleware => [middleware(\&with_apples_api_header)],
          ),
      ],
      http_default => not_found(
          detail => 'That page does not exist in the Apple demo.',
      ),
      middleware => [middleware('RequestId')],
      lifespan => { startup => \&startup },
      desc     => 'Starlette apples comparison application',
  );
C</apples> and C</apples/> reach the child C</> leaves. C</apples/export> is a
PAGI-only NDJSON export canary, deliberately absent from the Starlette
comparison. The selected child owns
C<PATCH /apples> and its C<Allow: GET, HEAD, POST>. Constraint C<Int> validates
the decoded capture but does not coerce it.

The root file is an instantiated File Response on an exact Route, not a Mount:
C</> alone selects it. C</welcome> is a source-free Pages application endpoint. The
C</apples> Mount owns that complete subtree, so child 404 and 405 outcomes do
not fall through to root siblings. Inside that logical namespace, local
reverse address C<read> means C</apples/read>; there is no namespace
deduplication rule.

The source-free Pages application is placed directly at root
C<http_default>. It runs only for Router NONE, so an unknown path stays 404
while a known path with the wrong method retains the Router's authoritative
405 and Allow field. A catch-all Route would be a real FULL/PARTIAL candidate
and would change those method outcomes.

=head2 Declarative Middleware Placement and Helpers

Middleware entries are pure app-to-app PAGI wrappers, nested in the order
L<PAGI::Routing/MIDDLEWARE AND HEAD> shows; the first entry in each list is
outermost.

Use L<PAGI::Utils::Middleware> to keep channel ownership visible:

  use Future::AsyncAwait;
  use PAGI::Utils::Middleware qw(clone_scope wrap_send wrap_receive);
  use PAGI::Routing qw(:routes :middleware);

  my $factory = sub {
      my ($app) = @_;

      return async sub {
          my ($scope, $receive, $send) = @_;

          # Immediate request-local shallow state change; no I/O.
          my $child = clone_scope($scope, { 'pagi.request_id' => make_id() });

          # Construction only: no event has been emitted or received yet.
          my $out = wrap_send($send, async sub {
              my ($event, $downstream) = @_;
              if (($event->{type} // '') eq 'http.response.start') {
                  $event = {
                      %$event,
                      headers => [@{$event->{headers} // []},
                          ['x-request-id', $child->{'pagi.request_id'}]],
                  };
              }
              await $downstream->($event); # this actually emits and awaits
          });

          my $in = wrap_receive($receive, async sub {
              my ($downstream) = @_;
              my $event = await $downstream->(); # receive happens here
              return $event;
          });

          await $app->($child, $in, $out);
      };
  };

  my $routing = router(
      routes => [
          route('/' => \&home, middleware => [middleware($factory)]),
      ],
      # Both core entries are explicit middleware descriptions.
      middleware => [middleware('RequestId', header => 'X-Request-ID')],
  );

C<wrap_send> and C<wrap_receive> never delegate automatically. An interceptor
may short-circuit, replace, expand, filter, or synthesize events. Return or
await the downstream Future when completion, failure, and backpressure must
remain attached. Factory execution happens once during C<to_app>; returned
wrappers run per request. Core Router, Route, Mount, and Compose lists contain
only C<middleware(...)> descriptions.

=head2 Compose Safety and Application Error Policy

Compose installs the same root safety graph around the distinct root Router it
constructs from C<routes>. It takes the ErrorHandler out of C<middleware>,
wherever it is listed, and places its two halves as Starlette builds an
application -- C<ServerErrorMiddleware> outermost, C<ExceptionMiddleware>
around the router:

  outer idempotent application-root HEAD boundary
    Compose's emergency ErrorHandler (server errors only)
      your ErrorHandler's server-error boundary: handler, on_error
        response-completion guard
          author middleware, in listed order
            your ErrorHandler's exception boundary: catch
              Compose root Router

An error a route throws reaches the exception boundary first: a C<catch> entry
or an HTTP error's built-in answer handles it there, inside every author
middleware. Anything unhandled -- an ordinary bug, or any error an author
middleware throws -- is answered by C<handler> (or the stock 500) outside
them, reported, and re-raised for the server. Without an ErrorHandler of your
own, the emergency one's exception boundary is the one around the router.
Compose's stock error response is a plain-text, no-store 500, with a final
hardcoded UTF-8 text 500 only if an author handler itself fails. One stock
ErrorHandler per Compose: a second dies when the application is built. A
subclass of ErrorHandler is not split; it wraps what follows it, where it is
listed.

Because the 500 is rendered outside the author middleware, and a PAGI scope
is copied rather than changed in place, nothing an author middleware adds
reaches it: not RequestId's C<pagi.request_id> or its C<X-Request-ID> header,
not AccessLog's line for it, not a header SecurityHeaders or CORS sets.
Middleware listed in C<middleware> see the error pass through them as an
exception. Starlette's middleware have the same limit. Request identity,
access logging and globally enforced response headers that must cover
server-error responses wrap Compose instead, with the middleware's own
C<wrap>:

  use PAGI::Middleware::AccessLog;
  use PAGI::Middleware::RequestId;
  use PAGI::Middleware::SecurityHeaders;

  my $composed = compose(
      routes => [mount('/' => app => $routing)],
      middleware => [
          middleware('ErrorHandler',
              handler  => \&server_error,
              on_error => \&report_error),
      ],
  );

  # Outermost first: every response, the 500 included, gets a request ID, an
  # access-log line and the security headers; on_error and the handler see
  # the same pagi.request_id.
  my $app = PAGI::Middleware::RequestId->new->wrap(
      PAGI::Middleware::AccessLog->new->wrap(
          PAGI::Middleware::SecurityHeaders->new->wrap($composed->to_app)));

A bare Router has no root ErrorHandler, response-completion guard, or lifespan
owner, but its compiled app already installs a Router HeadBoundary. If a
selected application sends nothing, a direct Router call completes without
synthesizing a response. Compose wraps that same Router in the safety graph
above; the outer idempotent HEAD boundary becomes the wire owner, and the guard
converts pre-start silence into its production-safe 500.

For example, a database failed Future before response start is awaited by the
author ErrorHandler, reported through C<on_error>, rendered by
C<server_error>, and then re-raised so the server logs it too (see
L</Who reports an application error>). C<on_error> may return immediately or
through a Future; its failure is contained. If the database fails after a streaming response has
started, ErrorHandler awaits reporting, calls no handler, emits no second
start, and rethrows the original database exception so the server can abort.

Ordinary ErrorHandler instances default to static production mode and never
consult C<PAGI_ENV>. Compose's private outer instance resolves development per
handled request and falls back to safe production output if resolution fails.
The built-in answer is plain text. To answer an unhandled error another way,
give ErrorHandler a C<handler>; the errors the application expects get
C<catch> entries (see L</Thrown pages and house-styled errors>):

  use PAGI::ErrorContext qw(error_context);
  use PAGI::Response qw(response);

  middleware('ErrorHandler',
      handler => sub {
          my ($request) = @_;
          my $error = error_context($request);
          return response('HTML', '<h1>Something went wrong</h1>', status => 500)
              unless $error->detail;                  # production
          return $error->default;                     # development: the built-in page, with the detail
      })

A C<handler> answers only unhandled errors: HTTP errors and thrown pages never
reach it. C<error_context($request)> gives the error, its status and a
client-safe message; returning C<< $error->default >> leaves it to the
built-in answer. A handler is authoritative for its own content and headers.

=head3 Who reports an application error

PAGI-Tools turns an exception into a response; it does not report it. The
server does. Given

  compose(routes => [
      route('/boom'    => sub { die "database unreachable\n" }),
      route('/missing' => sub { die My::NotFound->new }),  # status_code() is 404
  ]);

C</boom> gets a 500 page, and after that page is complete Compose re-raises
the exception. PAGI::Server logs it through its own log, where C<log_level>
governs it and a replaced C<logger> receives it:

  PAGI application error (after response complete): database unreachable

C</missing> gets a 404 page and nothing is logged: an HTTP error is handled
-- by a C<catch> entry or its built-in answer -- and a handled error is an
outcome, not a failure. A thrown HTTP error or page of 500 or more is the
exception: it is answered, then re-raised and logged like C</boom>, since
whoever throws a 500 means "this broke" (Starlette logs nothing for an
C<HTTPException(500)>). Otherwise only an unhandled error is re-raised. The same holds for an ErrorHandler you install yourself. Behind a server other than PAGI::Server,
the re-raised exception reaches whatever that server does with an application
failure after a complete response.

This keeps one place responsible for operational errors: the server, which
the operator already configures. Add C<on_error> when you want B<more> than
the server's log, such as an error tracker or paging:

  middleware('ErrorHandler',
      on_error => sub {
          my ($error, $scope) = @_;
          $tracker->capture($error,
              path       => $scope->{path},
              request_id => $scope->{'pagi.request_id'});  # with RequestId around Compose
          return;
      }),

C<on_error> runs before the 500 is rendered; the server still logs the error
afterwards. If ErrorHandlers are nested, an C<on_error> on each of them runs
for the same error, because each one re-raises it.

In tests, L<PAGI::Test::Client> plays the server's part: by default it warns
C<exception after response completed: ...> for a re-raised error, or raises it
with C<< raise_app_exceptions => 1 >>. A test that deliberately provokes a 500
should capture that warning.

=head3 Thrown pages and house-styled errors

Return responses; throw only from code far from the handler. When you do,
L<PAGI::Exception::HTTP> says what went wrong and a thrown Response is an
answer in itself. One ErrorHandler C<catch> entry gives HTTP errors the house
style, as Starlette's C<exception_handlers={HTTPException: ...}> does; thrown
pages answer as they are without one:

  use PAGI::Response qw(response);

  middleware('ErrorHandler', catch => {
      'PAGI::Exception::HTTP' => sub {
          my ($request, $error) = @_;
          return response('JSON', { error => $error->message },
              headers => $error->headers);
      },
  })

An entry answers in full, as a Starlette exception handler does: the error's
headers -- a C<Retry-After>, say -- are sent only if it passes them on. The
exception is a 405's C<Allow>: an entry's 405 that sends none gets the
router's.

A thrown page answers as itself, whatever its status, and never reaches
C<catch>. A thrown object ErrorHandler cannot read as a page -- one with
C<to_app> but no usable status, such as an exception written for Plack -- is
an ordinary error: the stock 500, and its C<to_app> is never run. A thrown
page below 400, such as C<die response('Redirect', '/login')>, is sent at once.

Routing misses reach the entry too. When the innermost ErrorHandler around a
router has C<catch> entries, the router raises a path nothing matches as a 404 HTTP error and a
method a matched path does not allow as a 405 carrying C<Allow>, as
Starlette's router raises C<HTTPException> -- so the entry above answers them
in JSON, and a C<404> or C<405> status entry answers just those. With no entry
for them, they get the router's own plain-text answers, unchanged. A Router
mounted inside raises its misses the same way, unless an ErrorHandler nearer
it decides for it: the innermost ErrorHandler answers, as Starlette's
innermost C<ExceptionMiddleware> does, so an outer C<catch> table never
reaches past an inner ErrorHandler, and a Compose mounted inside answers its
own errors. An explicit C<http_default> still answers a path nothing
matches, before any entry sees it.

=head3 Re-render a form from an error handler

A route can leave the errors its domain raises to one place and still answer
with the form the user typed. A C<catch> entry answering an error a route's
handler threw gets that route's own Request, as a Starlette exception handler
gets the endpoint's: the form the route read, its C<path_param>s, and the
scope keys of middleware inside the ErrorHandler (the session, the CSRF
token).

  use Future::AsyncAwait;
  use PAGI::Tools qw(compose middleware response route);

  package My::TitleTaken { sub new { my ($class, %f) = @_; bless {%f}, $class } }

  my %taken;

  sub html { my ($text) = @_; $text =~ s/([&<>"])/'&#' . ord($1) . ';'/ge; $text }

  sub task_form {
      my ($title, $error, @options) = @_;
      return response('HTML', (defined $error ? '<p class="error">' . html($error) . '</p>' : '')
          . '<form method="post"><input name="title" value="' . html($title) . '">'
          . '<button>Add</button></form>', @options);
  }

  # The route reads the form and raises the board's error; it does not
  # answer it.
  async sub create {
      my ($request) = @_;
      my $title = (await $request->form_params)->get('title') // '';
      die My::TitleTaken->new(title => $title) if $taken{lc $title};
      $taken{lc $title} = 1;
      return response('Redirect', '/', status => 303);
  }

  my $app = compose(
      routes => [route('/tasks' => \&create, methods => ['POST'])],
      middleware => [middleware('ErrorHandler', catch => {
          # The route's own Request: the form create read is there.
          'My::TitleTaken' => async sub {
              my ($request, $error) = @_;
              my $title = (await $request->form_params)->get('title');
              return task_form($title, qq{There is already a task called "$title".}, status => 409);
          },
      })],
  );

This is the route-level part of ErrorHandler only: an error an author
middleware throws gets C<handler>, with a Request that has no body. The
complete application, with templates, the session's CSRF token and a
missing-task entry that names the id from C<path_param>, is
F<examples/internal-tool>, beside the same board in Flask.

=head2 Real Catch-All Routes

A Router default means "nothing matched." A wildcard is a real route:

  router(routes => [
      route('/api/users' => \&users),
      route('/*path' => \&spa, methods => ['GET']), # keep last
  ]);

  router(routes => [
      mount('/docs', routes => [
          route('/assets/*path' => \&asset),
          route('/*path' => \&docs_spa, methods => ['GET']),
      ]),
      route('/health' => \&health),
  ]);

The subtree catch-all affects only C</docs>. A GET-only catch-all makes an
unknown POST a 405 because its path matched partially. C<methods =E<gt> '*'>
turns the catch-all into a full match for every method and can supersede a 405
collected from an earlier specific route.

=head2 Custom HEAD without Running an Expensive GET

Put the explicit HEAD route before GET:

  route('/report' => \&head_report, methods => ['HEAD']),
  route('/report' => \&get_report,  methods => ['GET']),

Reversing the declarations invokes GET for HEAD because GET automatically
includes HEAD and the first full match wins. If C<head_report>'s constraint
returns false, the GET route's automatic HEAD remains the fallback. The router
suppresses the final wire body for either handler while preserving status and
GET-equivalent headers. Put body-derived response middleware in the router's
C<middleware> list, inside that HEAD boundary.

=head2 Constraint Forms and Wildcard Safety

All constraints receive one decoded scalar and validate without coercion;
L<PAGI::Routing/Path parameters, wildcards, and constraints> lists the four
ways to write one. With C<Int> from Types::Standard:

  use Types::Standard qw(Int);
  route('/typed/{id:&Int}' => \&show);

C<Int> accepts signed integers, and the handler gets the text, not a
number: C</typed/09> matches, and C<path_param('id')> is C<"09">, not C<9>.
Numify at the boundary that needs a number:

  async sub show ($request) {
      my $id = 0 + $request->path_param('id');   # "09" -> 9
      return response('JSON', { id => $id });
  }

or use a pattern with one spelling per number, C<{id:[1-9][0-9]*}>, when
C</typed/09> should be a 404 instead (it also refuses C<0> and C<-3>).

A local provider can narrow C<Int> further, here to positive numbers. It
still receives the text, so C<"09"> passes it:

  sub PersonId {
      my $int = Int;
      return sub {
          my ($value) = @_;
          return $int->check($value) && $value > 0;
      };
  }

  route('/people/{id:&PersonId}' => \&show);

C<*path> captures decoded values including C<..>, repeated separators, and
backslashes. Never concatenate that value with a filesystem root. When no
custom authorization or response headers are needed, mount
L<PAGI::App::File> and let it own the complete file response:

  use PAGI::App::File;

  my $files = PAGI::App::File->from_app_path('public')->to_app;

For a native handler that genuinely needs custom policy, validate the request
path before any filesystem check and emit only the returned lexical path:

  use Future;
  use Future::AsyncAwait;
  use PAGI::Pages;
  use PAGI::Utils qw(invoke_app path_from_root);

  my $files = async sub {
      my ($scope, $receive, $send) = @_;
      my $untrusted_path = $scope->{path};

      my $path = path_from_root('/var/www/files', $untrusted_path);
      unless (defined $path) {
          my $response = PAGI::Pages->forbidden;
          return await Future->wrap(invoke_app($response, $scope, $receive, $send));
      }

      unless (-f $path && -r $path) {
          my $response = PAGI::Pages->not_found;
          return await Future->wrap(invoke_app($response, $scope, $receive, $send));
      }

      await Future->wrap($send->({
          type    => 'http.response.start',
          status  => 200,
          headers => [['content-type', 'application/octet-stream']],
      }));
      return await Future->wrap($send->({
          type => 'http.response.body', file => $path, more => 0,
      }));
  };

L<PAGI::Utils/path_from_root> is lexical and performs no I/O. It neither
resolves symlinks nor grants access; run authentication and authorization as
separate policy after it returns. The PAGI server opens the eventual C<file>
event. Configured symlinks extend administrator authority, so use a dedicated
root that attackers cannot modify and enforce suitable filesystem ownership
and permissions. Those are deployment best practices, not physical
confinement enforced by the helper. See the
L<rooted file-serving upgrade guide|https://github.com/jjn1056/PAGI-Tools/blob/main/UPGRADING-REFERENCE.md#rooted-file-serving-security-contract>
for changed status and option behavior.

=head2 Linking inside a mounted app

Route names are logical addresses, not URL paths. A Mount named C<api>
holding a route named C<note> gives the address C</api/note>, whatever
prefix the Mount serves. A reference without a leading C</> resolves from
the namespace of the handler that calls it, so routes inside a Mount link to
their siblings, and up to their parent, without knowing where they are
mounted:

  use v5.40;
  use PAGI::Tools qw(compose mount path_for response route);
  use PAGI::Test::Client;

  my $app = compose(routes => [
      route('/' => sub ($request) {
          # An absolute reference names the full address, from anywhere.
          response('JSON', { note => path_for($request, '/api/note', { id => 1 }) });
      }, name => 'home'),
      mount('/api', routes => [
          route('/notes/{id}' => sub ($request) {
              response('JSON', { id => $request->path_param('id') });
          }, name => 'note'),
          route('/notes' => sub ($request) {
              response('JSON', {
                  notes => path_for($request, 'notes'),     # a sibling: /api/notes
                  home  => path_for($request, '../home'),   # the parent's: /
              });
          }, name => 'notes'),
      ], name => 'api'),
  ]);

  my $client = PAGI::Test::Client->new(app => $app);
  my $from_root = $client->get('/')->json;           # { note => '/api/notes/1' }
  my $from_api  = $client->get('/api/notes')->json;  # { notes => '/api/notes', home => '/' }

Mount the same routes again at C</v2> under the name C<v2>, and
C<path_for($request, 'notes')> gives C</v2/notes> there with no change to the
handlers. The same routes mounted twice work the same way; an absolute
reference names the placement:

  use PAGI::Routing::URL qw(path_for url_for);

  my $routing = router(routes => [
      mount('/api/v1', routes => $shared, name => 'v1'),
      mount('/api/v2', routes => $shared, name => 'v2'),
  ]);

  $routing->path_for('/v1/user', { id => 42 });
  path_for($request, '/v2/user', { id => 42 });
  url_for($request, '/v2/user',  { id => 42 });

A relative reference inherits the captures its target needs, an explicit
value wins, and an absolute reference inherits nothing:

  # Current address: /person/blog/show; captures person_id=42, blog_id=7
  path_for($request, 'index');                    # inherits person_id
  path_for($request, '../show');                  # parent namespace
  path_for($request, 'show', { blog_id => 8 });  # explicit value wins
  path_for($request, '/person/blog/show', {
      person_id => 9,
      blog_id   => 3,
  });                                      # absolute: no inheritance

The full rules -- C<./> and C<../>, absolute references, and which
captures a relative reference inherits -- are in
L<PAGI::Routing::URL/REFERENCES> and L<PAGI::Routing::URL/PLACEMENT AND ROOT PATH>.

=head2 Linking to static files

Name the mount and its name is a link target: C<path_for> gives the
mount's prefix, and with C<path> a file below it, with the proxy prefix
applied. A page that hardcodes C</static/app.css> breaks under a root
path; this does not:

  use v5.40;
  use PAGI::App::File;
  use PAGI::Tools qw(compose mount path_for response route);
  use PAGI::Test::Client;

  my $app = compose(routes => [
      route('/' => sub ($request) {
          response('JSON', {
              css    => path_for($request, 'static', { path => 'css/app.css' }),
              prefix => path_for($request, 'static'),
          });
      }, name => 'home'),
      mount('/static', app => PAGI::App::File->new(root => 'public'), name => 'static'),
  ]);

  # Served under the root path /app, as behind a proxy that strips it.
  my $client = PAGI::Test::Client->new(app => $app, root_path => '/app');
  my $links  = $client->get('/app/')->json;   # { css => '/app/static/css/app.css', prefix => '/app/static' }

Leading slashes in C<path> are dropped, and each segment is
percent-encoded; C<..> is not rewritten, so do not build C<path> from
untrusted input. From a handler inside another mount, use the absolute
name, C</static>. A route and a mount cannot share a name.

=head2 Matched-Route Metadata

Each compiled Router records the route it selected in the request scope,
under C<pagi.routing>. Middleware in that Router's own list can read it
after the request has been answered, for example to log which route
served each request:

  use v5.40;
  use Future::AsyncAwait;
  use PAGI::Tools qw(compose middleware mount response route router);
  use PAGI::Test::Client;

  # Logs the route that answered, after the response, for every request this
  # Router owns. It must sit in the Router's own middleware list: middleware
  # outside the compiled Router never sees the routing metadata.
  my @log;
  my $log_route = sub ($app) {
      return async sub ($scope, $receive, $send) {
          await $app->($scope, $receive, $send);
          my $match = $scope->{'pagi.routing'}{frames}[-1]{match};
          push @log, $match
              ? "$scope->{path} -> $match->{route} (" . ($match->{name} // 'unnamed') . ')'
              : "$scope->{path} -> no route";
      };
  };

  my $routing = router(
      routes => [
          route('/' => sub ($request) { response('Text', 'home') }, name => 'home'),
          mount('/notes', routes => [
              route('/{id}' => sub ($request) { response('Text', 'a note') }, name => 'show'),
          ], name => 'notes'),
      ],
      middleware => [middleware($log_route)],
  );

  my $app = compose(routes => [mount('/' => app => $routing)]);

  my $client = PAGI::Test::Client->new(app => $app);
  $client->get($_) for '/', '/notes/7', '/nowhere';
  # @log is now:
  #   / -> / (/home)
  #   /notes/7 -> /notes/{id} (/notes/show)
  #   /nowhere -> no route

C<match> holds the complete route pattern, its absolute name, its
namespace and its C<desc>; it is undefined when the Router answered 404
or 405 itself. Treat the data as read-only. The complete schema, with
mount records and nested frames, is
L<PAGI::Routing/MATCHED-ROUTE SCOPE CONVENTION>.

=head2 Lifespan Around Declarative Routing

Routing deliberately ignores lifespan scopes. Put lifecycle policy at the
deployed application root with L<PAGI::Compose>:

  use Future::AsyncAwait;
  use PAGI::Compose qw(compose);
  use PAGI::Routing qw(mount);

  my $app = compose(
      routes => [mount('/' => app => $routing)],
      lifespan => {
        startup => async sub {
          my ($state, $scope) = @_;
          $state->{db} = await connect_db();
        },
      },
  )->to_app;

The server owns C<$state> and makes it visible to later request scopes. Compose
fails startup clearly if callbacks are configured but the server does not
provide valid state. It consumes lifespan itself, so do not put a second
lifespan consumer around the same deployed root.

For a hand-built native PAGI application, L<PAGI::Lifespan> remains the
low-level wrapper form:

  use PAGI::Lifespan;

  my $app = PAGI::Lifespan->wrap(
      $native_app,
      startup => \&startup,
  );

At the raw event level, L<PAGI::Utils/handle_lifespan> can drive a lifespan
scope directly:

  use PAGI::Utils qw(handle_lifespan);

  return await handle_lifespan($scope, $receive, $send,
      startup => \&startup,
  ) if $scope->{type} eq 'lifespan';

=head2 Class-Based Exact Leaves and Ordinary Assemblers

Use classes where protocol behavior earns one, not to introduce another
Router grammar. This complete shape keeps topology declarative:

  package Example::Store;

  sub new {
      my ($class, @messages) = @_;
      return bless { messages => \@messages }, $class;
  }

  sub all {
      my ($self) = @_;
      return $self->{messages};
  }

  package MessageAPI;
  use parent 'PAGI::Endpoint::HTTP';
  use PAGI::Response qw(response);

  sub get {
      my ($self, $request) = @_;
      return response('JSON', $self->{store}->all);
  }

  package ChatEndpoint;
  use parent 'PAGI::Endpoint::WebSocket';
  use Future::AsyncAwait;

  async sub on_connect {
      my ($self, $websocket) = @_;
      await $websocket->accept;
      await $websocket->send_json({ ready => \1 });
  }

  package EventEndpoint;
  use parent 'PAGI::Endpoint::SSE';
  use Future::AsyncAwait;

  async sub on_connect {
      my ($self, $sse) = @_;
      await $sse->send_event(data => { ready => \1 });
  }

  package MyApp::API;
  use PAGI::Routing qw(endpoint route router sse websocket);

  sub new {
      my ($class, %args) = @_;
      return bless \%args, $class;
  }

  sub routing {
      my ($self) = @_;
      return router(
          desc => 'API routes',
          routes => [
              route('/messages' => endpoint('MessageAPI', store => $self->{store}),
                  name => 'messages'),
              websocket('/chat' => endpoint('ChatEndpoint', hub => $self->{hub}),
                  name => 'chat'),
              sse('/events' => endpoint('EventEndpoint', bus => $self->{bus}),
                  name => 'events'),
          ],
      );
  }

  package MyApp::Root;
  use PAGI::App::File;
  use PAGI::Compose qw(compose);
  use PAGI::Pages qw(welcome);
  use PAGI::Routing qw(mount route);
  use PAGI::Utils qw(app_path);

  sub new {
      my ($class, %args) = @_;
      return bless \%args, $class;
  }

  sub home { return welcome() }

  sub public_root { return app_path('public') }

  sub application {
      my ($self) = @_;
      my $api = MyApp::API->new(%{$self->{services}})->routing;
      return compose(routes => [
          route('/' => \&home, name => 'home'),
          mount('/api', app => $api, name => 'api'),
          mount('/static', app => PAGI::App::File->new(
              root => $self->public_root,
          )),
      ]);
  }

  package main;
  my $app = MyApp::Root->new(services => {
      store => Example::Store->new(
          { id => 1, text => 'hello' },
      ),
      hub   => bless({}, 'Example::Hub'),
      bus   => bless({}, 'Example::Bus'),
  })->application;

C<endpoint> loads each class and builds a fresh object for each request or
connection, so request and connection state may live on C<$self>. A class
that shares one object across every request says so with C<BUILD_APP>, and
then keeps only configuration and shared services on C<$self>
(L<PAGI::Endpoint>). HTTP C<allowed_methods> is consulted once when the
Route is built. A finite C<methods> declaration must be a restriction of
that snapshot. Only scalar C<< methods => '*' >> bypasses the capability
and lets the Endpoint own method dispatch. The Router otherwise owns
OPTIONS participation, PARTIAL, and the final C<Allow> union.

The asset-owning module calls C<app_path> directly. The helper returns a path
string; it does not construct a file application.

=head1 RESPONSE EXTENSIBILITY

Buffered response subclasses can introduce either a representation or a
semantic document type. Override C<render> for a new encoding. Override
C<new>, normalize the source value, and delegate to C<SUPER::new> when the
wire representation already exists but the application needs a stronger
document contract.

=head2 Company Collection JSON Response

Suppose every collection API at a company uses C<data>, C<meta>, and optional
C<links> members. This is semantic JSON policy, not a new JSON encoder. Build
and validate the envelope in the subclass constructor, then let
L<PAGI::Response::JSON> perform JSON encoding:

  package MyCompany::Response::Collection;
  use v5.40;

  use Carp qw(croak);
  use parent 'PAGI::Response::JSON';

  sub new ($class, $source, @response_options) {
      croak 'collection response requires a hashref'
          unless ref($source) eq 'HASH';

      my $items = $source->{items};
      croak 'collection response items must be an arrayref'
          unless ref($items) eq 'ARRAY';

      my $meta = $source->{meta} // {};
      croak 'collection response meta must be a hashref'
          unless ref($meta) eq 'HASH';

      my $document = {
          data => $items,
          meta => {
              %$meta,
              count => scalar @$items,
          },
      };

      if (exists $source->{links}) {
          croak 'collection response links must be a hashref'
              unless ref($source->{links}) eq 'HASH';
          $document->{links} = $source->{links};
      }

      return $class->SUPER::new(
          $document,
          @response_options,
      );
  }

  1;

C<new> owns the collection contract: invalid source values fail immediately,
and every constructed instance already contains the completed envelope.
Inherited C<render> has one job--encode that document as JSON. The inherited
C<to_app>, status, headers, cookies, content type, and buffered delivery
require no registration or reimplementation.

Build it by name with a leading C<+>, the way C<response> builds any
Response class from outside C<PAGI::Response::> -- the class needs no export
of its own:

  use v5.40;
  use PAGI::Response qw(response);
  use PAGI::Routing qw(route router);

  sub list_people ($request) {
      my $people = load_people();

      return response('+MyCompany::Response::Collection',
          {
              items => $people,
              meta  => {
                  total => scalar @$people,
                  page  => 1,
              },
              links => {
                  self => $request->path,
              },
          },
          headers => [
              'X-Collection-Version' => '1',
          ],
      );
  }

  my $routing = router(routes => [
      route('/people' => \&list_people, name => 'people'),
  ]);

The handler returns an ordinary Response app object. Route needs no knowledge
of the company subclass and invokes it through the inherited C<to_app>
contract.

Pass C<@response_options> to C<SUPER::new> unchanged. Converting them to a
hash in the subclass would silently discard duplicate options before the base
constructor could diagnose them. If a specialization needs its own constructor
options, give the semantic source a documented shape, as C<items>, C<meta>,
and C<links> do above, rather than intercepting the base response option list.

If the only requirement is a convenience function that wraps data in a hash,
a local factory returning C<response('JSON', ...)> may be enough. Use a subclass
when the document shape, validation, media type, or further extension is an
application-level type worth naming.

=head1 RESPONSE DELIVERY RECIPES

=head2 Relay a Request Body with Backpressure

Request-body input and response output can remain incremental without raw
PAGI. C<pipe_from> requests the next input chunk only after the previous output
write settles:

  use Future::AsyncAwait;
  use PAGI::Response qw(response);

  async sub echo_upload($request) {
      my $input = $request->body_stream(max_bytes => 100 * 1024 * 1024);

      return response('Stream',
          async sub ($writer) {
              await $writer->pipe_from($input);
              die 'upload was truncated' if $input->truncated;
          },
          content_type => 'application/octet-stream',
      );
  }

Always await C<write>, C<write_text>, or C<pipe_from>. One outstanding write is
allowed; overlap fails rather than building a queue. Optional Writer transport
watermarks help push-style sources, but awaiting each send is the portable
backpressure boundary.

PAGI send settlement means the server accepted an event into outbound
processing or finished discarding it after disconnect, not that the client
received it. Writer checks connection state after settlement and does not count
a discarded chunk. Stream may cancel producer-owned work, never the send
Future, and cleanup runs once. It has no WebSocket/SSE reconnect behavior.

=head2 Enforce a Per-Route Limit on an Unknown-Length Upload

A server-wide body limit protects the process. A route-specific policy belongs
to the application and must count bytes as it reads them; C<Content-Length> may
be absent or untrusted. This raw HTTP application limits one streaming upload:

  use Future::AsyncAwait;

  my $limit = 10 * 1024 * 1024;
  my $upload = async sub {
      my ($scope, $receive, $send) = @_;
      die 'upload app requires an http scope' unless $scope->{type} eq 'http';

      my $connection = $scope->{'pagi.connection'}
          or die 'upload app requires the Www 0.6 connection API';
      my $seen = 0;

      while (1) {
          my $event = await $receive->();
          return if $event->{type} eq 'http.disconnect';
          next unless $event->{type} eq 'http.request';

          $seen += length($event->{body} // '');
          if ($seen > $limit) {
              if ($connection->response_started) {
                  # Use only when this response format defines such an error.
                  await $send->({
                      type => 'http.response.body',
                      body => qq({"error":"upload too large"}\n),
                      more => 1,
                  });
                  $connection->abort("route upload limit exceeded after $seen bytes");
              } else {
                  await $send->({
                      type => 'http.response.start', status => 413,
                      headers => [['content-type', 'text/plain']],
                  });
                  await $send->({
                      type => 'http.response.body', body => 'upload too large', more => 0,
                  });
              }
              return;
          }

          last unless $event->{more};
      }

      # Process the accepted upload and send its ordinary response here.
  };

After response start, status and headers are committed. If the response format
has a client-visible error record, send it in-band and await that send before
calling public C<abort>; otherwise abort directly. The application owns this
abort and its diagnostic detail. This recipe is for raw C<http> scopes and does
not imply that SSE helpers expose HTTP request-body readers.

HEAD normally executes the whole producer behind the outer suppression
boundary. Put a cheap explicit HEAD Route before an expensive GET Route:

  route('/export' => \&head_export, methods => ['HEAD']);
  route('/export' => response('Stream', \&produce_export), methods => ['GET']);

=head2 Send One Selected File

C<response('File', ...)> receives a trusted path selected by the application:

  use PAGI::Response qw(response);

  route('/report' => response('File',
      '/srv/reports/monthly.pdf',
      filename => 'monthly.pdf',
  ));

Construction validates options but defers filesystem inspection until each
request's preflight. Validate explicitly during startup if a missing deployment
file must prevent startup. C<offset>/C<length> expose one logical 200
representation; only a valid client Range produces 206. Use
L<PAGI::App::File> instead when an untrusted URL path must be resolved beneath
a configured root.

=head2 Refusing WebSocket and SSE with applications

C<deny> and C<decline> accept the same six useful application forms. This
complete route tree exposes each form on separate C</ws/E<lt>formE<gt>> and
C</events/E<lt>formE<gt>> requests:

  use strict;
  use warnings;
  use Future;
  use Future::AsyncAwait;
  use PAGI::Compose qw(compose);
  use PAGI::Pages ();
  use PAGI::Response qw(response);
  use PAGI::Routing qw(sse websocket);
  use PAGI::Utils qw(as_app_object);

  {
      package MyApp::NoticeService;
      sub new {
          my ($class, %args) = @_;
          return bless { label => $args{label} }, $class;
      }
      sub notice_for {
          my ($self, $request) = @_;
          return Future->done($self->{label} . ':' . $request->path);
      }
  }

  {
      package MyApp::Refusal;
      sub new { return bless {}, $_[0] }
      sub to_app {
          my ($self) = @_;
          return async sub {
              my ($scope, $receive, $send) = @_;
              my $body = 'Custom application: ' . $scope->{path};
              await $send->({
                  type => 'http.response.start', status => 503,
                  headers => [['content-type', 'text/plain; charset=utf-8']],
              });
              await $send->({
                  type => 'http.response.body', body => $body, more => 0,
              });
              return;
          };
      }
  }

  my $notices = MyApp::NoticeService->new(label => 'notice-service');
  my $handler = sub {
      my ($request) = @_;
      return response('JSON',
          { error => 'Unavailable', path => $request->path },
          status => 503,
      );
  };
  my $async_handler = async sub {
      my ($request) = @_;
      my $notice = await $notices->notice_for($request);
      return response('JSON',
          { error => 'Unavailable', notice => $notice },
          status => 503,
      );
  };
  my $page = PAGI::Pages->service_unavailable(
      detail => 'Protocol refusal example',
  );
  my $object = MyApp::Refusal->new;
  my $native = as_app_object(async sub {
      my ($scope, $receive, $send) = @_;
      await $send->({
          type => 'http.response.start', status => 503,
          headers => [['content-type', 'text/plain; charset=utf-8']],
      });
      await $send->({
          type => 'http.response.body', body => 'Scheduled maintenance', more => 0,
      });
      return;
  });

  my $app = compose(routes => [
      # 1. A concrete Response: text on WebSocket, JSON on SSE.
      websocket('/ws/response' => async sub {
          my ($ws) = @_;
          await $ws->deny(response('Text', 'Scheduled maintenance', status => 503));
          return;
      }),
      sse('/events/response' => async sub {
          my ($sse) = @_;
          await $sse->decline(response('JSON',
              { error => 'Unavailable', form => 'response' }, status => 503,
          ));
          return;
      }),

      # 2. One synchronous Request handler, reusable at either boundary.
      websocket('/ws/handler' => async sub {
          my ($ws) = @_;
          await $ws->deny($handler);
          return;
      }),
      sse('/events/handler' => async sub {
          my ($sse) = @_;
          await $sse->decline($handler);
          return;
      }),

      # 3. One async Request handler awaiting application-owned work.
      websocket('/ws/async-handler' => async sub {
          my ($ws) = @_;
          await $ws->deny($async_handler);
          return;
      }),
      sse('/events/async-handler' => async sub {
          my ($sse) = @_;
          await $sse->decline($async_handler);
          return;
      }),

      # 4. Pages directly, or returned by a Request handler.
      websocket('/ws/pages' => async sub {
          my ($ws) = @_;
          await $ws->deny($page);
          return;
      }),
      sse('/events/pages' => async sub {
          my ($sse) = @_;
          await $sse->decline(sub { return $page });
          return;
      }),

      # 5. Any complete application object with to_app.
      websocket('/ws/object' => async sub {
          my ($ws) = @_;
          await $ws->deny($object);
          return;
      }),
      sse('/events/object' => async sub {
          my ($sse) = @_;
          await $sse->decline($object);
          return;
      }),

      # 6. A native triplet application selected explicitly.
      websocket('/ws/native' => async sub {
          my ($ws) = @_;
          await $ws->deny($native);
          return;
      }),
      sse('/events/native' => async sub {
          my ($sse) = @_;
          await $sse->decline($native);
          return;
      }),
  ]);

These routes are alternatives for different requests. Call one refusal helper,
await it, and return from the endpoint; do not try the forms sequentially on
one connection. A live attempt that finishes before response start can be
retried sequentially, but after response start or terminal completion another
refusal fails. Overlapping refusal and acceptance/start calls are unsupported.

A bare coderef in C<deny> or C<decline> position is a one-C<Request> handler.
If that handler returns a coderef, the returned value is a native triplet
application. C<as_app_object> selects the native triplet meaning when passing a
coderef directly. Await the Future returned by C<deny> or C<decline>.
Cancellation follows the invoked application's normal behavior; the helper
does not keep abandoned application work running. Built-in Responses protect
server-owned sends, and connection terminal notification continues to drive
helper cleanup.

Every delegated application receives the original protocol scope, remaining
receive stream, and original send channel. The scope remains C<websocket> or
C<sse>; the helper does not spoof C<http>. Pages therefore negotiates from the
real request headers without a mandatory C<response_for> step.

All forms require the current universal C<pagi.connection> capability, including
buffered Responses. The sending environment requires WebSocket refusal status
300 or greater. SSE may decline with ordinary HTTP status 200 or 204, including
204 to stop browser C<EventSource> reconnection. Application compatibility and
errors belong to the selected application.

F<examples/protocol-refusal/app.pl> is the maintained executable version, with
all twelve routes exercised through L<PAGI::Test::Client>.

=head1 HEADER RECIPES

=head2 Extract credentials and keep response policy in the application

For a backend that distinguishes malformed presentation from a missing or
unsupported scheme, raise only during extraction. Verification remains outside
that exception handler. The backend returns a result; a protected handler maps
its failure code to an explicit 400 or 401 response and Bearer challenge.

  my $token;
  my $parsed = eval {
      $token = $request->bearer_token(raise_on_error => 1);
      1;
  };
  return unauth_result(failure => {
      code => 'malformed_authorization',
      message => 'Supply one valid Bearer credential.',
  }) unless $parsed;
  return unauth_result() unless defined $token;
  # Verify $token here; a rejected token has a different failure.

C<< $request->basic_auth(raise_on_error =E<gt> 1) >> similarly returns
C<(username, password)> in list context. The default read instead returns
C<undef> for unusable Bearer input (or C<(undef, undef)> for Basic), so it
cannot distinguish a malformed credential from an absent one. Neither helper
verifies a credential or constructs a response. Without the C<eval>, a
malformed or duplicate field is a L<PAGI::Exception::HTTP> 400, C<The
Authorization header could not be parsed.>, which the Authentication middleware
answers before the application runs. See L<PAGI::Request/AUTH HELPERS>.

=head2 Read upload parameters and write download parameters

The request reader separates a normalized media type from raw parameter bytes.
An empty parameter hash is a valid field without parameters. Multipart upload
C<filename*> remains separate from C<filename> and is not decoded as a
download name.

  my $media = $request->headers->content_type;
  my $params = $request->headers->content_type_parameters;
  if (defined($media) && $media eq 'multipart/form-data' && $params) {
      my $boundary = $params->{boundary};
      # The multipart reader also uses this boundary while parsing the body.
  }

For a download, the formatter accepts a Perl character filename and emits a
byte header; a non-ASCII name becomes UTF-8 C<filename*>. No fallback name
is invented. A caller may supply an explicit ASCII C<filename> fallback and
an already-formatted C<filename*> when both are required.

  use utf8;
  use PAGI::Utils::Headers qw(content_disposition);
  $response->headers->set('Content-Disposition',
      content_disposition('attachment', filename => 'résumé.pdf'));

=head2 Compose Vary across middleware

Use the mutating Headers method when several components add cache dependencies.
It combines repeated Vary fields, deduplicates names without regard to case,
and retains unrelated headers. A wildcard remains a wildcard.

  $response->headers->add_vary('Accept-Encoding');
  $response->headers->add_vary('Origin');

The independent C<merge_vary(\@existing_values, @names)> function returns a
single value when no Headers container is available. Both paths reject a
malformed Vary field instead of silently dropping an existing dependency.

=head2 Add a header from middleware

A middleware adds response headers on a copy: the response's own header list
belongs to whoever built it, and an application may send the same list for
every response (see L<PAGI::Spec/Middleware>). C<wrap_response_headers> hands
you a L<PAGI::Headers> copy and sends a new event with your changes:

  use Future::AsyncAwait;
  use PAGI::Utils::Middleware qw(wrap_response_headers);

  sub with_build_header {
      my ($app) = @_;
      return async sub {
          my ($scope, $receive, $send) = @_;
          my $wrapped_send = wrap_response_headers($send, sub {
              my ($headers) = @_;
              $headers->set('X-Build', $ENV{BUILD_ID} // 'dev');   # replace
              $headers->add_vary('Accept-Language');                 # merge Vary
          });
          await $app->($scope, $receive, $wrapped_send);
      };
  }

Use C<add> for a header that repeats (C<Set-Cookie>) and C<set_default> to keep
a value the response already has. To hear back from layers further in, seed a
shared reference before calling inward -- L<PAGI::Middleware::Stash> above
you and L<PAGI::Stash> to read it, or the spec
Cookbook's "Reporting back to an outer layer" recipe.

=head2 Vary on a request header you branch on

When a handler answers differently by a request header, the response says so
in C<Vary>, or a shared cache serves one client's answer to another. For
Accept, L<PAGI::Middleware::ContentNegotiation> writes C<Vary: Accept> for
you. For any other header, the handler or a small route middleware writes
it.

htmx asks for a fragment by sending C<HX-Request: true>; the full page and
the fragment are both HTML:

  async sub notes {
      my ($request) = @_;
      my $notes = load_notes();
      my $html = $request->header('HX-Request') ? render_fragment($notes)
                                                : render_page($notes);
      return response('HTML', $html, headers => [Vary => 'HX-Request']);
  }

The same, for every answer of a route, as route middleware:

  use PAGI::Utils::Middleware qw(wrap_response_headers);

  sub vary_on_hx {
      my ($app) = @_;
      return async sub {
          my ($scope, $receive, $send) = @_;
          await $app->($scope, $receive, wrap_response_headers($send, sub {
              $_[0]->add_vary('HX-Request');
          }));
      };
  }

  route('/notes' => \&notes, middleware => [middleware(\&vary_on_hx)])

htmx's documentation also asks you to turn off
C<htmx.config.historyRestoreAsHxRequest> when the server answers fragments
by C<HX-Request>, so a history restore is not cached as a fragment.

A response thrown with C<die response('JSON', ...)> is sent by Compose's error
handler, outside your route's middleware, so it gets no C<Vary> from there.
Return an answer that depends on a request header; throw only answers that
do not.

=head2 Compare conditional entity tags

For an existing representation selected by a successful GET or HEAD, read all
C<If-None-Match> occurrences and compare them weakly with its current ETag.
Quoted commas are part of a tag, and malformed conditions return C<undef> by
default. A present condition takes precedence over C<If-Modified-Since>; do
not use a date fallback merely because this condition is unusable.

  use PAGI::Utils::Headers qw(etag_matches);
  my $condition = $request->headers->if_none_match;
  if (defined($condition) && etag_matches($condition, $current_etag, weak => 1)) {
      # Send the eligible representation's bodyless 304 with its validators.
  }

If the representation exists without a current ETag, inspect
C<< $condition->{any} >> for the wildcard case instead of calling
C<etag_matches>. The File and ConditionalGet integrations handle their own
eligibility, response metadata, and range policy.

=head1 AUTHENTICATION & SESSIONS

L<PAGI::Auth> constructs authentication results, reads the installed context
and formats individual C<WWW-Authenticate> values; the
L<PAGI::Middleware::Requires> middleware declares what a route requires.
Beyond it, applications choose ordinary Pages or Response applications for
refusals. Basic credentials and Bearer
tokens require TLS in real deployments.

=head2 Declaring what a route requires

C<middleware('Requires', scopes => SCOPES, %options)> is Starlette's
C<@requires> as middleware. What it wraps runs only for an authenticated user
holding every scope; anyone else gets a plain 403, a C<refuse> application of
your own, or a C<redirect>. On a route it guards that route, and on a mount
every route under the mount. WebSocket and SSE routes are denied or declined
before they start. It needs the Authentication middleware in front of it,
and C<route_table> shows it in each protected route's C<middleware>.

  use v5.40;
  use Future::AsyncAwait;
  use PAGI::Auth qw(auth auth_result unauth_result);
  use PAGI::Auth::SimpleUser;
  use PAGI::Compose qw(compose);
  use PAGI::Response qw(response);
  use PAGI::Routing qw(middleware mount route);

  my %grants = (reader => ['notes:read'], editor => ['notes:read', 'notes:write']);

  my $app = compose(
      middleware => [middleware('Authentication', backend => sub ($request) {
          my $token = $request->bearer_token;
          return unauth_result() unless defined $token && $grants{$token};
          return auth_result(
              user   => PAGI::Auth::SimpleUser->new(identity => $token),
              scopes => $grants{$token},
          );
      })],
      routes => [
          # Any authenticated user.
          route('/me' => sub ($request) {
              response('JSON', { me => auth($request)->user->identity });
          }, middleware => [middleware('Requires')]),
          # Every listed scope.
          route('/notes' => async sub ($request) {
              response('JSON', { saved => await $request->json }, status => 201);
          }, methods => ['POST'],
              middleware => [middleware('Requires', scopes => ['notes:read', 'notes:write'])]),
          # Hide the route's existence from those without access.
          route('/audit' => sub ($request) {
              response('JSON', { audit => [] });
          }, middleware => [middleware('Requires', scopes => ['admin'],
              refuse => response('Text', 'Not Found', status => 404))]),
          # Browsers: go to the route named 'login', with ?next= set.
          route('/home' => sub ($request) {
              response('JSON', { home => 1 });
          }, middleware => [middleware('Requires', redirect => ['login'])]),
          route('/login' => sub ($request) { response('JSON', { login => 1 }) }, name => 'login'),
          # A group: every route under the mount needs notes:write.
          mount('/drafts', middleware => [middleware('Requires', scopes => ['notes:write'])], routes => [
              route('/' => sub ($request) { response('JSON', { drafts => [] }) }),
          ]),
      ],
  );

C<redirect> takes a string, used exactly as written, or an arrayref of
C<path_for> arguments -- a route name, then its parameters, query and
fragment. The arrayref is resolved against the refused request, which is the
point of it: the target's parameters are filled from the current route's,
and the original path and query are added as C<next> so the login page can
send the user back. On C</orgs/acme/billing>:

  route('/orgs/{org}/settings' => \&settings,
      middleware => [middleware('Requires', redirect => ['org_login'])]),
      # /orgs/acme/login?next=%2Forgs%2Facme%2Fsettings
  route('/orgs/{org}/billing' => \&billing,
      middleware => [middleware('Requires', redirect => ['org_login', {}, { reason => 'billing' }])]),
      # /orgs/acme/login?next=%2Forgs%2Facme%2Fbilling&reason=billing
  route('/orgs/{org}/login' => \&org_login, name => 'org_login'),
  route('/account' => \&account,
      middleware => [middleware('Requires', redirect => 'https://login.example.com/?app=notes')]),
      # exactly that

A C<next> in your own query wins over the automatic one. Act on C<next> only
when it is a local path (F<examples/auth-cookie-login> shows the check).

Names resolve as from a handler where the middleware runs: on a mount, as
from inside it. A login page outside a named mount is C<../login> (or
C</login>); under an unnamed mount the enclosing Router's names are the
mount's too. An arrayref needs a Router's routing frame, so at Compose's
application level give a string location instead.

Like Starlette's, the refusal is one status: it does not tell an
unauthenticated user from a missing scope or send a C<WWW-Authenticate>
challenge. An API that wants RFC 6750 challenges builds those responses
itself, as below.

=head2 Basic Challenge

B<Request handler:> format the field value and return an ordinary Pages app.

  use PAGI::Auth qw(www_authenticate);
  use PAGI::Pages;

  sub protected($request) {
      return PAGI::Pages->status(401,
          as      => 'text',
          detail  => 'Authentication is required.',
          headers => ['WWW-Authenticate' => www_authenticate(
              'Basic', realm => 'Staff', charset => 'UTF-8',
          )],
      );
  }

=head2 Missing Bearer Token

B<Request handler:> a missing token is a plain Bearer challenge without an
C<error> parameter.

  use PAGI::Auth qw(www_authenticate);
  use PAGI::Pages;

  sub token_required($request) {
      return PAGI::Pages->status(401,
          detail  => 'An access token is required.',
          headers => ['WWW-Authenticate' =>
              www_authenticate('Bearer', realm => 'api')],
      );
  }

=head2 Invalid Bearer Token

B<Request handler:> validation happened elsewhere. The description is public
wire text; never put the token, a password, or an internal exception in it.
The error URI choice is explicitly absolute.

  return PAGI::Pages->status(401,
      headers => ['WWW-Authenticate' => www_authenticate('Bearer',
          realm             => 'api',
          error             => 'invalid_token',
          error_description => 'The access token is no longer valid.',
          error_uri         => 'https://example.test/errors/invalid-token',
      )],
  );

=head2 Insufficient Bearer Scope

B<Request handler:> an authenticated principal without permission receives
403. The application chooses the status and challenge parameters.

  use PAGI::Auth qw(www_authenticate);
  use PAGI::Pages;

  return PAGI::Pages->status(403,
      headers => ['WWW-Authenticate' => www_authenticate('Bearer',
          realm => 'api', error => 'insufficient_scope', scope => 'write',
      )],
      detail  => 'Write access is required.',
  );

Unknown Bearer extension error names remain open protocol values; Auth does
not guess whether they imply 401 or 403.

=head2 Multiple Authentication Challenges

B<Request handler:> pass repeated ordered fields. Values are never comma-joined.

  use PAGI::Auth qw(www_authenticate);
  use PAGI::Pages;

  return PAGI::Pages->status(401, headers => [
      'WWW-Authenticate' => www_authenticate('Basic', realm => 'Staff'),
      'WWW-Authenticate' => www_authenticate('Bearer', realm => 'api'),
      'WWW-Authenticate' => 'Negotiate ' . $encoded_token,
  ]);

=head2 Explicit Login Redirect Policy

B<Request handler:> C<< middleware('Requires', redirect => ['login']) >> on
the route covers the usual case (see L</Declaring what a route requires>).
Written by hand, the same policy is a redirect the handler chooses; keep the 401 challenge for
clients that need protocol authentication.

  use PAGI::Pages qw(redirect);

  sub browser_home($request) {
      return redirect('/login', status => 303) unless signed_in($request);
      return home_page($request);
  }

F<examples/auth-cookie-login> demonstrates the complete cookie and session
flow, including login and logout methods. It requires Perl 5.40 or newer.

=head2 Deliberate 404 Concealment

B<Request handler:> when disclosing resource existence is itself sensitive,
make concealment explicit policy -- C<< middleware('Requires', scopes => [...], refuse => response('Text', 'Not Found', status => 404)) >>
when the rule is "these scopes", or by hand when it is something else:

  use PAGI::Pages qw(not_found);

  sub confidential_report($request) {
      return not_found(detail => 'Report not found')
          unless may_discover_report($request);
      return report_response($request);
  }

=head2 WebSocket Authentication Denial

B<WebSocket endpoint:> pass the negotiated Pages application directly and await
C<deny>.

  use PAGI::Auth qw(www_authenticate);
  use PAGI::Pages;

  websocket('/chat' => async sub {
      my ($ws) = @_;
      unless (authorized($ws)) {
          my $failure = PAGI::Pages->status(401,
              as      => 'text',
              headers => ['WWW-Authenticate' =>
                  www_authenticate('Bearer', realm => 'chat')],
          );
          await $ws->deny($failure);
          return;
      }
      await $ws->accept;
      await $ws->run;
  });

The Pages application negotiates on the original WebSocket scope and emits
an ordinary C<http.response.*> response. C<response_for> remains available for
code that intentionally needs a concrete local Response, but refusal does not
require that materialization step.

=head2 SSE Authentication Decline

B<SSE endpoint:> decline before starting the stream.

  use PAGI::Auth qw(www_authenticate);
  use PAGI::Pages;

  sse('/events' => async sub {
      my ($sse) = @_;
      unless (authorized($sse)) {
          my $failure = PAGI::Pages->status(401,
              as      => 'text',
              headers => ['WWW-Authenticate' =>
                  www_authenticate('Bearer', realm => 'events')],
          );
          await $sse->decline($failure);
          return;
      }
      await $sse->start;
      await $sse->run;
  });

The negotiated 401 contains the structured Bearer C<WWW-Authenticate> field.
C<decline> invokes the Pages application on the original SSE scope. Connection
terminal notification drives helper cleanup independently of that invocation.

=head2 Invoke an Authentication Refusal from a Native Application

B<Native triplet app:> use the normal application invocation helper.

  use Future::AsyncAwait;
  use PAGI::Auth qw(www_authenticate);
  use PAGI::Pages;
  use PAGI::Utils qw(invoke_app);

  my $failure = PAGI::Pages->status(401,
      headers => ['WWW-Authenticate' =>
          www_authenticate('Bearer', realm => 'native')],
  );

  my $app = async sub {
      my ($scope, $receive, $send) = @_;
      return await invoke_app($failure, $scope, $receive, $send);
  };

=head2 Custom Pages Presentation for Authentication Refusals

B<Request handler setup:> reuse a configured Pages subclass. Rendering hooks
stay synchronous.

  use PAGI::Auth qw(www_authenticate);

  my $pages = MyApp::Pages->new;

  sub custom_token_required($request) {
      return $pages->status(401,
          headers => ['WWW-Authenticate' =>
              www_authenticate('Bearer', realm => 'api')],
          detail  => 'Sign in to continue.',
      );
  }

=head2 Session Management

Use L<PAGI::Middleware::Session> for session management. The middleware
populates C<< $scope->{'pagi.session'} >>; the L<PAGI::Session> helper wraps
that hashref with a convenient (and typo-catching) API.

  use strict;
  use warnings;
  use PAGI::Middleware::Builder;
  use PAGI::Middleware::Session qw(session_state);
  use PAGI::Session qw(session);
  use PAGI::Response qw(response);
  use PAGI::Routing qw(route router);

  my @routes;

  push @routes, route('/login' => sub {
      my ($request) = @_;

      # Set session data
      my $session = session($request);
      $session->set(user_id => 123);
      $session->set(username => 'alice');

      return response('Text', 'Logged in!');
  });

  push @routes, route('/profile' => sub {
      my ($request) = @_;

      # Read session data (the second arg is a default for optional keys)
      my $session = session($request);
      my $username = $session->get('username', 'Guest');

      return response('Text', "Hello, $username!");
  });

  push @routes, route('/logout' => sub {
      my ($request) = @_;

      # Clear session data
      session($request)->clear;

      return response('Text', 'Logged out!');
  });

  my $routing = router(routes => \@routes);

  # Wrap the Router with the session middleware
  my $app = builder {
      enable 'Session',
          state  => session_state('Cookie',
              cookie_name => 'session_id',
              expire      => 86400,   # the cookie lasts 1 day
          ),
          expire => 86400;            # and so does the session on the server
      $routing;
  };

=head2 Basic Authentication

  use strict;
  use warnings;
  use PAGI::Auth qw(auth auth_result unauth_result www_authenticate);
  use PAGI::Middleware::Builder;
  use PAGI::Response qw(response);
  use PAGI::Routing qw(route router);

  my $routing = router(routes => [
      route('/' => sub {
          my ($request) = @_;
          return response('Text', 'Protected content')
              if auth($request)->user->is_authenticated;
          my $response = response('Text', 'Credentials required', status => 401);
          $response->headers->set('WWW-Authenticate',
              www_authenticate('Basic', realm => 'Admin Area'));
          return $response;
      }),
  ]);

  my $app = builder {
      enable 'Authentication', backend => sub {
          my ($request) = @_;
          my ($username, $password);
          my $parsed = eval {
              ($username, $password) = $request->basic_auth(raise_on_error => 1);
              1;
          };
          return unauth_result(failure => {
              code => 'malformed_authorization',
              message => 'Supply one valid Basic credential.',
          }) unless $parsed;
          return unauth_result() unless defined($username) && defined($password);
          return unauth_result(failure => { message => 'Credentials were not accepted.' })
              unless $username eq 'admin' && $password eq 'secret';
          return auth_result(user => MyApp::User->new($username));
      };
      $routing;
  };

=head2 Bearer Token (JWT)

This example accepts HS256 tokens with a valid C<exp> and a nonempty C<sub>.
Configure C<JWT_SECRET> with the shared signing secret used by your issuer.
L<Crypt::JWT> recommends pinning C<accepted_alg>; C<verify_exp =E<gt> 1>
requires expiration, whereas its default only checks C<exp> when present.
These are this application's token rules, not policy imposed by PAGI::Auth.

  use strict;
  use warnings;
  use Crypt::JWT qw(decode_jwt);
  use PAGI::Auth qw(auth auth_result unauth_result www_authenticate);
  use PAGI::Auth::SimpleUser;
  use PAGI::Middleware::Builder;
  use PAGI::Response qw(response);
  use PAGI::Routing qw(route router);

  my $secret = $ENV{JWT_SECRET} // die 'Configure JWT_SECRET';

  my $routing = router(routes => [

  route('/api/me' => sub {
      my ($request) = @_;
      my $result = auth($request);
      return response('JSON', { user => $result->user->identity })
          if $result->user->is_authenticated;
      my $failure = $result->failure;
      my $malformed = $failure
          && ($failure->code // '') eq 'malformed_authorization';
      my @challenge = (realm => 'api');
      push @challenge, error => ($malformed ? 'invalid_request' : 'invalid_token')
          if $failure;
      my $response = response('JSON', { error => 'authentication_required' },
          status => $malformed ? 400 : 401);
      $response->headers->set('WWW-Authenticate',
          www_authenticate('Bearer', @challenge));
      return $response;
  }),
  ]);

  # Parsing, JWT verification, and safe rejection messages belong to the backend.
  my $app = builder {
      enable 'Authentication', backend => sub {
          my ($request) = @_;
          my $token;
          my $parsed = eval {
              $token = $request->bearer_token(raise_on_error => 1);
              1;
          };
          return unauth_result(failure => {
              code => 'malformed_authorization',
              message => 'Supply one valid Bearer credential.',
          }) unless $parsed;
          return unauth_result() unless defined $token;
          my $claims = eval {
              decode_jwt(
                  token        => $token,
                  key          => $secret,
                  accepted_alg => 'HS256',
                  verify_exp   => 1,
              );
          };
          return unauth_result(failure => { message => 'The token was not accepted.' })
              unless ref($claims) eq 'HASH'
                  && defined($claims->{sub}) && !ref($claims->{sub})
                  && length($claims->{sub});
          return auth_result(user => PAGI::Auth::SimpleUser->new(identity => $claims->{sub}));
      };
      $routing;
  };

=head1 REAL-TIME PATTERNS

=head2 Real-Time Fan-Out (Pub/Sub)

Fanning a message out to other WebSocket or SSE connections means one
scope's handler holding and calling C<send> for a different scope. PAGI's
sequential-sends contract only covers a single scope's own C<send>, so an
architecture that holds other scopes' sends cannot earn full fidelity to it
without its own multiplexing layer. That layer is the scope of the coming
B<PAGI-Channels> distribution (own-scope receive-multiplexed messaging,
with in-memory and Redis backends) rather than this Cookbook. Reach for it
when you need chat rooms, live dashboards, or any other fan-out pattern.

=head2 In-Loop WebSocket Rate Limiting

Rate limiting used to be middleware that wrapped C<receive> and injected a
synthetic C<websocket.disconnect> when a client went over budget. That shape
cannot be made faithful to the protocol: the server, not middleware, owns
disconnect delivery, so a middleware-fabricated disconnect is a ghost event
with a made-up reason, and closing from inside a wrapped C<receive> means
the close send races whatever the real handler does next, unawaited.

Enforce the limit where the real receive loop already lives instead -- a
token bucket checked against each incoming message, with a real, awaited
C<< $ws->close >> when the budget is blown:

  use Future::AsyncAwait;
  use PAGI::Routing qw(websocket);
  use PAGI::WebSocket;
  use Time::HiRes qw(time);

  my $chat_route = websocket('/chat' => async sub {
      my ($ws) = @_;
      await $ws->accept;

      my $limit  = 10;               # messages per second
      my $burst  = 2;                # allow short bursts up to limit * burst
      my $tokens = $limit * $burst;
      my $last   = time();

      await $ws->each_text(async sub {
          my ($text) = @_;

          my $now = time();
          $tokens += ($now - $last) * $limit;
          $tokens = $limit * $burst if $tokens > $limit * $burst;
          $last = $now;

          if ($tokens < 1) {
              return await $ws->close(code => 1008, reason => 'Rate limit exceeded');
          }
          $tokens -= 1;

          await $ws->send_text("you said: $text");
      });
  });

C<each_text> already serializes callback invocations against the receive
loop -- the next message is not read until this callback's Future settles --
so the token check and the reply share the same natural ordering the old
middleware wrapper had to fake with a synthetic event. Closing from inside
the loop is a real, awaited C<websocket.close> that the server delivers
exactly once, with the real code and reason -- no synthesized disconnect,
and nothing races it.

If several routes need the same limiter, factor the token-bucket state and
check into a small helper function and call it from each route's loop --
ordinary code reuse, not middleware pretending to own protocol lifecycle
events it can't actually generate.

=head2 SSE Dashboard

Server-Sent Events are ideal for real-time dashboards:

  use strict;
  use warnings;
  use Future::AsyncAwait;
  use PAGI::SSE;
  use PAGI::Routing qw(router sse);

  my $routing = router(routes => [

  sse('/events' => async sub {
      my ($sse) = @_;

      # Start the stream explicitly before anything else touches it --
      # don't lean on a method's own implicit auto-start.
      await $sse->start;

      # Enable keepalive to prevent proxy timeout
      await $sse->keepalive(15);

      # Subscribe to metrics updates (your pub/sub system). The callback
      # comes from an external, synchronous pub/sub API, so it can't await
      # here. try_send_event is the best-effort send for exactly this: it
      # never throws, and it needs no await.
      my $sub_id = subscribe_metrics(sub {
          my ($metrics) = @_;
          $sse->try_send_event(
              event => 'metrics',
              data  => $metrics,
          );
      });

      # Unsubscribe however the stream ends, at once if the client has
      # already gone.
      $sse->on_close(sub { unsubscribe_metrics($sub_id) });
      await $sse->run;
  }),
  ]);

  $routing->to_app;

JavaScript client:

  const events = new EventSource('/events');

  events.addEventListener('metrics', (e) => {
      const data = JSON.parse(e.data);
      document.getElementById('cpu').textContent = data.cpu.toFixed(1) + '%';
      document.getElementById('memory').textContent = data.memory.toFixed(1) + '%';
  });

See C<examples/sse-dashboard/> for a complete dashboard example.

=head2 Closing an SSE stream, and recording why

Returning from an SSE handler ends the stream when your code does. Call
C<< $sse->close >> to end it B<explicitly and immediately> -- from anywhere,
including deep in a helper -- which also wakes a parked C<< $sse->run >>. An
optional C<reason> is recorded server-side (logs, metrics, tracing) and passed
to C<on_close>; it is B<never> sent to the client, since SSE has no close frame:

  sse('/quotes' => async sub {
      my ($sse) = @_;

      my $sub = subscribe_feed($sse->query_param('job'));

      # One cleanup hook, however the stream ends (client gone, our close, ...).
      $sse->on_close(async sub {
          my ($sse, $reason) = @_;
          await $sub->cancel;                  # async cleanup, awaited
      });

      while (defined(my $tick = await $sub->next)) {
          await $sse->send_event(event => 'quote', data => $tick);
          next unless $tick->{final};

          # Tell the CLIENT with an in-band event it listens for, then close with
          # a SERVER-SIDE reason for your logs.
          await $sse->send_event(event => 'done', data => { ok => 1 });
          return await $sse->close(reason => 'feed_complete');
      }
      await $sse->close(reason => 'feed_gone');
  });

The two "why" channels are deliberately separate: a normal C<sse.send> event is
the only thing the browser can observe, while C<reason> is server-side metadata.
Because the close is an event on C<$send>, middleware can observe it -- wrap
C<$send> to fan close reasons out to metrics or tracing without touching the
handler:

  sub observe_sse_closes {
      my ($app) = @_;
      return async sub {
          my ($scope, $receive, $send) = @_;
          my $wrapped = async sub {
              my ($event) = @_;
              metric_inc('sse_close', $event->{reason} // 'unspecified')
                  if ($event->{type} // '') eq 'sse.close';
              return await $send->($event);    # forward unchanged
          };
          await $app->($scope, $receive, $wrapped);
      };
  }

Apply it at the mount or Router level (event middleware). See L<PAGI::SSE/close>
for the method, L<PAGI::Spec::Www/"Close SSE - C<send> event"> for the protocol
event, and L<PAGI::Cookbook/"Ending a stream: return vs C<sse.close>"> for the
native form.

=head2 Declining an SSE request (404 / 401 / 204 stop-reconnect)

An SSE request is an ordinary C<GET> with C<Accept: text/event-stream>. Before
you start the stream you can B<decline> it and return a normal HTTP response
instead -- no event stream. Use C<< $sse->decline >>, which is how most
application code should write this:

  use PAGI::Auth qw(www_authenticate);
  use PAGI::Pages;

  sse('/feed' => async sub {
      my ($sse) = @_;

      # Application policy has already decided whether an identity exists.
      unless (has_authenticated_identity($sse)) {
          my $failure = PAGI::Pages->status(401,
              as      => 'text',
              headers => ['WWW-Authenticate' =>
                  www_authenticate('Bearer', realm => 'events')],
          );
          await $sse->decline($failure);
          return;
      }

      await $sse->start;
      # ... stream ...
  });

This is response construction after an application-owned identity decision. It
does not parse a query parameter, credential, or token, and PAGI::Auth does not
provide a credential parser or identity provider. C<decline> invokes the
Pages application and retains SSE lifecycle ownership.

Three common reasons to decline:

=over 4

=item * B<404> -- no such SSE endpoint. A L<PAGI::Routing::Router> already does this
for an unmatched SSE route; you rarely write it by hand.

=item * B<401> / B<403> -- authentication or authorization failed; don't open a
stream.

=item * B<204> -- the spec's mechanism to B<stop> an C<EventSource> from
reconnecting. A browser's C<EventSource> reconnects on any non-success or
network drop; answering the request with C<204 No Content> tells it to stop for
good.

=back

  # Tell EventSource to stop reconnecting: a bare 204.
  await $sse->decline(PAGI::Response::response('Empty', status => 204));
  return;

A normally completed decline is a clean end, not an abnormal disconnect. The
server does not deliver C<sse.disconnect> on its own because no event stream
started. If raw application code calls its C<$receive> callback after the
refusal, however, that receive resolves with a
reasonless C<sse.disconnect> reporting the clean terminal scope. Return right
after declining, as above; there is no further application work to perform.

First-send-wins picks the mode: once you have sent C<sse.start> a decline
raises, and once you have sent C<http.response.start> a stream event
(C<sse.send>, C<sse.start>, ...) raises. Decide before you start.

See L<PAGI::SSE/decline> for the method and
L<PAGI::Spec::Www/"Decline SSE - C<send> event"> for the protocol events and
the full state machine.

=head3 Application boundary

C<decline> converts the selected value through its public C<to_app> contract
and invokes that application with the original SSE scope, remaining receive
stream, and original send channel. The application emits ordinary
C<http.response.start> and C<http.response.body> events. Every refusal target,
including buffered Responses, requires the current public universal connection
API so caller cancellation, transport loss, and retained cleanup have one
authoritative terminal source.

=head1 BACKGROUND WORK

Web requests should respond quickly. Long-running work should be done in the background.

=head2 Background Work the Client Does Not Wait For

Work a handler starts and does not await -- an email, an analytics call --
still needs an owner: something that keeps it alive, hears when it fails,
and lets shutdown wait for it. L<PAGI::FutureOwner> is that owner:

  use v5.40;
  use Future::AsyncAwait;
  use Future::IO;    # pagi-server binds the implementation
  use PAGI::FutureOwner;
  use PAGI::Tools qw(compose response route);

  async sub send_welcome_email ($email) {
      await Future::IO->sleep(2);    # in reality, an async HTTP call
      warn "Email sent to $email\n";
  }

  sub signup ($request) {
      # Started now; the client does not wait for it.
      $request->state->get('background')->adopt(send_welcome_email('user@example.com'));
      return response('JSON', { status => 'created' }, status => 201);
  }

  my $app = compose(
      routes   => [route('/signup' => \&signup, methods => ['POST'])],
      lifespan => {
          # The owner lives as long as the application, like any other
          # long-lived thing a handler reaches for.
          startup => sub ($state, $scope) {
              $state->{background} = PAGI::FutureOwner->new(
                  on_failure => sub ($error) { warn "Background task failed: $error" },
              );
          },
          # Work still running finishes before the process exits.
          shutdown => async sub ($state, $scope) { await $state->{background}->settled },
      },
  );

Do not drop such a Future, and do not C<< ->retain >> it: a retained Future
belongs to nobody, so nothing can wait for it and its failure is lost.

B<Middleware authors:> If your middleware inherits from L<IO::Async::Notifier>,
use C<< $self->adopt_future($f) >> instead. It properly tracks futures and
propagates unhandled errors to the notifier's C<invoke_error> method.

=head2 Work After the Response

Some work should start only once the client has its answer: a welcome email
for a signup that succeeded, say. Register it on the connection's
C<on_complete> (L<PAGI::HTTPConnection/connection>), and hand what it starts to the
same lifespan-owned L<PAGI::FutureOwner>:

  use v5.40;
  use Future::AsyncAwait;
  use Future::IO;    # pagi-server binds the implementation
  use PAGI::FutureOwner;
  use PAGI::Tools qw(compose response route);

  async sub send_welcome_email ($email) {
      await Future::IO->sleep(2);    # in reality, an async HTTP call
      warn "Email sent to $email\n";
  }

  async sub signup ($request) {
      my $email = (await $request->json)->{email};
      # ... create the account: everything that can fail comes first ...
      my $background = $request->state->get('background');
      $request->connection->on_complete(sub {
          $background->adopt(send_welcome_email($email));
      });
      return response('JSON', { status => 'created' }, status => 201);
  }

  my $app = compose(
      routes   => [route('/signup' => \&signup, methods => ['POST'])],
      lifespan => {
          startup => sub ($state, $scope) {
              $state->{background} = PAGI::FutureOwner->new(
                  on_failure => sub ($error) { warn "Background task failed: $error" },
              );
          },
          # Emails still being sent finish before the process exits.
          shutdown => async sub ($state, $scope) { await $state->{background}->settled },
      },
  );

C<on_complete> runs once the response has been delivered, whatever its
status; a client that disconnects first does not trigger it. A 500 is
delivered too, so a handler that registers C<on_complete> and then dies still
fires it: register it just before C<return>, after everything that can fail.
C<on_end> runs however the connection ends; use it for cleanup that must
always run, not for work that assumes success.

Start the work in the handler instead (L</Background Work the Client Does Not
Wait For>) when it does not depend on the client getting its answer.

=head2 CPU-Bound Work in Subprocess

B<Note:> This pattern uses L<IO::Async::Function>, which is specific to
L<PAGI::Server>'s L<IO::Async> backend. It won't work with other PAGI servers.

For blocking or CPU-intensive work, use L<IO::Async::Function> to run in a child process:

  use strict;
  use warnings;
  use Future::AsyncAwait;
  use IO::Async::Function;
  use IO::Async::Loop;
  use PAGI::Compose qw(compose);
  use PAGI::FutureOwner;
  use PAGI::Response qw(response);
  use PAGI::Routing qw(route);

  my $loop = IO::Async::Loop->new;

  # Owns work started for a client that does not wait for it.
  my $background = PAGI::FutureOwner->new(
      on_failure => sub { warn "PDF failed: $_[0]" },
  );

  # Worker runs code in subprocess
  my $pdf_worker = IO::Async::Function->new(
      code => sub {
          my ($data) = @_;
          # This blocking code runs in a CHILD PROCESS
          # It doesn't block the main event loop
          sleep 5;  # Simulate heavy work
          return "PDF generated for $data";
      },
  );
  $loop->add($pdf_worker);

  my $app = compose(
      routes => [
          # Wait for the result: this request waits; others do not.
          route('/generate-pdf' => async sub {
              my ($request) = @_;
              my $result = await $pdf_worker->call(args => ['report']);
              return response('JSON', { result => $result });
          }, methods => ['POST']),

          # Start the work and answer at once; $background owns the work.
          route('/generate-pdf/later' => sub {
              my ($request) = @_;
              my $f = $pdf_worker->call(args => ['report']);
              $f->on_done(sub { warn "PDF ready: $_[0]\n" });
              $background->adopt($f);
              return response('JSON', { status => 'processing' }, status => 202);
          }, methods => ['POST']),
      ],
      lifespan => {
          # Work still running finishes before the process exits.
          shutdown => async sub { await $background->settled },
      },
  )->to_app;

B<Warning:> IO::Async::Function forks child processes. If running with C<--workers N>, each server worker forks its own Function workers. With 4 server workers and 2 Function workers each, you have 12 processes. For high-volume CPU work, consider a dedicated job queue instead.

C<examples/background-tasks/> shows the asynchronous patterns;
C<examples/process-streaming/> drives a subprocess through L<Future::IO>,
without naming an event loop.

=head2 Watching or changing the request body

Whoever reads a request body hands the application a receive that delivers
a body (L<PAGI::Middleware/Reading the request body>). To watch or change
it as it streams, a middleware wraps C<$receive>, and the application reads
through the wrapper: the middleware sees
each C<http.request> event as it goes past, and may hand on a changed one.
These two are plain C<app-E<gt>app> functions, which C<middleware> takes as
factories. The first only watches, as the body streams. The second hands
the application a gzip-encoded body decompressed: the first time the
application asks for the body, it reads the whole compressed body inside
that receive and returns the plain one, as msgpack-asgi (which Starlette's
documentation points to) converts a body. That reads ahead, so it bounds
both sizes -- a small gzip body can decompress to gigabytes:

  use v5.40;
  use Future::AsyncAwait;
  use IO::Uncompress::Gunzip ();
  use PAGI::Exception::HTTP;
  use PAGI::HTTPConnection;
  use PAGI::Tools qw(compose middleware response route);

  my $MAX_BODY = 10 * 1024 * 1024;    # compressed or not

  # Watching: the body's size, counted as the application reads it.
  sub logged_body_size ($app) {
      return async sub ($scope, $receive, $send) {
          return await $app->($scope, $receive, $send) unless $scope->{type} eq 'http';
          my $size = 0;
          my $counting = async sub {
              my $event = await $receive->();
              if ($event->{type} eq 'http.request') {
                  $size += length($event->{body} // '');
                  warn "request body: $size bytes\n" unless $event->{more};
              }
              return $event;
          };
          await $app->($scope, $counting, $send);
      };
  }

  # Changing: a Content-Encoding: gzip body reaches the application as the
  # plain body, in one event, with the encoding and length headers gone.
  sub gunzip_body ($app) {
      return async sub ($scope, $receive, $send) {
          return await $app->($scope, $receive, $send) unless $scope->{type} eq 'http';
          my $encoding = PAGI::HTTPConnection->new($scope)->header('content-encoding');
          return await $app->($scope, $receive, $send)
              unless defined($encoding) && lc($encoding) eq 'gzip';
          my $plain_scope = { %$scope, headers => [
              grep { lc($_->[0]) ne 'content-encoding' && lc($_->[0]) ne 'content-length' }
                  @{ $scope->{headers} } ] };
          my $decoded = 0;
          my $decoding = async sub {
              return await $receive->() if $decoded;
              my $packed = '';
              while (1) {
                  my $event = await $receive->();
                  if ($event->{type} ne 'http.request') {
                      return $event unless length $packed;    # no body: hand it on
                      die "Request body incomplete: client disconnected mid-body\n";
                  }
                  $packed .= $event->{body} // '';
                  PAGI::Exception::HTTP->throw(413, 'Request body too large.')
                      if length $packed > $MAX_BODY;
                  last unless $event->{more};
              }
              $decoded = 1;
              my $gunzip = IO::Uncompress::Gunzip->new(\$packed, Transparent => 0)
                  or PAGI::Exception::HTTP->throw(400, 'The gzip request body could not be decoded.');
              my $plain = '';
              while (1) {
                  my $read = $gunzip->read(my $block, 64 * 1024);
                  PAGI::Exception::HTTP->throw(400, 'The gzip request body could not be decoded.')
                      if $read < 0;
                  last if $read == 0;
                  $plain .= $block;
                  PAGI::Exception::HTTP->throw(413, 'Request body too large.')
                      if length $plain > $MAX_BODY;
              }
              return { type => 'http.request', body => $plain, more => 0 };
          };
          await $app->($plain_scope, $decoding, $send);
      };
  }

  my $app = compose(
      routes => [route('/echo' => async sub ($request) {
          response('Text', ($request->header('content-encoding') // 'identity') . ': ' . await $request->body);
      }, methods => ['POST'])],
      # gunzip_body is outermost, so logged_body_size counts the plain body.
      middleware => [middleware(\&gunzip_body), middleware(\&logged_body_size)],
  );

Both run only as far as the application reads: a route that never reads the
body never decompresses or counts it. To change a body as it streams,
change each event in the receive and hand it on, as C<logged_body_size>
hands each one on. A middleware that refuses on the body
throws from the read that decides, as C<gunzip_body> does for a body that is
not gzip; examples/signed-requests refuses a forged signature on the last
chunk that way. examples/modify-form-post reads a whole form first instead,
and hands the application the rewritten body.

=head2 CSRF on a streamed upload

A route that streams a plain HTML form's upload with C<multipart_stream>
needs no CSRF code of its own. L<PAGI::Middleware::CSRF> reads a multipart
form only as far as its C<csrf_token> field, checks it, and hands the route
the whole body, so the upload after the token streams to the route as it
arrives. The form puts its token field before the file -- browsers send
fields in document order -- and a file part before the token is refused:

  use v5.40;
  use Future::AsyncAwait;
  use File::Temp qw(tempdir);
  use PAGI::CSRF qw(csrf);
  use PAGI::Tools qw(compose middleware response route);

  my $uploads = tempdir(CLEANUP => 1);
  my $files   = 0;

  # The page's upload form puts its csrf_token field before the file.
  async sub notes ($request) {
      my $token = csrf($request)->token;
      return response('HTML', <<"HTML");
  <form method="post" action="/upload" enctype="multipart/form-data">
  <input type="hidden" name="csrf_token" value="$token">
  <input type="file" name="file"> <button>Upload</button>
  </form>
  HTML
  }

  # Only a request whose token the middleware matched gets here: an
  # X-CSRF-Token header, or the form's field, read before the file.
  async sub upload ($request) {
      my $stream = $request->multipart_stream;
      my $bytes  = 0;
      while (defined(my $part = await $stream->next)) {
          next unless $part->is_file;
          $bytes += await $part->stream_to_file("$uploads/upload-" . ++$files);
      }
      return response('Text', "Stored $bytes bytes");
  }

  my $app = compose(
      routes => [
          route('/notes' => \&notes, methods => ['GET']),
          route('/upload' => \&upload, methods => ['POST']),
      ],
      middleware => [middleware('CSRF', form_field => 'csrf_token')],
  );

A script that sends the C<X-CSRF-Token> header uploads in any part order:
the middleware then reads nothing. A form's token must come within
C<max_form_size> bytes (1 MiB by default), however large the file after it.

=head2 A huge upload in a legacy encoding

C<body_stream(decode =E<gt> ...)> decodes as the body arrives. For the
heaviest legacy-encoded uploads, spool the bytes to disk first and read the
file through PerlIO's own decoder, line by line:

  my $path = "$dir/import.csv";
  await $request->body_stream->stream_to_file($path);
  open my $fh, '<:encoding(cp1252)', $path or die "$path: $!";
  while (my $line = <$fh>) { ... }

C<:encoding> also reads the encodings a stream cannot (ISO-2022-JP,
UTF-7), because it reads by lines.

=head2 Accept JSON and a form on one route

A route that takes the same data from an API client (JSON) and from a
browser (a form) reads the body by its Content-Type, and refuses anything
else as the client's 415:

  use PAGI::Exception::RequestBody;

  async sub create {
      my ($request) = @_;
      my $data = $request->is_json ? await $request->json
               : $request->is_form ? (await $request->form_params)->as_hashref
               : PAGI::Exception::RequestBody->throw(
                     status_code => 415,
                     reason      => 'unsupported_media_type',
                     message     => 'The request body must be JSON or a form.',
                 );
      my $text = ref $data eq 'HASH' ? $data->{text} : undef;
      return response('Text', 'A note needs text.', status => 400)
          unless defined $text && !ref $text && length $text;
      ...
  }

=over 4

=item * C<is_json> is true for C<application/json> and every C<+json> type
(C<application/vnd.api+json>, ...); C<is_form> for URL-encoded and multipart
forms.

=item * C<as_hashref> keeps the last value of a repeated form field; use
C<as_hashref_mixed> for an array of them.

=item * The thrown L<PAGI::Exception::RequestBody> is answered like every other
body error: a plain-text 415 from Compose, or your ErrorHandler's rendering.

=item * The data is still only as trustworthy as its checks: a JSON body need
not be an object, and a field need not be a string. Check the shape before
using it.

=item * C<< $request->body >> still holds the raw bytes of a JSON or
URL-encoded body after it has been parsed, for a signature check.

=back

C<examples/content-negotiation> uses this in its C<create>.

=head2 Bad request bodies

A body the client got wrong -- not JSON, not valid in its charset under
C<strict>, text in a charset Perl does not know, a multipart body that cannot
be parsed, a part over a limit -- is the client's error, not the
application's. L<PAGI::Request>'s buffered helpers throw a
L<PAGI::Exception::RequestBody> (status 400, 413 for a limit, or 415 for an
unknown charset), and every
Compose application answers with that status. Most handlers need no code for
it; one that wants its own response catches the error:

  use v5.40;
  use Future::AsyncAwait;
  use PAGI::Compose qw(compose);
  use PAGI::Response qw(response);
  use PAGI::Routing qw(middleware route);

  # No code: a body that is not JSON becomes a plain-text 400 carrying
  # "The request body is not valid JSON."
  async sub create_note ($request) {
      my $data = await $request->json;
      return response('JSON', { created => $data }, status => 201);
  }

  # Its own response: catch the RequestBody exception, and rethrow anything else.
  async sub create_note_kindly ($request) {
      my $data;
      unless (eval { $data = await $request->json; 1 }) {
          my $error = $@;
          die $error unless ref $error && $error->isa('PAGI::Exception::RequestBody');
          return response('JSON',
              { error => 'Send a JSON object, like {"text": "..."}.' },
              status => 400,
          );
      }
      return response('JSON', { created => $data }, status => 201);
  }

  my $app = compose(routes => [
      route('/notes'        => \&create_note,        methods => ['POST']),
      route('/notes/kindly' => \&create_note_kindly, methods => ['POST']),
  ]);

To give every route the same shape instead, give ErrorHandler a C<catch>
entry for L<PAGI::Exception::RequestBody>. The entry gets the Request and the
error: its C<message> is the exception's client-safe sentence, and its
C<cause> holds the underlying error for logs:

  my $uniform = compose(
      middleware => [middleware('ErrorHandler', catch => {
          'PAGI::Exception::RequestBody' => sub ($request, $error) {
              return response('JSON', { error => $error->message });
          },
      })],
      routes => [route('/notes' => \&create_note, methods => ['POST'])],
  );

The limits behind the 413 are C<form_params>' C<max_file_size>,
C<max_field_size>, C<max_files> and C<max_fields>; see L<PAGI::Request>.

=head1 COMMAND-LINE RECIPES

=head2 Environment Modes

pagi-server auto-detects development vs production mode based on whether
you're running in an interactive terminal:

  # Development mode (TTY detected) - Lint middleware + access logging
  pagi-server app.pl

  # Production mode (no TTY, e.g., systemd/docker) - no middleware, no logging
  # This happens automatically when running as a daemon

  # Explicit mode selection
  pagi-server -E production app.pl
  pagi-server -E development app.pl
  pagi-server -E none app.pl  # Disable all auto-middleware

  # Via environment variable
  PAGI_ENV=production pagi-server app.pl

  # Enable logging in production (writes to file)
  pagi-server -E production --access-log /var/log/pagi.log app.pl

  # Disable auto-middleware even in development
  pagi-server --no-default-middleware app.pl

=head2 Inline Apps with -e

Like C<perl -e>, you can run inline PAGI apps. This is useful for quick
tests or one-liners:

  # Quick static file server
  pagi-server -MPAGI::App::Directory \
      -e 'PAGI::App::Directory->new(root => "/var/www")->to_app'

  # Serve a single file
  pagi-server -MPAGI::App::File \
      -e 'PAGI::App::File->new(root => ".")->to_app'

  # Quick redirect
  pagi-server -MPAGI::Response \
      -e 'PAGI::Response::response('Redirect', "https://example.com")->to_app'

=head2 Loading Modules with -M

The C<-M> flag loads modules before C<-e> code runs, like C<perl -M>:

  # Load multiple modules
  pagi-server -MPAGI::App::File -MPAGI::Middleware::Builder \
      -e 'use PAGI::Middleware::Builder; builder { enable "GZip"; PAGI::App::File->new(root => ".") }'

  # Cuddled form (no space after -M)
  pagi-server -MPAGI::App::File -e 'PAGI::App::File->new(root => ".")->to_app'

=head2 Common pagi-server Patterns

  # Development with verbose logging
  pagi-server --log-level debug app.pl

  # Production multi-worker deployment
  pagi-server -E production --host 0.0.0.0 -p 80 --workers 4 app.pl

  # With custom library paths
  pagi-server -I ./lib -I ./local/lib app.pl

  # HTTPS with TLS
  pagi-server --ssl-cert cert.pem --ssl-key key.pem -p 443 app.pl

  # Daemonized with PID file
  pagi-server -D --pid /var/run/pagi.pid app.pl

  # Maximum performance (no access logging)
  pagi-server --no-access-log --workers 8 -E production app.pl

  # Using EV event loop for better performance
  pagi-server --loop EV app.pl

=head2 TLS/HTTPS

L<PAGI::Server> supports TLS natively:

  pagi-server app.pl --port 443 \
      --ssl-cert /path/to/cert.pem \
      --ssl-key /path/to/key.pem

For development, generate a self-signed certificate:

  openssl req -x509 -newkey rsa:4096 -keyout key.pem -out cert.pem \
      -days 365 -nodes -subj '/CN=localhost'

  pagi-server app.pl --port 3443 \
      --ssl-cert cert.pem --ssl-key key.pem

Then access via C<https://localhost:3443> (browser will warn about self-signed cert).

See C<examples/11-tls-https/> for more TLS configuration options.

=head2 Serving Large Files with X-Sendfile

For production deployments behind a reverse proxy (Nginx, Apache), use
L<PAGI::Middleware::XSendfile> to delegate file serving to the proxy.
This frees your application worker immediately while the proxy handles
the file transfer using optimized kernel sendfile.

=head3 Why X-Sendfile?

Direct file serving from your application ties up a worker process for
the entire transfer. With slow clients or large files, this limits your
concurrency. X-Sendfile lets your app send a header telling the proxy
to serve the file:

  # Your app sends:
  X-Accel-Redirect: /protected/files/large.bin
  Content-Type: application/octet-stream

  # Nginx intercepts and serves the file directly

Benefits:

=over 4

=item * Worker freed immediately after sending headers

=item * Proxy uses kernel sendfile (zero-copy, efficient)

=item * Proxy handles Range requests, caching, connection management

=item * Slow clients don't block your app

=back

=head3 Nginx Configuration

Configure an internal location for protected files:

  # nginx.conf
  location /protected/ {
      internal;                       # Only accessible via X-Accel-Redirect
      alias /var/www/files/;          # Actual file location
  }

=head3 Application Setup

  use strict;
  use warnings;
  use Future::AsyncAwait;
  use PAGI::Middleware::Builder;
  use PAGI::App::File;

  my $app = builder {
      enable 'XSendfile',
          type    => 'X-Accel-Redirect',
          mapping => { '/var/www/files/' => '/protected/' };

      PAGI::App::File->new(
          root          => '/var/www/files',
          handle_ranges => 0,  # Let nginx handle Range requests
      );
  };

B<Note:> Setting C<handle_ranges =E<gt> 0> is important. It tells your app
to ignore Range headers and always send full files. The reverse proxy will
handle Range requests more efficiently using its native sendfile.

=head3 Custom Download Handler

For more control (authentication, logging, custom headers):

  use strict;
  use warnings;
  use Future;
  use Future::AsyncAwait;
  use PAGI::Middleware::Builder;
  use PAGI::Pages;
  use PAGI::Request;
  use PAGI::Routing qw(route router);
  use PAGI::Utils qw(as_app_object invoke_app path_from_root);

  sub authenticate;
  sub can_download;

  my $router = router(routes => [
  route('/download/{filename}' => as_app_object(async sub {
      my ($scope, $receive, $send) = @_;
      my $req = PAGI::Request->new($scope, $receive);

      my $filename = $req->path_param('filename');
      my $filepath = path_from_root('/var/www/files', $filename);
      unless (defined $filepath) {
          my $response = PAGI::Pages->forbidden;
          return await Future->wrap(invoke_app($response, $scope, $receive, $send));
      }

      # Authentication and authorization are separate from path validation.
      my $user = authenticate($scope);
      unless ($user && can_download($user, $filepath)) {
          my $response = PAGI::Pages->forbidden;
          return await Future->wrap(invoke_app($response, $scope, $receive, $send));
      }

      unless (-f $filepath && -r $filepath) {
          my $response = PAGI::Pages->not_found;
          return await Future->wrap(invoke_app($response, $scope, $receive, $send));
      }

      # Validate request-derived header data independently.
      my ($download_name) = $filename =~ /\A([A-Za-z0-9][A-Za-z0-9._-]*)\z/;
      unless (defined $download_name) {
          my $response = PAGI::Pages->forbidden;
          return await Future->wrap(invoke_app($response, $scope, $receive, $send));
      }

      # Send file response directly via native protocol events (XSendfile middleware will intercept)
      await Future->wrap($send->({
          type    => 'http.response.start',
          status  => 200,
          headers => [
              ['content-type', 'application/octet-stream'],
              ['content-disposition', qq{attachment; filename="$download_name"}],
          ],
      }));
      return await Future->wrap($send->({
          type => 'http.response.body', file => $filepath, more => 0,
      }));
  })),
  ]);

  my $app = builder {
      enable 'XSendfile',
          type    => 'X-Accel-Redirect',
          mapping => { '/var/www/files/' => '/protected/' };
      $router;
  };

Replace C<authenticate> and C<can_download> with application policy. The
request filename is used only after independent path and header validation;
the validated lexical C<$filepath> is the C<file> event intercepted by
XSendfile. Hash mappings are component-aware, use the most-specific source
prefix, and leave an unmatched original C<file> event unchanged rather than
publishing a raw proxy path.

=head3 Apache Configuration (mod_xsendfile)

Enable mod_xsendfile and whitelist your file directory:

  # Apache config
  XSendFile On
  XSendFilePath /var/www/files

  # Application
  my $app = builder {
      enable 'XSendfile', type => 'X-Sendfile';
      $my_app;
  };

=head3 Filehandle Support

The middleware also works with filehandle responses, but only if the
filehandle object has a C<path()> method. L<IO::File::WithPath> from CPAN
is an easy drop-in for this:

  use IO::File::WithPath;

  # This works - IO::File::WithPath provides the path method
  my $fh = IO::File::WithPath->new('/path/to/file.bin', 'r');
  await $send->({ type => 'http.response.body', fh => $fh });

  # This does NOT trigger X-Sendfile (no path method)
  open my $plain_fh, '<', '/path/to/file.bin';
  await $send->({ type => 'http.response.body', fh => $plain_fh });

For plain filehandles, either use C<file =E<gt> $path> directly, or use
L<IO::File::WithPath>. See L<PAGI::Middleware::XSendfile> for details.

=head1 RESPONSE VALUES, EMISSION, AND TEST CAPTURE

A production L<PAGI::Response> is a complete reusable value. Its concrete class
identifies the representation or delivery behavior, and construction performs
no protocol I/O. It stores no request scope, send callback, connection, or
per-invocation Writer.

=head2 Metadata and invocation state

Response metadata is inspectable before emission:

  status / has_status / status_try
  headers / header / header_all / has_header / header_try / remove_header
  content_type / has_content_type / content_type_try
  cookie / delete_cookie
  is_buffered / body

Every constructed Response is already complete; there is no incomplete
body-mode state to query. Connection facts belong to the active
L<PAGI::Request> or native C<pagi.connection>. C<to_app> retains the exact
configured Response object, and each invocation derives its request-local
delivery plan before the first send. Deliberate mutation after C<to_app>
remains caller-owned, unwise for shared components, but valid. Concurrent
mutation while an invocation derives its plan is unsupported.

A normal handler returns the value:

  async sub create_item {
      my ($request) = @_;
      my $item = await create_from($request);
      return PAGI::Response::response('JSON', $item, status => 201);
  }

A native application owns the full triplet and one explicit delegation:

  use PAGI::Utils qw(invoke_app);
  my $res = PAGI::Response::response('JSON', $data, status => 200);
  await invoke_app($res, $scope, $receive, $send);

Do not emit inside a normal Request handler and then return the same value to
Routing. Handler completion still requires one Response; application
fallthrough needs an explicit Router outcome or application sentinel, never a
partially built Response.

=head2 Streaming state belongs to Writer

L<PAGI::Response::Stream> creates one invocation-local
L<PAGI::Response::Writer>. Await every C<write> before producing another chunk.
Its Future is the response-side backpressure boundary. C<bytes_written> counts
only chunks whose sends settled while the connection still reported connected;
settlement never proves client delivery. C<is_closed>, C<is_disconnected>, and
C<disconnect_reason> describe that Writer invocation, not the reusable Stream
value.

=head2 Streaming Response Formats

A streaming format is a L<PAGI::Response::Stream> subclass with a default
content type and a C<format_item> method. Producers call
C<< $writer->write_item($item) >>; Stream calls your C<format_item> to turn
the item into bytes, then handles backpressure, disconnects and cleanup as
for any stream. L<PAGI::Response::NDJSON> is the shipped example. Here is
tab-separated values:

  use v5.40;
  use Future::AsyncAwait;

  package MyApp::Response::TSV;
  use parent 'PAGI::Response::Stream';
  use Carp qw(croak);
  use Encode qw(encode);

  sub default_content_type { 'text/tab-separated-values; charset=utf-8' }

  sub format_item {
      my ($self, $row) = @_;
      my @fields = map { $_ // '' } @$row;    # undef is an empty field
      for my $field (@fields) {
          croak 'TSV fields cannot contain tabs or newlines' if $field =~ /[\t\r\n]/;
      }
      return encode('UTF-8', join("\t", @fields) . "\n");
  }

  package main;

  my $response = MyApp::Response::TSV->new(async sub {
      my ($writer) = @_;
      await $writer->write_item(['id', 'name']);
      await $writer->write_item([1, 'Ada']);
  });

C<format_item> must return encoded bytes, and must not change the response:
one response value can serve many requests at once. Here fields are character
strings, encoded once as UTF-8; an undefined field is written empty. Status, headers and
content type are the usual response options. Anything a format needs between
items, such as whether a header row was sent, belongs in the producer.

=head2 Test Response is a captured-wire decoder

L<PAGI::Test::Response> is deliberately a different class. The test client
feeds it captured response events; it reconstructs status, headers, body bytes,
decoded text, and JSON, including bytes referenced by C<file> and C<fh> events.
It is not a production Response, cannot be returned from a handler, and does
not have C<respond> or C<to_app>.

  my $captured = $client->get('/items/1');
  is($captured->status, 200);
  is($captured->json, { id => 1 });

This distinction keeps test assertions about observed wire output separate from
the reusable value that produced it.

=head1 TESTING

Use L<PAGI::Test::Client> to test apps directly without a running server:

  use strict;
  use warnings;
  use Test2::V0;
  use PAGI::Test::Client;

  # Load your app
  my $app = require './app.pl';
  my $client = PAGI::Test::Client->new(app => $app);

  subtest 'GET /' => sub {
      my $res = $client->get('/');
      is $res->status, 200, 'status is 200';
      like $res->text, qr/Hello/, 'body contains Hello';
  };

  subtest 'POST /api/users' => sub {
      my $res = $client->post('/api/users',
          json => { name => 'Alice' },
      );
      is $res->status, 201, 'status is 201';
      is $res->json->{id}, 1, 'returns user id';
  };

  subtest 'form submission' => sub {
      my $res = $client->post('/login',
          form => { user => 'admin', pass => 'secret' },
      );
      is $res->status, 302, 'redirects after login';

      # Session cookies persist across requests
      my $dashboard = $client->get('/dashboard');
      is $dashboard->status, 200, 'authenticated access';
  };

  subtest 'custom headers' => sub {
      my $res = $client->get('/api/data',
          headers => { Authorization => 'Bearer token123' },
      );
      is $res->status, 200;
  };

  done_testing;

See L<PAGI::Test::Client> for the full API including WebSocket and SSE testing.
