=encoding UTF-8

=head1 NAME

PAGI::Tools::Tutorial - Optional convenience helpers for PAGI applications

Route matches a complete URL leaf. Mount composes an application under a
prefix. Router selects and owns routing outcomes. Middleware wraps behavior.
Compose owns the application root and lifespan.

=head1 DESCRIPTION

PAGI itself is a protocol; see L<PAGI::Tutorial> for the protocol tutorial.
The C<PAGI-Tools> distribution adds B<optional> convenience helpers built on
top of that protocol: middleware, request/response sugar, WebSocket and SSE
helpers, routers, and ready-made applications. None of these are required to
write a complete PAGI application; they exist to save you boilerplate when you
want it, and every one of them is an ordinary PAGI application or a plain
wrapper around the C<$scope>/C<$receive>/C<$send> protocol. This guide covers
them.

=head1 PART 1: HELLO WORLD

A PAGI application is an C<async> sub that receives three arguments: C<$scope>
(the request metadata), C<$receive> (pull request-body events), and C<$send>
(push response events). At the raw protocol level, "hello world" emits two
events — the response start (status and headers) and the body:

  use Future::AsyncAwait;

  my $app = async sub {
      my ($scope, $receive, $send) = @_;
      await $send->({
          type    => 'http.response.start',
          status  => 200,
          headers => [['content-type', 'text/plain']],
      });
      await $send->({
          type => 'http.response.body',
          body => 'Hello, world!',
          more => 0,
      });
  };

That is a complete, server-ready application — no toolkit required. The helpers
in this distribution simply make the common cases shorter. Here is the same
response built as a L<PAGI::Response> value:

  use Future::AsyncAwait;
  use PAGI::Response qw(text_response json_response);
  use PAGI::Utils qw(invoke_app);

  my $app = async sub {
      my ($scope, $receive, $send) = @_;
      await invoke_app(
          text_response('Hello, world!'),
          $scope, $receive, $send,
      );
  };

C<PAGI::Response> assembles the two events and participates through the same
application protocol as any other PAGI component. Returning JSON is just as
short:

  await invoke_app(
      json_response({ hello => 'world' }),
      $scope, $receive, $send,
  );

From here the tutorial builds up: routing requests to handlers (PART 2),
reading form and JSON input (PART 3), the concrete Response class family (PART 4),
real-time and streaming (PART 5), middleware (PART 6), and composing larger
applications (PART 7).

=head1 PART 2: ROUTING

=head2 2.1 PAGI::Routing - Immutable Declarative Routing

L<PAGI::Routing> is the compact route-tree API. HTTP handlers receive one
L<PAGI::Request> and return immediate or Future-backed application values,
commonly L<PAGI::Response> or L<PAGI::Pages::Application>. WebSocket and SSE
handlers receive their direct protocol objects:

  Route CODE endpoint        -> one Request/WebSocket/SSE argument
  Route to_app object        -> native PAGI application
  Mount/Compose/default CODE -> native PAGI application
  handler result             -> native CODE or instantiated to_app object

  use Future::AsyncAwait;
  use PAGI::Routing qw(:routes);
  use PAGI::Response qw(html_response json_response);

  async sub home {
      my ($request) = @_;
      return html_response('<h1>Home</h1>');
  }

  async sub user {
      my ($request) = @_;
      return json_response({ id => $request->path_param('id') });
  }

  my $routing = router(
      routes => [
          route('/' => \&home, name => 'home'),
          mount('/api',
              routes => [
                  route('/users/{id}' => \&user,
                      name        => 'user',
                      methods     => ['GET'],
                      constraints => { id => qr/\d+/ },
                  ),
              ],
              name => 'api',
          ),
      ],
  );

  my $routing_component = $routing->to_app;

Constructors validate and build immutable descriptions. C<to_app> compiles a
fresh native PAGI wrapper graph and starts no request; call it once for the app
instance and retain the returned coderef. At request time routing matches in
declaration order, constructs the selected protocol object, awaits the handler, and emits its returned
Response exactly once.

The compiled coderef is a complete Router application for routing outcomes. If
no route answers, NONE emits its stock Pages 404 or configured HTTP-only
C<http_default>; PARTIAL emits its built-in Pages 405 with authoritative
C<Allow>. Compose does not own routing fallback. It owns deployed root safety,
including ErrorHandler, response-completion guarding, the outer HEAD boundary,
and lifespan.

Reusable semantic constraints can sit beside a parameter. An imported
Type::Tiny type is an ordinary zero-argument provider function:

  use Types::Standard qw(Int);

  route('/users/{id:&Int}' => \&user, name => 'user');

PAGI calls C<Int> while constructing the route and later validates without
coercing the captured string. Type::Tiny is optional for applications; it is
not a PAGI::Tools runtime dependency. A package-local provider can give an
application rule its own name and semantics:

  sub PersonId {
      my $int = Int;
      return sub {
          my ($value) = @_;
          return $int->check($value) && $value > 0;
      };
  }

  route('/people/{id:&PersonId}' => \&person, name => 'person');

Use a short inline regex for a short path-local rule and the explicit
C<constraints> hash for dynamic, subclass-dependent, or complex rules. See
L<PAGI::Routing/Path parameters, wildcards, and constraints> for provider
lookup, escaping, and reverse-routing behavior.

GET includes HEAD automatically. Paths are exact, with no slash redirect or
automatic OPTIONS. Mount has one composition contract and exactly one named
target:

  mount('/api', routes => \@nodes, name => 'api')
  mount('/people', app => $people, name => 'person')
  mount('/static', app => $static_app)

C<routes> constructs a complete child Router application. C<app> retains a
native application or instantiated component; an immutable Router remains
inspectable while other applications are opaque. A local C<name> is optional
for either form. After a prefix matches, the child owns its full match, 404,
and 405. Those responses flow through child, Mount-occurrence, and parent
middleware, but the parent never resumes scanning.

The immutable functional form takes an arrayref of nodes. The callback
shorthand belongs only to the mutable App/Endpoint builder:

  mount('/reports', routes => [route('/' => \&report)])

  $r->mount('/reports', routes => sub {
      my ($child) = @_;
      $child->get('/' => \&report);
  });

Route and structural-mount names are local segments; slash constructs absolute
logical addresses such as C</api/user>. Import URL helpers from their Router
owner; request-bound calls may resolve from the active namespace and inherit
only target-required captures:

  use PAGI::Routing::URL qw(path_for url_for);

  path_for($request, 'user');
  url_for($request, 'user', { id => 42 }, { tab => 'profile' }, 'details');
  url_for($request, 'user',
      query    => { tab => 'profile' },
      fragment => 'details',
  );

Absolute request-bound references and Router-object calls inherit nothing. URL
generation is not authorization. Reverse helpers return strings or croak; they
send no protocol events or redirects.

Pure route/mount/router middleware lists contain explicit descriptions, such
as C<< middleware =E<gt> [middleware($factory)] >>. Use
C<middleware($class, %config)> for deferred class construction,
C<middleware($factory, %config)> for a configured synchronous factory, and
C<middleware($object)> for an already configured C<wrap> object. Native
three-channel CODE endpoints remain explicit with C<as_app>. See L<PAGI::Routing> for
the complete lifecycle and
L<PAGI::Tools::Cookbook> for mounted, application, protocol, reverse-routing, and
metadata recipes.

=head2 2.2 PAGI::Compose - Application Root

L<PAGI::Compose> is the optional next layer when one deployed root should own
the route target, application-wide middleware, and startup/shutdown callbacks:

  use PAGI::Compose qw(compose);
  use PAGI::Routing qw(router route middleware);

  my @nodes = (
      route('/' => \&home),
  );

  my $app = compose(
      routes => \@nodes,
      middleware => [
          middleware('RequestId'),
      ],
      lifespan => {
          startup => sub {
              my ($state, $scope) = @_;
              $state->{db} = connect_db();
          },
          shutdown => sub {
              my ($state, $scope) = @_;
              $state->{db}->disconnect;
          },
      },
  )->to_app;

The server owns C<$state>. C<PAGI::Lifespan> passes each exact incoming
non-lifespan scope onward and installs or adopts state on that same hashref; it
does not promise a shallow request-scope copy. Compose does not invent state,
so a server without lifespan-state support receives a clear startup failure
whenever callbacks are configured. Plain and Future-backed callbacks are both
accepted.

C<routes> is the compact form. When a separately configured Router or another
application component already exists, pass it through C<app> instead:

  my $routing = router(
      routes => \@nodes,
      middleware => [middleware('RouterMetrics')],
  );

  my $app = compose(
      app => $routing,
      middleware => [
          middleware('RequestId'),
      ],
      lifespan => { startup => \&startup },
  )->to_app;

The router middleware sees only scopes and outcomes owned by that router.
Compose middleware is application-wide: it surrounds routing, lifespan, HTTP,
WebSocket, SSE, and extension scopes. The first listed middleware is outermost.
Only the deployed root runs lifecycle callbacks; mounting or nesting a Compose
description retains request dispatch but does not run that inner lifecycle.

For HTTP, a directly compiled Router already installs its own HeadBoundary.
Compose adds an outer, idempotent application-root HEAD boundary plus
ErrorHandler and a response-completion guard outside author middleware and the
target. The Router already owns 404 and 405. Configure its C<http_default> when
the application needs custom missing-route presentation; method mismatches
retain the Router-generated 405 and authoritative C<Allow>. A selected native
app that sends nothing is incomplete output and becomes 500, never an implicit
miss.

C<compose(...)> returns an immutable description. The final C<to_app> compiles
the native three-channel PAGI coderef once. Compose is not a base class and it
does not duplicate Router callback APIs or reverse-routing methods.

=head2 2.3 PAGI::App::Router - Mutable Routing

L<PAGI::App::Router> is the mutable frontend for the same immutable routing
model. Its verb methods append declarations in written order; ordinary
handlers use the same direct protocol contract as C<PAGI::Routing>:

  use PAGI::App::Router;
  use PAGI::Compose qw(compose);
  use PAGI::Routing qw(middleware);
  use PAGI::Response qw(text_response json_response);
  use PAGI::Utils qw(as_app);

  my $router = PAGI::App::Router->new;

  $router->get('/' => sub {
      my ($request) = @_;
      return text_response('Home');
  })->name('home');

  $router->post('/users' => sub {
      my ($request) = @_;
      return json_response({ created => 1 }, status => 201);
  })->name('create_user');

  $router->get('/users/{id}' => [
      'RequestId',
      $logging_factory,
      $configured_auth,
      middleware('Session', cookie_name => 'sid'),
  ] => sub {
      my ($request) = @_;
      return json_response({ id => $request->path_param('id') });
  })->name('show_user');

  # Native three-channel CODE is an explicit application value.
  $router->get('/download' => as_app($download_app));
  $router->websocket('/ws' => as_app($native_ws_app));
  $router->sse('/events' => as_app($native_sse_app));

  my $snapshot = $router->to_router;
  my $app = compose(app => $snapshot)->to_app;

The middleware entries above are intentional App Router sugar: the frontend
immediately materializes class names, synchronous factory coderefs, configured
objects with C<wrap>, and explicit C<middleware(...)> descriptions into the
explicit descriptions required by the immutable core. Factories and C<wrap>
run while C<to_app> compiles; the native app they return runs per request.
Each C<to_router> call creates a fresh immutable snapshot, so retain one when
inspection, reverse routing, and compilation must refer to the same route
identities.

For handlers bound to a configured object, subclass
L<PAGI::Endpoint::Router>. Its C<routes($builder)> method uses the same verb
surface but accepts local unqualified method names. Construct nested Endpoint
objects explicitly and mount C<< app => $child->to_router >> when their names
must remain discoverable. Mounting C<< app => $child >> is valid opaque
application composition. Package strings do not load routing behavior.

=head2 2.4 Choosing a Router

The three APIs are declaration frontends at different abstraction boundaries:

  PAGI::Routing          immutable functional declarations   Request handlers
  PAGI::App::Router      mutable imperative builder          verb methods + Request
  PAGI::Endpoint::Router class/role-oriented frontend        local method names

All three materialize L<PAGI::Routing::Router> and share Pattern parsing,
Resolver slash addresses, Compiler matching, route metadata, constraints,
GET/HEAD behavior, Router-owned HTTP outcomes, first-seen method evidence,
reverse routing, pure native middleware, and exact written order. The first
full match wins; declarations are never separated by kind or sorted by mount
prefix.

The selected Router owns NONE and PARTIAL. NONE invokes its HTTP-only
C<http_default> or stock Pages 404; PARTIAL emits its compliant Pages 405.
WebSocket and first-class SSE misses keep their stock protocol behavior.
Compose remains the application root for lifespan, error handling, and
response-completion safety.

Choose C<PAGI::Routing> for functional immutable declarations,
C<PAGI::App::Router> for incremental mutation with closures, and
C<PAGI::Endpoint::Router> when local methods and ordinary object fields make
the application boundary clearer. This release intentionally removes the old
App and Endpoint matcher, handler, naming, middleware, state, and package-load
contracts. See F<UPGRADING.md> for exercised before-and-after migrations.

=head1 PART 3: HANDLING REQUESTS

Once a request is routed to a handler, L<PAGI::Request> turns the raw C<$scope>
and C<$receive> into a convenient object: query and path parameters, headers,
cookies, and — the focus of this part — form bodies, JSON bodies, and file
uploads. It handles UTF-8 decoding and body parsing for you.

=head2 3.1 PAGI::Request - Request Parsing

L<PAGI::Request> parses HTTP requests and provides convenient accessors for headers, query parameters, cookies, and request bodies.

=head3 Creating a Request

  my $req = PAGI::Request->new($scope, $receive);

Normal Router handlers receive this object directly. Raw PAGI applications
construct it only when they choose the Request API; construction requires an
HTTP scope and a receive coderef.

=head3 Basic Properties

  $req->method         # HTTP method (GET, POST, etc.)
  $req->path           # URL path (decoded UTF-8)
  $req->query_string   # Query string (raw bytes)
  $req->scheme         # 'http' or 'https'
  $req->host           # Host header value

=head3 Headers

  # Get single header (case-insensitive)
  my $user_agent = $req->header('user-agent') // 'Unknown';

  # Get content type
  my $ct = $req->content_type;

  # Get bearer token from Authorization: Bearer <token>
  my $token = $req->bearer_token;

=head3 Query Parameters

  # Get single parameter
  my $page = $req->query_param('page') // '1';

  # Get all parameters as Hash::MultiValue
  my $params = $req->query_params;
  my @tags = $params->get_all('tag');  # For ?tag=foo&tag=bar

=head3 Body Parsing

  # Read entire body as raw bytes
  my $bytes = await $req->body;

  # Parse JSON body
  my $data = await $req->json;

  # Parse URL-encoded form
  my $form = await $req->form_params;
  my $name = $form->get('name');

  # Or get a single form value directly
  my $email = await $req->form_param('email');

Content-type predicates:

=over 4

=item * C<is_json()> - True if Content-Type is application/json

=item * C<is_form()> - True if form data (urlencoded or multipart)

=back

=head3 Streaming Large Request Bodies

The body methods above buffer the whole body in memory. For large uploads,
stream it instead with C<body_stream>, which returns a
L<PAGI::Request::BodyStream> you consume incrementally:

  # Pull chunks yourself (undef at end-of-body or client disconnect)
  my $stream = $req->body_stream(max_bytes => 100 * 1024 * 1024);
  while (defined(my $chunk = await $stream->next_chunk)) {
      # ... process $chunk ...
  }
  if ($stream->truncated) {
      # Client disconnected before the body finished -- whatever chunks
      # you already saw were only part of the intended upload.
      warn "upload cut short";
  }

C<next_chunk> returns C<undef> both at a legitimate end of body and after a
client disconnect -- C<undef> alone doesn't tell you which happened. Check
C<< $stream->truncated >> after the loop to distinguish "the body really
ended here" from "the client hung up early". When the server supplies
C<pagi.connection>, inspect C<< $req->connection->disconnect_reason >> for
why. The buffered methods (C<body>/C<text>/C<json>/C<form_params>)
take the opposite stance: they croak on a mid-body disconnect rather than
handing back a partial body as if it were complete, since nothing downstream
of those methods ever sees raw chunks to make that judgment call itself.

  # Or drain straight to a file (never holds the whole body in memory)
  await $req->body_stream->stream_to_file('/uploads/data.bin');

  # Or to a custom async sink — the read pauses until your sink resolves,
  # giving you natural backpressure
  await $req->body_stream->stream_to(async sub ($chunk) {
      await $store->append($chunk);
  });

Options: C<max_bytes> (a size cap; defaults to the Content-Length header),
C<decode> (e.g. C<'UTF-8'>, which handles multi-byte sequences split across
chunk boundaries), and C<strict> (throw on invalid UTF-8).

B<Streaming is mutually exclusive with the buffered methods.> Once you call
C<body_stream>, C<body>/C<text>/C<json>/C<form_params> are unavailable on that
request (and vice versa) — a body can only be consumed once.

Multipart file uploads stream automatically: C<< $req->upload >> /
C<< $req->uploads >> spool large parts to a temp file rather than holding them
in memory, so you rarely need C<body_stream> for ordinary form uploads. See
L<PAGI::Request::BodyStream> for the full API and backpressure examples.

When you would rather own where each upload goes, C<multipart_stream> returns a
L<PAGI::Request::MultipartStream> that yields one part at a time:

  my $stream = $req->multipart_stream;
  while (defined(my $part = await $stream->next)) {
      if ($part->is_file) {
          await $part->stream_to(async sub ($chunk) { await $sink->write($chunk) });
      } else {
          my $value = await $part->value;
      }
  }

This bypasses the auto-spool, so each upload part goes straight to your sink (an
S3 client, a transform, an async writer) instead of a temp file, and the sink
can be fully asynchronous -- the read pauses until your sink's Future resolves.
Slow-client and idle-read timeouts, and the aggregate C<max_body_size> cap, are
enforced by the PAGI server, not by this layer (the stream cannot impose a
wall-clock timeout itself).

=head2 3.2 Optional Scope Capabilities

Request owns HTTP input. Router- and middleware-owned capabilities are
separate facades whose imports make the dependency visible:

  use PAGI::CSRF qw(csrf);
  use PAGI::Routing::URL qw(path_for url_for);
  use PAGI::Session qw(session);
  use PAGI::Stash qw(stash);
  use PAGI::State qw(app_state);
  use PAGI::Transport qw(transport);

  my $db      = app_state($request)->get('db');
  my $user    = session($request)->get('user');
  my $result  = stash($request)->get('result');
  my $token   = csrf($request)->token;
  my $home    = path_for($request, '/home');
  my $flow    = transport($request);             # optional; may be undef

Each factory also accepts a native scope, so middleware and applications
can use the same capability without constructing Request. Session and CSRF
croak when their required middleware data is absent; State and Transport
return C<undef> when their optional capability is absent. Stash is created
lazily in the request scope.

C<app_state> is deliberately not named C<state>: under C<use v5.40>, a call
spelled C<state (...)> parses as Perl's C<state> declarator instead of calling an
imported function. C<< $request->state >> is the method form. It returns a
strict L<PAGI::State> facade when state exists; C<get> catches missing-key
typos and C<data> is the explicit escape hatch for code that requires a real
HashRef.

The temporary C<< $state->{key} >> bridge warns once per callsite. Set
C<PAGI_SILENCE_STATE_HASHREF_WARNING> to exactly C<1> only while migrating.
The object overload preserves dereference syntax, not
C<< ref($state) eq 'HASH' >>, HashRef type constraints, serializers, or clone
libraries; pass C<< $state->data >> to those consumers.

C<< $request->is_disconnected >> is tri-state: true after disconnect, false
when a supplied connection remains open, and C<undef> when the server supplied
no C<pagi.connection> capability. Test C<defined> when the unsupported case
matters. Advanced disconnect callbacks live on C<< $request->connection >>;
outbound watermark and drain operations live on C<transport($request)>.

=head1 PART 4: BUILDING RESPONSES

=head2 4.1 PAGI::Response - Concrete Response Values

L<PAGI::Response> is a class family, not a mutable body-mode builder. The class
or factory name tells you what is buffered and how it is delivered:

  Class                             Factory
  --------------------------------  -----------------
  PAGI::Response                    response
  PAGI::Response::Text              text_response
  PAGI::Response::HTML              html_response
  PAGI::Response::JSON              json_response
  PAGI::Response::Problem           problem_response
  PAGI::Response::Redirect          redirect_response
  PAGI::Response::Empty             empty_response
  PAGI::Response::File              file_response
  PAGI::Response::Stream            stream_response

The first seven hold their complete encoded bytes in memory. File keeps one
trusted selected path and uses a PAGI C<file> event. Stream runs a fresh
producer and Writer for each invocation. Nothing consumes a source merely to
guess whether it is finite.

  use PAGI::Response qw(
      response text_response html_response json_response
      redirect_response empty_response file_response stream_response
  );
  use PAGI::Response::Text ();

  my $text = PAGI::Response::Text->new('Hello'); # class form
  my $json = json_response({ ok => \1 });          # factory form

The base C<response($bytes)> accepts already encoded bytes. Text and HTML
strictly encode Unicode as UTF-8; JSON serializes one finite Perl value and
does not promise object member order. For another charset, encode explicitly:

  use Encode qw(encode);
  my $latin1 = response(
      encode('ISO-8859-1', $text),
      content_type => 'text/plain; charset=iso-8859-1',
  );

Common options are C<status>, C<content_type>, and flat C<headers>. Metadata
methods such as C<status>, C<header>, C<content_type>, C<cookie>, and their
C<*_try>/inspection forms remain available before emission. C<to_app> retains
the exact configured Response object; it does not clone or freeze it. Each
invocation derives a request-local delivery plan before its first send. The
Response stores no scope or connection, so an unchanged preconstructed value
can serve concurrent requests.

Normal Request handlers return application values for Routing to invoke. A
Response object is the common case:

  $router->get('/health' => sub {
      my ($request) = @_;
      return json_response(
          { ok => \1 },
          status  => 200,
          headers => ['X-Request-ID' => request_id($request)],
      );
  });

A native PAGI application owns all three channels and delegates explicitly:

  use PAGI::Utils qw(invoke_app);

  my $app = async sub {
      my ($scope, $receive, $send) = @_;
      my $response = json_response({ created => \1 }, status => 201);
      await invoke_app($response, $scope, $receive, $send);
  };

C<to_app> exposes the exact Response as an HTTP-only native application. A
non-HTTP scope fails before emission; controlled WebSocket denial and SSE
decline use their protocol methods instead. Compose remains the deployed-root
owner for lifespan, errors, response completion, and final HEAD suppression.

File construction validates option shape, not the filesystem. Existence,
readability, metadata, conditions, and range planning happen at request-time
preflight. If configuration must fail at startup, check it explicitly during
startup. C<offset>/C<length> describe a complete logical 200 representation;
only a valid client Range produces 206 and Content-Range.

Stream backpressure is the Future returned by each write:

  return stream_response(async sub {
      my ($writer) = @_;
      await $writer->write("one\n");
      await $writer->write("two\n");
  });

Never overlap writes. A send settles when the server accepted or discarded the
event, not when the client received it. Writer awaits and then checks connection
state; a disconnected discarded chunk is not counted. Stream may cancel its
own producer, never a send Future, and runs local cleanup exactly once. An
ordinary HTTP Stream has no WebSocket/SSE reconnection semantics. HEAD normally
runs the whole producer behind the outer body-suppression boundary; put a
lightweight explicit HEAD route before an expensive streaming GET route.

=head2 4.2 PAGI::Pages - Conventional Negotiated Responses

Use L<PAGI::Pages> when the response is a conventional welcome, HTTP error, or
redirect rather than an application-owned literal document. Its source-free
factories return deferred HTTP applications:

  use PAGI::Pages qw(welcome gone);
  use PAGI::Response qw(json_response);

  route('/items/{id}' => async sub {
      my ($request) = @_;
      my $item = await find_item($request->path_param('id'));
      return PAGI::Pages->not_found(detail => 'Item not found') unless $item;
      return json_response($item);
  });

A native app delegates the deferred Pages application through the ordinary
application protocol:

  use PAGI::Utils qw(invoke_app);
  await invoke_app(
      PAGI::Pages->not_found(as => 'text'),
      $scope, $receive, $send,
  );

Pages exports nothing by default. C<:common> omits the collision-prone
C<status> and C<redirect>; import them individually or choose C<:all>.
Class methods, configured-instance methods, and exports have the same
source-free factory contract:

  route('/' => welcome());
  mount('/gone', app => gone(detail => 'Retired'));

Route remains an exact method-aware leaf; a Mount owns its selected prefix and
complete rewritten subtree. The same Pages value can be a Router
C<http_default> directly. A bare Pages root declines lifespan in automatic
server mode; strict lifespan rejects that decline. Pages does not handle
lifespan, so use Compose when startup and shutdown ownership is required.

Automatic representation selection negotiates HTML, RFC 9457 problem JSON for
errors (ordinary JSON for welcome and redirects), and text. Use C<< as =>
'html' >>, C<'json'>, or C<'text'> for a fixed representation. Error responses
default to C<Cache-Control: no-store>. Pages also validates mandatory fields:

  PAGI::Pages->unauthorized(
      challenge => 'Bearer realm="api"');
  PAGI::Pages->method_not_allowed(
      allow => [qw(GET HEAD)]);

Redirect query preservation is explicit and defaults off:

  PAGI::Pages->redirect('/search#results',
      status => 308, preserve_query => 1);

Use a Pages instance or subclass explicitly when application presentation
needs custom synchronous render hooks. Compose has no Pages configuration
option.

=head1 PART 5: REAL-TIME & STREAMING

=head2 5.1 PAGI::WebSocket - WebSocket Helper

L<PAGI::WebSocket> simplifies WebSocket connections:

  my $ws = PAGI::WebSocket->new($scope, $receive, $send);
  await $ws->accept;

  # Send and receive
  await $ws->send_text("Hello!");
  my $msg = await $ws->receive;

  # JSON messages
  await $ws->send_json({ type => 'greeting' });
  my $data = await $ws->receive_json;

  # Message loop
  await $ws->each_text(async sub {
      my ($text) = @_;
      await $ws->send_text("Echo: $text");
  });

  await $ws->close(1000, 'Goodbye');

Before C<accept>, a concrete finite or Stream Response can deny the handshake:

  use PAGI::Response qw(text_response);

  await $ws->deny(
      text_response('Unauthorized', status => 401),
  );

The optional denial extension maps ordinary body events. File is rejected
before start; without the extension WebSocket uses its policy-close fallback.

=head2 5.2 PAGI::SSE - Server-Sent Events Helper

L<PAGI::SSE> simplifies Server-Sent Events:

  my $sse = PAGI::SSE->new($scope, $receive, $send);
  await $sse->start;

  # Send events (data is a named argument)
  await $sse->send_event(data => "Hello!");
  await $sse->send_event(data => "User logged in", event => 'login', id => '42');

  # Send JSON with an event name (hashref/arrayref data is auto-encoded)
  await $sse->send_event(data => { count => 5 }, event => 'update');

  # Or, for a plain JSON message with no event name:
  await $sse->send_json({ count => 5 });

  # Keepalive to prevent proxy timeouts
  await $sse->keepalive(15);

  # Wait for disconnect
  await $sse->run;

Before C<start>, decline with the same Response vocabulary:

  use PAGI::Response qw(problem_response);

  await $sse->decline(
      problem_response({ title => 'Not Found', status => 404 }),
  );

Denial/decline start-send settlement commits the protocol response slot; it is
server acceptance/settlement, not proof of client delivery. Pending body sends
at disconnect resolve normally under PAGI 0.002007. Cleanup follows protocol state
and disconnect watchers rather than an invented send failure. HTTP Stream is a
finite request's body delivery mechanism; WebSocket and live SSE retain their
own connection, event, keepalive, and reconnection lifecycles.

=head1 PART 6: MIDDLEWARE

Middleware provides reusable functionality that wraps your application handlers. PAGI includes 30+ middleware components for logging, security, compression, sessions, and more.

=head2 6.1 How Middleware Works

At the protocol level there is nothing special about middleware: it is simply a
PAGI application that wraps another PAGI application. It receives the same
C<($scope, $receive, $send)>, does its work before and/or after, and delegates
to the app it wraps. That lets a middleware:

=over 4

=item * Modify the request scope before the inner app sees it

=item * Short-circuit the request and respond early, without calling the inner app

=item * Intercept and modify the response on its way out

=item * Add side effects such as logging or timing

=back

=head3 The raw-PAGI version

Say we want to stamp every response with an C<X-Powered-By> header. With nothing
but the protocol, a middleware is a function that wraps an app and intercepts the
C<http.response.start> event by wrapping C<$send>:

  use Future::AsyncAwait;

  sub add_powered_by {
      my ($app) = @_;
      return async sub {
          my ($scope, $receive, $send) = @_;

          # Wrap $send so we can edit the response-start event on its way out
          my $wrapped_send = async sub {
              my ($event) = @_;
              if ($event->{type} eq 'http.response.start') {
                  push @{ $event->{headers} }, ['x-powered-by', 'PAGI'];
              }
              await $send->($event);
          };

          await $app->($scope, $receive, $wrapped_send);
      };
  }

It works, but you write the C<$send>-wrapping boilerplate by hand, and you
compose middleware by nesting function calls — which reads inside-out and hides
the running order:

  my $app = add_powered_by( time_requests( access_log( $inner_app ) ) );

=head3 The PAGI::Middleware version

Here is the same middleware as a L<PAGI::Middleware> subclass. The base class
supplies the wrapping helpers; C<intercept_send> hands your callback each
outgoing C<$event> together with the original C<$send> to forward it to:

  package MyApp::Middleware::PoweredBy;
  use parent 'PAGI::Middleware';
  use Future::AsyncAwait;

  sub wrap {
      my ($self, $app) = @_;
      return async sub {
          my ($scope, $receive, $send) = @_;

          my $wrapped_send = $self->intercept_send($send, async sub {
              my ($event, $orig_send) = @_;
              push @{ $event->{headers} }, ['x-powered-by', 'PAGI']
                  if $event->{type} eq 'http.response.start';
              await $orig_send->($event);
          });

          await $app->($scope, $receive, $wrapped_send);
      };
  }

  1;

Now it composes with the C<builder> as a flat stack that reads top-to-bottom, in
the order it runs:

  use PAGI::Middleware::Builder;

  my $app = builder {
      enable '+MyApp::Middleware::PoweredBy';
      enable 'AccessLog';
      enable 'Runtime';
      $router;
  };

=head3 Why the toolkit version is worth it

The behavior is identical — what you gain is everything around it:

=over 4

=item * B<Composition.> The C<builder> stack reads in run order, top to bottom,
instead of inside-out function nesting. Adding, removing, or reordering a
middleware is a one-line change.

=item * B<Configuration.> A middleware is a configurable object —
C<enable 'GZip', min_size =E<gt> 1024> — with construction-time validation,
rather than a closure capturing lexicals.

=item * B<Reuse.> It is an ordinary class: ship it on CPAN, share it between
apps, or reach for one of the 30+ already in this distribution (see
L</6.3 Essential Middleware Reference>) rather than writing your own.

=item * B<Conditional and per-route use.> C<enable_if { ... } 'Name'> applies a
middleware only when a condition holds, and any route can carry its own
middleware list (see L</6.2 Using Middleware with Builder>).

=item * B<Helpers.> The base provides C<intercept_send>, C<modify_scope>,
C<buffer_request_body>, and friends, so each middleware isn't re-implementing
the protocol plumbing.

=back

=head2 6.2 Using Middleware with Builder

The L<PAGI::Middleware::Builder> DSL lets you compose middleware into your application.

=head3 Global Middleware

Apply middleware to all routes using the C<builder> function:

  use PAGI::Middleware::Builder;
  use PAGI::App::Router;
  use PAGI::Utils qw(as_app);

  my $router = PAGI::App::Router->new;

  $router->get('/' => as_app(async sub {
      my ($scope, $receive, $send) = @_;
      await $send->({
          type    => 'http.response.start',
          status  => 200,
          headers => [['content-type', 'text/plain']],
      });
      await $send->({
          type => 'http.response.body',
          body => 'Hello World',
          more => 0,
      });
  }));

  # Wrap with middleware using builder; the block's final value can be
  # an app coderef, a component, or (as here) the router itself
  my $app = builder {
      enable 'AccessLog', format => 'combined';
      enable 'CORS', origins => '*';
      enable 'GZip', min_size => 1024;
      $router;
  };

Middleware executes in order: AccessLog -> CORS -> GZip -> app.

=head3 Multiple Middleware Example

  my $app = builder {
      enable 'RequestId';                      # Add X-Request-Id header
      enable 'AccessLog', format => 'tiny';    # Log requests
      enable 'Runtime';                        # Add X-Runtime header
      enable 'CORS', origins => '*';           # Enable CORS
      enable 'SecurityHeaders';                # Add security headers
      enable 'GZip', min_size => 1024;         # Compress responses
      enable 'ErrorHandler', development => 1;  # Development diagnostics
      $router;
  };

=head3 Middleware Instances

C<enable> also accepts an already-configured middleware instance — useful
when you build the instance elsewhere or want construction-time errors.
The parentheses are required for the instance form:

  my $gzip = PAGI::Middleware::GZip->new(min_size => 1024);

  my $app = builder {
      enable 'AccessLog', format => 'tiny';
      enable($gzip);
      $router;
  };

=head3 Performance

=over 4

=item * L<PAGI::Middleware::GZip>

=head3 Error Handling

=over 4

=item * L<PAGI::Middleware::ErrorHandler>

Catch and format errors:

  enable 'ErrorHandler', development => 1;  # Safely stringified development detail
  enable 'ErrorHandler';                    # Production (default): generic errors, no detail leak

C<ErrorHandler>'s built-in response negotiates through L<PAGI::Pages>. Supply
a concrete Response through the existing handler seam to fix its representation:

  use PAGI::Response qw(problem_response);

  enable 'ErrorHandler',
      handler => sub {
          my ($request, $error) = @_;
          return problem_response({
              title  => 'Internal Server Error',
              status => 500,
          });
      };

Use C<html_response> or C<text_response> for other fixed forms. Ordinary
construction has static C<development =E<gt> 0> behavior and
does not consult C<PAGI_ENV>. Its optional C<handler> receives
C<($request, $error)> and returns an immediate or Future-backed Response.
The wrapper may inspect C<$error> to choose
safe response fields; the Response factory does not consume the exception
implicitly.
C<on_error> is awaited reporting, not rendering; reporter failure is contained.
Before response start, ErrorHandler reports and renders. After start it reports,
emits no replacement response, and rethrows the original exception so the
server can abort the incomplete stream. Built-in bodies are byte-correct UTF-8
and carry C<Cache-Control: no-store>.

=back

=head2 6.4 Writing Custom Middleware

Create reusable middleware by extending L<PAGI::Middleware>:

  package MyApp::Middleware::Auth;
  use parent 'PAGI::Middleware';
  use Future::AsyncAwait;

  sub new {
      my ($class, %args) = @_;
      return bless { secret => $args{secret} }, $class;
  }

  sub wrap {
      my ($self, $app) = @_;

      return async sub {
          my ($scope, $receive, $send) = @_;

          # Check auth header
          my $auth = $self->get_header($scope, 'Authorization');

          if ($auth && $auth =~ /^Bearer (.+)/) {
              my $token = $1;
              my $user = verify_token($token, $self->{secret});
              PAGI::Stash->new($scope)->set(user => $user) if $user;
          }

          # Call next middleware/app
          await $app->($scope, $receive, $send);
      };
  }

  sub get_header {
      my ($self, $scope, $name) = @_;
      $name = lc $name;
      for my $header (@{$scope->{headers} || []}) {
          return $header->[1] if lc($header->[0]) eq $name;
      }
      return undef;
  }

  sub verify_token {
      my ($token, $secret) = @_;
      # Token verification logic here
      return { id => 1, username => 'alice' };
  }

  1;

Use it with the builder:

  my $app = builder {
      enable '+MyApp::Middleware::Auth', secret => 'secret-key';
      $router;
  };

The leading C<+> tells the builder to use the class name as-is instead of
prepending C<PAGI::Middleware::>. This is the Plack-familiar exact-package
escape shared by Builder and explicit routing middleware descriptions. Or skip
name resolution entirely by
passing a configured instance (parentheses required):

  my $app = builder {
      enable(MyApp::Middleware::Auth->new(secret => 'secret-key'));
      $router;
  };

Or per-route:

  use PAGI::Response qw(text_response);

  my $auth = MyApp::Middleware::Auth->new(secret => 'secret-key');
  $router->get('/admin' => [$auth] => sub {
      my ($request) = @_;
      return text_response('admin');
  });

=head3 Middleware Patterns

=over 4

=item * Modify scope

Add data for downstream handlers:

  sub wrap {
      my ($self, $app) = @_;
      return async sub {
          my ($scope, $receive, $send) = @_;
          PAGI::Stash->new($scope)->set(custom_data => 'value');
          await $app->($scope, $receive, $send);
      };
  }

=item * Intercept responses

Modify outgoing events:

  sub wrap {
      my ($self, $app) = @_;
      return async sub {
          my ($scope, $receive, $send) = @_;

          my $wrapped_send = $self->intercept_send($send, async sub {
              my ($event, $original_send) = @_;
              if ($event->{type} eq 'http.response.start') {
                  push @{$event->{headers}}, ['x-custom', 'value'];
              }
              await $original_send->($event);
          });

          await $app->($scope, $receive, $wrapped_send);
      };
  }

=item * Short-circuit requests

Return early without calling inner app:

  sub wrap {
      my ($self, $app) = @_;
      return async sub {
          my ($scope, $receive, $send) = @_;

          # Check condition
          unless ($self->is_authorized($scope)) {
              await $send->({
                  type    => 'http.response.start',
                  status  => 403,
                  headers => [['content-type', 'text/plain']],
              });
              await $send->({
                  type => 'http.response.body',
                  body => 'Forbidden',
                  more => 0,
              });
              return;  # Don't call $app
          }

          await $app->($scope, $receive, $send);
      };
  }

=back

=head1 PART 7: COMPOSING APPLICATIONS

PAGI ships with several ready-to-use applications for common tasks. These can be mounted with routers or used standalone.

=head2 7.1 PAGI::App::File - Static Files

L<PAGI::App::File> serves static files with security, caching, and streaming:

  use PAGI::App::File;

  my $static = PAGI::App::File->from_app_path('public');
  $router->mount('/static', app => $static);

Features:

=over 4

=item * Efficient streaming (large files don't consume memory)

=item * ETag caching with 304 Not Modified support

=item * HTTP Range requests for resume support

=item * Automatic MIME type detection

=item * Lexically rooted request paths and hidden files forbidden by default

=back

Use this component by default. It selects indexes and MIME types, streams with
C<file> events, negotiates errors, and handles conditional and Range requests
without loading file bodies into application memory.

If custom authorization or response headers require a native handler, begin with
the same lexical boundary:

  use Future;
  use Future::AsyncAwait;
  use PAGI::Pages;
  use PAGI::Utils qw(invoke_app path_from_root);

  my $download = async sub {
      my ($scope, $receive, $send) = @_;
      my $untrusted_path = $scope->{path};

      my $path = path_from_root('/var/www/files', $untrusted_path);
      unless (defined $path) {
          my $response = PAGI::Pages->forbidden;
          return await Future->wrap(
              invoke_app($response, $scope, $receive, $send),
          );
      }

      # Replace the safe default with application-specific authorization.
      my $authorized = 0;
      unless ($authorized) {
          my $response = PAGI::Pages->forbidden;
          return await Future->wrap(
              invoke_app($response, $scope, $receive, $send),
          );
      }

      unless (-f $path && -r $path) {
          my $response = PAGI::Pages->not_found;
          return await Future->wrap(
              invoke_app($response, $scope, $receive, $send),
          );
      }

      await Future->wrap($send->({
          type    => 'http.response.start',
          status  => 200,
          headers => [['content-type', 'application/octet-stream']],
      }));
      return await Future->wrap($send->({
          type => 'http.response.body', file => $path, more => 0,
      }));
  };

C<path_from_root> performs no I/O and does not resolve symlinks. The server
opens the later C<file> event. A configured symlink therefore extends
administrator authority beyond the lexical root. Keep rooted file trees
dedicated and non-attacker-writable, enforce suitable ownership and
permissions, and treat those controls as deployment practice rather than a
physical-confinement guarantee. See
L<PAGI::Tools::Cookbook/Serving Large Files with X-Sendfile> for the complete
authenticated download recipe and the
L<upgrade guide|https://github.com/jjn1056/PAGI-Tools/blob/main/UPGRADING.md#rooted-file-serving-security-contract>
for changed status and option behavior.

=head2 7.2 PAGI::App::Healthcheck - Health Endpoints

L<PAGI::App::Healthcheck> creates health check endpoints:

  use PAGI::App::Healthcheck;

  my $health = PAGI::App::Healthcheck->new(
      version => '1.0.0',
      checks => {
          database => sub { $db && $db->ping },
          cache    => sub { $redis && $redis->ping },
      },
  );

  $router->mount('/health', app => $health);

=head2 7.3 PAGI::App::URLMap - Mount Applications

L<PAGI::App::URLMap> routes requests to different apps based on URL prefix:

  use PAGI::App::URLMap;

  my $urlmap = PAGI::App::URLMap->new;
  $urlmap->mount('/api' => $api_app);
  $urlmap->mount('/admin' => $admin_app);
  $urlmap->mount('/static' => $static);
  compose(app => $urlmap)->to_app;

Each selected mount and C<default> is opaque. A Router child is nevertheless a
complete application for its own 404 and 405 outcomes. URLMap does not inspect
its names or allow parent routing to resume; use a declarative Mount with an
immutable Router C<app> when reverse discovery matters.

=head2 7.4 PAGI::App::Cascade - Try Apps in Sequence

L<PAGI::App::Cascade> tries apps in order using two independent rules:
explicit non-final statuses in C<catch>, while silence is always an error:

  use PAGI::App::Cascade;

  my $routing = PAGI::App::Cascade->new(
      apps => [$static, $api, $fallback],
      catch => [404, 405],
  );

  my $app = compose(app => $routing)->to_app;

A non-caught response streams after its start event. A caught response is
suppressed and awaited through its terminal body before the next child runs.
An arbitrary silent HTTP child is an application error. Routers emit ordinary
404/405 responses, so those statuses advance only when listed in C<catch>; a
final Router response passes through unchanged.

=head2 7.5 PAGI::App::Proxy - Reverse Proxy

L<PAGI::App::Proxy> forwards requests to backend servers:

  use PAGI::App::Proxy;

  my $proxy = PAGI::App::Proxy->new(
      backend => 'http://localhost:8080',
      timeout => 30,
  );
  $router->mount('/api', app => $proxy);

=head2 7.6 PAGI::App::WrapPSGI - Use Existing PSGI Apps

L<PAGI::App::WrapPSGI> lets you use existing PSGI applications:

  use PAGI::App::WrapPSGI;

  my $wrapped = PAGI::App::WrapPSGI->new(psgi_app => $legacy_app);
  $router->mount('/legacy', app => $wrapped);

Useful for incremental migration from PSGI to PAGI.

=head2 7.7 Application Composition

Application positions accept two explicit native forms:

=over 4

=item * An B<async coderef> — the protocol-level form, used unchanged

=item * A B<component object> — anything with a C<to_app> method,
compiled once at composition time:
C<< PAGI::App::File->new(root => 'public') >>

=back

These positions accept coderefs or instantiated C<to_app> objects; package
strings are rejected because an application position does not define whether a
package should be constructed, called as a class, or treated as a singleton.
App positions include opaque mounts and explicit C<as_app> leaves in
L<PAGI::App::Router> and
L<PAGI::Routing>, C<mount> and the final block value in
L<PAGI::Middleware::Builder>'s C<builder {}>, L<PAGI::App::URLMap>
mounts and its C<default>, L<PAGI::App::Cascade> entries, and the
C<app> argument to L<PAGI::Test::Client>, L<PAGI::Lifespan/new>, and
L<PAGI::Lifespan/wrap>. Put together:

  use PAGI::Response qw(text_response);

  my $app = builder {
      enable 'AccessLog';
      mount '/static' => PAGI::App::File->new(root => 'public');
      mount '/api'    => MyApp::API->new;
      text_response('no such page', status => 404);
  };

Compilation happens exactly once, when the composition point receives
the component — never per request. Routing-aware App/Endpoint children are
deliberately stricter: load their packages normally, construct configured
objects explicitly, and pass immutable snapshots to
C<< mount('/prefix', app => $child->to_router) >> when reverse discovery is
required. Ordinary route targets receive the direct protocol object; native
coderefs and instantiated component apps belong only behind explicit
C<as_app> or opaque mount boundaries.

Middleware position is the same idea with a different duck type:
C<enable> accepts a middleware name (resolved under
C<PAGI::Middleware::>, with leading C<+> to select an exact package) or a configured instance
with a C<wrap> method. Builder, App Router, and Endpoint Router retain their
concise frontend forms. App Router and Endpoint Router immediately materialize
explicit descriptions for the immutable core. Middleware Builder is a separate
concise composition API: it retains its own middleware records and constructs
or wraps them during C<to_app>. Core routing middleware arrays contain only
L<PAGI::Routing::Middleware> descriptions. Factories have the form C<sub { my
($app) = @_; async sub { ... } }>.

Passing middleware where an app belongs (or vice versa) croaks at
composition time with a message pointing at the right position.

F<app.pl> may return either a native coderef or an instantiated component object
with C<to_app>, including a Compose description. A Router is already complete
for its own 404/405. Cascade is ordinary status-driven application coordination
and carries no special Router semantics. Wrap either with
C<< compose(app => $application) >> when the deployed application also needs
root ErrorHandler, response-completion guarding, and lifespan. The server may
compile that component object once, or the file may call C<to_app> explicitly.
A C<builder {}> block already returns a native coderef; whether it is complete
depends on the applications it composes.

=head2 7.8 Starlette Vocabulary, PAGI Boundaries

PAGI follows Starlette's Route/Mount/Router/application topology, not every
method on Starlette Request. L<PAGI::Request> owns HTTP input; imports identify
the Router or middleware that supplies optional behavior. This keeps optional
capability ownership visible and lets a higher-level framework use its own
Router API.

Ordinary handlers receive the direct Request, WebSocket, or SSE object, while C<as_app>, Mount
C<app>, Router C<http_default>, and Compose C<app> receive the native three
channels. Constraints validate without coercion. Names use slash logical
addresses and relative L<PAGI::Routing::URL> lookup. SSE is a first-class scope, and all
middleware is pure PAGI app-to-app wrapping.

Starlette's single multiprotocol Router C<default> was considered and
deliberately not copied. PAGI C<http_default> affects only HTTP NONE, leaving
the stock WebSocket and SSE miss paths intact. Compose, not Router, owns the
root lifespan. OpenAPI/schema generation and C<include_in_schema> remain
deferred until a concrete consumer exists; no placeholder option is shipped.
